# 07: 节流与预算 + 分级诊断

**What to build:** 三重节流与**分级诊断**——把贵的证据留到有人接话的时候。

主动播报是「固定成本 × 时间」，而你不在场时没有任何收益能摊平它。分级诊断的道理相同：
自动那一轮只读台账与诊断包**摘要**；读会话原文（12k 字符）、跑命令这些贵的动作，
只在被追问或已确认要修时做。

**Blocked by:** 06

**Status:** done

- [x] **去抖窗口**（票 06 已实现，本票把它的值与节流一起纳入配置）
- [x] **同任务冷却**：默认 30 分钟。同一任务在冷却期内不再唤醒（新事件仍照常入待办，
      只是不单独唤醒）；冷却到期后合并播报
- [x] **全局唤醒上限**：默认每小时 12 次（可配）。触顶时不再唤醒，
      但**必须记一条「本小时已达上限，N 条待办未播报」**——
      静默丢弃是这一票最容易犯的错
- [x] **分级诊断**：自动轮只允许读台账类工具 + 诊断包；`read_conversation` 与 `run_command`
      在自动轮里**不可用**（或可用但会被剥离），在被追问/已确认要修时才放开
- [x] 三个阈值进 `PipelineSettings`（`crates/core/src/config.rs`，`deny_unknown_fields`）+ 文档同步
- [x] 新增用例：连续两条同任务事件在冷却期内 → 一次唤醒（不是两次）
- [x] 新增用例：触顶时播报一条「已达上限」而不是静默
- [x] 新增用例（分级）：自动轮的模型拿到的工具集**不含** `read_conversation` 与 `run_command`；
      被追问时同一任务的那个集合**含**它们
- [x] token 账：值守轮的 token 记在播报那一行上，且**与人的回话分开统计**（便于回答「这周值守花了多少」）

**实施收尾（2026-09-18）:**

- **新增一张 `kanban_foreman_watch_wakes`（迁移 0020）**：唤醒账。为什么不能靠数会话行——
  「判定无需处理」那一轮**不落会话行却照样烧 token**，数会话行会让全局上限形同虚设，而
  「这周值守花了多少」也答不出来。三态 `broadcast` / `silent` / `capped`；表里带
  token 与 `event_count`。保留期与其余各表同口径，年龄清理进维护作业。
- **两个阈值**：`watch_task_cooldown_minutes`（30）、`watch_max_wakes_per_hour`（12），
  加上票 06 的 `watch_debounce_sec`，三个都进了 `docs/overview.md` §3 的参数表。
- **同任务冷却的判据是「这个任务最近有没有被消费过的待办」**（`count_consumed_attention_since`）：
  那一行的 `consumed_at` 就是「刚有人看过它」的账。被冷却挡住的事件**不消费**，
  于是「冷却到期后合并播报」是自然发生的，不需要另设一个「暂存区」。
- **触顶提示走 `role = system` 行**（操作台记的账），不是播报：它是「操作台告诉你发生了什么」，
  既不该花模型的钱，也不该被误读成值班长说的话。**同一小时只留一条**（用唤醒账里的
  `capped` 行判），否则触顶本身会变成新的刷屏源；待办一条不消费。
- **分级诊断摘在源头上**：`foreman_available_tools_except(mode, deny)` —— 广告集与执行点
  白名单仍从同一份名单出。分级最容易犯的错是只从执行点摘掉，于是模型看得见一个调用就被拒的
  工具，然后一遍遍试它。

## 备注

「上限触顶要留痕」这一条很重要：节流的目的**不是**让值班长闭嘴，是让它在**该说话的那一次**说话。
静默丢弃会让「我明明出了事它却没说」变成一个查不出来的现象——正是本批要消灭的那类现象。
