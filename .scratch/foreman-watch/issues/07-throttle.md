# 07: 节流与预算 + 分级诊断

**What to build:** 三重节流与**分级诊断**——把贵的证据留到有人接话的时候。

主动播报是「固定成本 × 时间」，而你不在场时没有任何收益能摊平它。分级诊断的道理相同：
自动那一轮只读台账与诊断包**摘要**；读会话原文（12k 字符）、跑命令这些贵的动作，
只在被追问或已确认要修时做。

**Blocked by:** 06

**Status:** ready-for-agent

- [ ] **去抖窗口**（票 06 已实现，本票把它的值与节流一起纳入配置）
- [ ] **同任务冷却**：默认 30 分钟。同一任务在冷却期内不再唤醒（新事件仍照常入待办，
      只是不单独唤醒）；冷却到期后合并播报
- [ ] **全局唤醒上限**：默认每小时 12 次（可配）。触顶时不再唤醒，
      但**必须记一条「本小时已达上限，N 条待办未播报」**——
      静默丢弃是这一票最容易犯的错
- [ ] **分级诊断**：自动轮只允许读台账类工具 + 诊断包；`read_conversation` 与 `run_command`
      在自动轮里**不可用**（或可用但会被剥离），在被追问/已确认要修时才放开
- [ ] 三个阈值进 `PipelineSettings`（`crates/core/src/config.rs`，`deny_unknown_fields`）+ 文档同步
- [ ] 新增用例：连续两条同任务事件在冷却期内 → 一次唤醒（不是两次）
- [ ] 新增用例：触顶时播报一条「已达上限」而不是静默
- [ ] 新增用例（分级）：自动轮的模型拿到的工具集**不含** `read_conversation` 与 `run_command`；
      被追问时同一任务的那个集合**含**它们
- [ ] token 账：值守轮的 token 记在播报那一行上，且**与人的回话分开统计**（便于回答「这周值守花了多少」）

## 备注

「上限触顶要留痕」这一条很重要：节流的目的**不是**让值班长闭嘴，是让它在**该说话的那一次**说话。
静默丢弃会让「我明明出了事它却没说」变成一个查不出来的现象——正是本批要消灭的那类现象。
