# 13: 项目级 run 的生命周期终止者

**What to build:** 给项目级伪阶段 run 一个明确的终止者——**修调度器的洞，不是给漏洞加观测**。

`check_timeouts` **有意跳过**项目级 run：
`if run.task_id.is_none() || run.cursor_id.is_none() { continue; }`
（`crates/core/src/scheduler/mod.rs:158-162`，注释说生命周期归 analyze 端点收尾）。

**实证（2026-09-17）**：`pseudo:project_analysis` 的三条 run（id 10 / 11 / 12）的
`last_activity_at` **冻结在 11:11 / 11:15**，**跨一次重启存活**，仍是 `running`。
原因是双重的：它们没有 `task_id`，`requeue_running_tasks` 不认它们（`crates/app/src/serve.rs:324-329`）；
`check_timeouts` 又有意跳过。**它们是永不清理的僵尸行。**

更早的同类（run 7 / 8）跑了 **4 小时 24 分**，两条还在同一分钟内一起结束（07:39:48 / 07:39:27）
——那个时间点像是一次重启，不像一次完成。

**所以这一条不是「让值守去盯」，是修调度器的洞。** 让值班长去盯一个「按设计就不该被盯」的东西，
是在给漏洞加观测而不是修它。

**Blocked by:** None（与其余各线无依赖，可并行）

**Status:** done

- [x] **动手前先把 analyze 端点读一遍**（`crates/app/src/routes/projects.rs:139-210`），
      确认它今天怎么收尾、在哪些路径上会不收尾
- [x] 给项目级 run 自己的超时（与节点超时语义**分开**——注释里那条理由是对的：
      它没有游标、不属节点超时语义）
- [x] 或者给它一个明确的终止者（谁起谁收、异常路径也要收）
- [x] 重启时的归队：项目级 run 要么一并归队，要么明确标成中断终态
      （**现在是最坏的一种：留在 `running`**）
- [x] 僵尸行清理：一次性把既有的 `running` 且心跳停止的项目级 run 标成终态（带原因）
- [x] 万一它确实会阻塞后续分析（`POST /projects/analyze` 若按「已有 run 在跑」去重），
      这一票要顺带解开——**先查证，别假设**
- [x] 新增用例：一条心跳停止的项目级 run 在 N 分钟后被标终态，且原因可读
- [x] 新增用例：重启后不存在 `running` 的项目级 run（无论归队还是标中断）

**实施收尾（2026-09-18）:**

- **先读了 analyze 端点**（票面的第一条要求）：它在**成功与失败两条路**上都会
  `finish_run`（成功 `Success`、LLM 不可用 `Failed`），收尾本身没问题；会不收尾的路径是
  **进程被杀 / 重启**——那条路径上 spawn 出去的任务随进程消失，run 行留在 `running`。
  故票面那句「先查证」的答案是：不是端点漏了收尾，是**异常路径没有终止者**。
- **另查证一件事**（票面的「先查证，别假设」）：`POST /projects/analyze`**不做去重**
  （每次都 `create_analysis` + 新 run 行），所以僵尸行不会阻塞后续分析——这一票不必解开什么。
  代价是它们会一直累积，故清理仍然必要。
- **终止者落在两处，共用同一个阈值**（`project_run_idle_timeout_sec`，默认 900s）：
  - 调度器 tick 新增 `abandon_stale_project_runs`：`running` 且心跳停了超过阈值 → 标
    `Timeout` + 一句可读原因（含停了多久、为什么归它管）。活着的那些心跳会刷新，不误伤；
  - 启动时一次性收（`Store::abandon_stale_project_runs`）：重启那一刻**所有**项目级
    `running` 都是孤儿，故这里不设宽限——「还有心跳」在重启后是不可能成立的条件。
- **为什么不给它归队**：项目级伪阶段不是「可以续上的活」——它是一次「探测 + 一次 LLM 摘要」，
  重跑一次比续接更简单，而续接没有游标可依。标中断终态是这一票的诚实选择。
- **三条用例**：心跳冻结 1 小时的被标终态且原因可读；心跳新鲜的不误伤；重启后不存在
  `running` 的项目级 run。

## 备注

票 05 的事件清单里**没有**这一类，是有意的：值守不该去补偿一个调度器自己的洞。
但值守**可以播报**它——所以这条修好之后，若还有项目级 run 长时间无心跳，那就是真需要人看的信号。
