# 对讲台信息流回看（talk-replay）

**Status:** ready-for-agent

> 来源：用户诉求「重新进入对讲台只能看到此后的信息流，之前的信息流看不见，能否优化」，
> 经 grilling 19 轮（Q1–Q19）逐项裁决定形。两轮代码探查的事实依据与全部裁决记录见对话
> 承载的共识稿；本 spec 是其定稿。
>
> **本 spec 显式修订五处既有口径**，落表时按本仓惯例标注修订编号：
> **决策 223**（不做进程退出那一轮的落账）、**决策 260**（回话落库才算数 + 裁决③
> 本地半截字合成）、**决策 182④**（消息与全仓同一把保留期尺）、**决策 204⑦**
> （归档不保护消息）、以及后端读接口**「不分页」**的产品立场。

## Problem Statement

重新进入对讲台，只能看到进入**之后**产生的信息流，进入之前的看不见。具体是三件事叠加：

**一、在飞一轮的前半段彻底看不见。** 值班长正在跑的那一轮，它的 thinking、工具调用步骤、
逐字正文只走 SSE 广播、**从不落库**——整轮结束才追加一行台账。而 SSE 是无回放的广播，
重连只收得住此后的新事件。于是刷新、切页、重启后重进，那一轮的前半段既不在库里、也补不
回流：代码注释的原话是「重接得上的是**此后的**增量，此前那些字永远不会再到达」。一轮
动辄跑几分钟，前半段恰是「它断在哪一步」最需要的信息。

**二、进程被杀时半截轮整段消失。** 一轮跑到一半关掉应用（或崩溃），已生成的前半段从未
落地，重启后连它存在过的痕迹都没有——台账里只剩一条孤立的 user 行，assistant 行永远不写。
既有决策（223「不做进程退出那一轮的落账」、260 裁决③ 前端本地合成半截字）把这一段的
呈现托付给了前端内存，而前端内存活不过重启。

**三、会话更早的消息与归档班次够不着。** 读接口只取最近 500 条、明文不分页；「归档」
只是把班次从列表里收起来并自动切走，**UI 上没有任何入口能翻回**。保留期清理（默认 30 天）
还会把消息删掉。三者叠加的结果是：「历史」在 500 条之外、归档那一刻、保留期到期三个
地方静默断掉——用户以为的「对话记录」其实是一条随时会缩短的窗口。

用户要的是：**重新进入，之前的信息流都在**——包括正在说的那一半、断掉的那半轮、
更早的那些消息、以及归档了的班次。

## Solution

把「信息流的历史」从**前端内存的现场**改为**后端台账的权威**，四条改动一起生效：

1. **在途轮边流边写。** 一轮开工即建在途 assistant 行，thinking / 工具步骤 / 逐字正文
   随广播节流落库，整轮结束收口成正常行；进程被杀留下的半截行由启动路径标成
   **已中断**。重进对讲台直接 refetch 就看得到前半段——刷新、切页、重启一条路覆盖。
2. **快照与直播精确拼接。** 在途相关 SSE 事件带上 `ledger_id` 与位置序号 `seq`，
   前端按「快照到 seq 为止 + seq 之后的增量」拼接，不重不漏。seq 只做去重、不做回放。
3. **中断轮以台账为唯一真相。** 前端退役「本地半截字合成失败轮」，重连后按台账里的
   已中断行重算时间线，带明确的中断标记渲染。
4. **历史的边界补真。** 消息表豁免保留期清理（永久）；会话内超出 500 条时向上游标
   懒加载（滚到顶再取更早）；班次 chip 行加「显示已归档」开关，归档班次以灰 chip
   打开、只读。

值守台账（`/talk/watch`）与对讲台同组件、同 store、同 SSE，自动获得同样的可见性，
无需单独实现。

## User Stories

1. As a 值班经理, I want 重新进入对讲台时看到值班长正在说的那一轮的前半段, so that 我不会因为刷新或切走再回来就丢掉它已经说过的内容。
2. As a 值班经理, I want 一轮还在跑时刷新页面，时间线上既有它开工到此刻的完整内容、又继续实时接上此后的字, so that 刷新对我来说是无感的。
3. As a 值班经理, I want 关掉应用再打开后，上次跑到一半断掉的那一轮仍出现在时间线上并带「已中断」标记, so that 我能知道它断在哪一步、而不是凭空以为那一轮没发生过。
4. As a 值班经理, I want 已中断的标记写明中断发生的时刻, so that 我能把它和当时的系统状况（关机 / 崩溃）对上。
5. As a 值班经理, I want 中断轮里保留 thinking 与工具调用步骤, so that 排查断点时能看到它当时正在想什么、正在做什么。
6. As a 值班经理, I want 中断轮与正常轮在时间线上只差一个标记、其余渲染完全一致, so that 我不需要学两套读法。
7. As a 值班经理, I want 重进后正在跑的那一轮从快照到直播的接缝处不重复字也不丢字, so that 我看到的是一条连续的对话流。
8. As a 值班经理, I want 中途重进时无需任何手动操作（点按钮 / 等提示）就能无缝续上看了一半的直播, so that 「接上看直播」是默认行为而不是要学的技巧。
9. As a 值班经理, I want 历史消息永不被自动清理, so that 我数月前和值班长的对话仍然原样在。
10. As a 值班经理, I want 单个会话超过 500 条时滚动到顶能继续加载更早的消息, so that 「更早的看不见」不会在会话内部复现我最初报的毛病。
11. As a 值班经理, I want 500 条以内时行为与现在完全一致（一次加载、直接滚动）, so that 多数时候我感知不到加载策略的变化。
12. As a 值班经理, I want 向上加载更早消息时视口不跳动、已读位置保持, so that 翻旧账不打断我正在读的地方。
13. As a 值班经理, I want 归档过的班次能通过一个开关翻回来查看, so that 我「收起来」的东西不会变成「永远找不回」。
14. As a 值班经理, I want 归档班次以灰 chip 显示在列表里与未归档的区分开, so that 我一眼知道哪些是收起来的。
15. As a 值班经理, I want 打开归档班次是只读的, so that 归档的语义仍然是「收起来」而不是「又变活跃了」。
16. As a 值班经理, I want 归档班次里能看到它的全部消息内容, so that 翻回来看的是对话本身而不只是会话元数据。
17. As a 值班经理, I want 在值守台账看到与对讲台同样的历史可见性, so that 两个入口读的是同一份事实、不需要分别确认哪边看得见。
18. As a 值班经理, I want 应用重启后归档班次与它的消息都还在, so that 永久历史不是「重启前永久」。
19. As a 值班经理, I want 保留期清理继续管运维侧的数据（提议、待办、任务会话、worktree）, so that 取消消息清理不会让磁盘无人打理。
20. As a 值班经理, I want 对讲台的归档动作确认文案不再说「30 天到期清理」, so that 界面说法与新的永久语义一致。
21. As a 排查断点的人, I want 已中断轮标明它是「中断」而不是「说完了」, so that 不会把半截话误读成完整结论。
22. As a 排查断点的人, I want 台账里那条中断行的落库内容尽可能接近断开前最后广播的字, so that 「断在哪一步」的取证不因节流而明显缺损。
23. As a 值班经理, I want 正常结束的轮收口后台账只有一行完整消息, so that 台账不因「边流边写」变成一地碎片。
24. As a 值班经理, I want 一轮失败时它的 user 行与部分结论照旧按既有语义落账, so that 决策 182② / 233 / 292 的既有行为不回退。
25. As a 值班经理, I want 发送中的停钮、提议确认钮等既有交互在新的写路径下行为不变, so that 本次优化不改变任何与历史无关的操作手感。
26. As a 前端读者, I want 中断轮的渲染判据是一个可单测的纯函数, so that 「清 / 留 / 以何姿态留」的纪律有机器门守着。
27. As a 前端读者, I want 快照与增量的拼接判据同样是纯函数, so that 防重防漏不依赖「测出来恰好没重」。
28. As a 维护者, I want 「在飞时台账里已有半截 assistant 行」成为契约测试钉住的语义, so that 有人改回「整轮结束才落」时立刻变红。
29. As a 维护者, I want 启动路径把悬挂的在途行标成已中断，与既有孤儿收口序列同姿势, so that 半截行不会永远显示「正在说」。
30. As a 维护者, I want 五处被修订的既有口径在决策日志里显式标注修订编号, so that 未来读者引用旧决策时能看到它已被本 spec 改写。
31. As a 值班经理, I want 任务对话（流水线 run 的会话）的同类问题被记录为后续票, so that 它不被遗忘也不被夹带进本轮半生不熟地实现。

## Implementation Decisions

**核心：台账从「整轮落地」改为「边流边写」。**

1. **在途行的生命周期**：一轮开工（user 行落库的同一时机）即创建 assistant 在途行；
   节流批写（合批节流的节拍是实现细节，目标是接缝窗口 ≲ 300ms）；整轮正常结束时收口
   为完整行——台账最终形状与今天一致（一次回话 = user 行 + assistant 行），「边流边写」
   不改变收口后的行数语义，只改变中途是否可见。
2. **中断标记**：进程被杀时在途行留在库里；启动恢复序列（既有三步之后）新增一步，
   把没有活跃轮对应的在途行标成**已中断**并记中断时刻——与 `orphan_inflight_model_requests`
   的孤儿收口同姿势。中断是行上的状态，不是新表。
3. **保真范围 = 全保**：thinking、工具调用步骤、逐字正文三者都随广播落库，重进后的
   前半段与当时直播所见同构。收口时的最终落库内容仍以整轮产物为准（既有路径不变）。
4. **契约改写**：`.scratch/foreman-talk/CONTRACT.md` 的「写 user 行 → 循环 → 写 assistant 行」
   改写为「写 user 行 + 建在途 assistant 行 → 循环（每步边广播边落库）→ 收口」。
5. **快照与直播的衔接**：`GET /foreman/session` 的 payload 天然带出在途行（messages 里
   多了那条半截行）；在途相关的 SSE 事件新增 `ledger_id`（所属行 id）与 `seq`（该行内
   位置序号）。前端判据：取快照记 `seq0`，只接受 `seq > seq0` 的增量。**seq 只用于去重，
   不用于回放**——不违反决策 275（275 禁的是 SSE 回放与 localStorage 回填，本方案仍是
   DB 权威 + refetch 校准）。
6. **前端退役本地半截字合成**：`resolveFollowOutcome` 三支（keep / settled / lost）中
   的 lost 支不再合成失败轮，改为「以台账已中断行重算时间线」；「任何一支都不许清掉
   已经出现的文字」的纪律由台账保证（字已在库里）。回退代价：重连瞬间最多回退最后
   ~300ms 未落库的字——可接受，那部分字本来也没进库。
7. **turn_in_flight 读数语义不变**：仍是进程内登记的直接读数，回答「此刻有没有轮在跑」；
   台账的在途/中断行回答「此前发生了什么」。两者分工，不合并。
8. **保留期豁免**：`kanban_foreman_messages` 退出按 `conversation_retention_days` 的清理，
   只摘这一张表；proposals / attention / 任务会话 / worktree 回收照旧吃同一 cutoff。
   既有「保留期到点被清理」的测试改写为反向断言（消息永存、其余照旧被清）。
9. **会话内向上游标**：读接口保留「最近 500 条」缺省语义，新增 `before_id` 游标参数
   （按行 id 升序补更早段）；前端滚到顶触发。500 条内不新增任何请求。
10. **归档可翻回**：会话列表新增 `include_archived` 能力（后端已有按 id 读含归档的
    路径，缺的是列表）；前端在班次 chip 行加「显示已归档」开关，归档班次渲染为灰 chip，
    打开为只读时间线（不提供续聊、不提供「恢复归档」动作）。
11. **watch 同源**：上述所有可见性对 `/talk/watch` 自动生效（同组件同 store 同 SSE，
    只差 `?kind=` 参数），不写分支逻辑；归档开关在 watch 模式同样可用。
12. **契约测试语义改写**（显式修订）：在飞期间 session payload 的 messages 不再是
    「只有 user 那句」，而是含半截 assistant 行——api_contract 中钉旧语义的断言按
    决策 260 行内改写。
13. **显式修订清单**（落表标注）：决策 223（进程退出轮不落账 → 落一条已中断行）、
    决策 260（回话落库才算数 → 在途即落库、收口才算完整；裁决③ 本地合成退役）、
    决策 182④（同一把保留期尺 → 消息表豁免）、决策 204⑦（归档不保护消息 →
    归档且清理豁免后消息永存）、后端「不分页」立场（→ 500 缺省 + 向上游标）。
14. **词汇表同步**：glossary 的班次条目「归档 = 从列表里收起来，消息照旧按保留期清理」
    需随 13 改写；在途轮条目补「台账有半截行」。

## Testing Decisions

**好测试的判据**：只断言外部可观察行为——API payload 形状、台账行的有无与状态、
时间线上渲染出什么；不断言内部调用了几次批写、用了什么节拍。

**接缝**：不新增任何可测试性接缝。主接缝取**对讲台线协议**（`GET /foreman/session`
payload + `/foreman/stream` 事件）——前后端唯一交汇点，在这里钉住两端同时覆盖。
其余全部落在既有测试层：

| 层 | 测什么 | 复用的既有装置（prior art） |
|---|---|---|
| L2 core 集成 | 在途行随轮推进而增长且节流生效；启动恢复把悬挂行标已中断（spawn+SIGKILL 形态）；保留期假时钟推过 30 天后消息仍在、proposals/attention 仍被清；收口后台账恰两行 | FakeAgent `Script::for_foreman()` 脚本槽（决策 182⑧）、testkit 临时 home、`Clock` 接缝、`restart_recovery.rs` 的真重启形态（票 08） |
| L3 契约 | 在飞时 messages 含半截 assistant 行且 `turn_in_flight` 照旧翻转；`include_archived` 列表含归档且按 id 仍可读；`before_id` 游标分段正确；SSE 在途事件带 `ledger_id` / `seq` | tower oneshot in-process；`api_contract.rs` 的 foreman 既有用例（改写钉旧语义那几条） |
| 前端 vitest | 快照+seq 拼接的防重防漏（纯函数：seq ≤ seq0 丢弃 / > 接受 / 无 seq 按老路径）；中断轮渲染判据（接替 `resolveFollowOutcome` 的 lost 支）；归档 chip 开关状态；滚顶加载不重不漏 | `realtime/foreman.test.ts` 归约表、`lib/talkTurns.test.ts`、`lib/delegation-scan.test.ts` 静态扫描守卫（落地哨改动必须过它） |
| L4 playwright | 重进看得到前半段；刷新后快照与直播接缝不重不漏；重启后中断轮带标记出现在时间线；归档开关翻得回、灰 chip、只读；滚到顶加载更早且视口不跳 | 既有 `talk.spec.ts`（决策 260 刷新用例在此，续写不新开 spec） |

**牙齿要求**（每条修订对应一颗）：改回「整轮结束才落」→ 契约测试红；启动不标中断 →
L2 红；清理函数又被接回消息表 → 保留期反向断言红；拼接判据退化 → vitest 红；
落地哨退回就地清字 → delegation-scan 红。

## Out of Scope

- **任务对话（流水线 run 的会话）的在途可见性**：同病（attempt 结束才落库），
  但通道与表结构不同（messages_json 整行重写 vs 消息逐行追加），记为后续票、不进本轮。
- **多窗口 / 多端同时观看**（Q4 裁定不做）。
- **SSE 回放**（决策 275 继续禁）与 **在途回填 localStorage**（同）。
- **归档班次的恢复续聊 / 物理删除 / 导出**（Q6：不做额外管理；Q15 只要只读入口）。
- **保留期配置的全局移除**：只摘消息表，不废 `conversation_retention_days` 本身。
- **检索 / 搜索历史消息**：本轮不引入。
- **中断轮的续跑**：已中断即终态，不提供「接着跑」。

## Further Notes

- **三处既有事实是本 spec 的地基**：① 消息表主键 `id INTEGER PRIMARY KEY AUTOINCREMENT`
  单调递增，前端已在把它当游标用（`maxLedgerId`），`before_id` 与 `seq` 都长在这上面；
  ② `/talk/watch` 与对讲台同组件同 store，watch 的受益是零成本的；③ 启动恢复序列已有
  「孤儿收口」先例可挂。
- **一处已知的交互交叉点**：`talk.watch(id)` 换班会 `resetLive()`，从 `/talk` 跳
  `/talk/watch` 会清一次在飞现场（决策 204③ / 220⑤ 的既有设计内行为）——本轮不改它，
  但实现时注意别让新的在途行渲染与它打架。
- **glossary 两处待同步**（见 Implementation Decisions 14），由票面记账，避免词汇表
  与实现各说各话——「工头一词指两个人」的历史教训。
