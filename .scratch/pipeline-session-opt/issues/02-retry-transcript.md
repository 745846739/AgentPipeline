## Comments

- 来源：同一会话复盘——run40/41 连续两败且探索费三付（同批文件读了三遍）；retry_prompt（决策 33 文档承诺的「错误回填」）在生产路径零调用，run40/41 的提示词里根本没有错误反馈。

- **评审记录（2026-09-25）**：三类失败中「超时」的边界——agent loop 内的 LLM 调用失败（含流读取超时）已由本机制续接；**调度器判的节点级停滞超时**（决策 64 / 226）是另一层：run 被外部判死、执行体可能已不在，其自动重试仍按决策 33 / 205 原口径干净起步，而人工续跑（resume cause `Timeout`）本就在 `resume_continues` 的 true 栏续接。若要把调度器层的超时重试也续接，须单独立决策——本票的机制（错误 turn 在循环内追加）覆盖不到那一层。
