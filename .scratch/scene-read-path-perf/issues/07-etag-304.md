# 07: ETag / 304——回看已完成任务时不再重搬

**What to build:** 用户的痛点是「每次打开同一个任务都等几秒」，而任务内容在两次打开之间
**常常没变**。给两个端点的响应加 `ETag` + `If-None-Match` 协商，命中就回 **304（零字节）**：

- `GET /tasks/{task_id}/conversations`（含票 03 加的 `include_messages=true` 分支）——
  现场页签的全部载荷就在这里；
- `GET /tasks/{task_id}` —— 详情页的头部/游标/动作。

**收益集中在「回看已完成任务」**：跑着的任务每次都变，跑完的则完全不变。改动后可把
`/commands`（票 02 已移出首屏、票 01 已压缩）与批量会话在重复打开时降到 0 字节。

**Blocked by:** 01, 02, 03（票 03 引入批量读法是 ETag 的主要受益面；票 01/02 先落地才
看得出 ETag 的边际收益还剩多少）

**Status:** done（2026-10-06，决策 361⑦）

## 落点

- `crates/app/src/routes/tasks.rs`：两个 handler 计算版本键 → `ETag` 响应头，
  读 `If-None-Match` 命中则 304（注意 304 不回 body，但必须保留 `ETag` 与缓存相关的头）。
- **版本键的坑（必须处理）**：会话摘要的 `status` 字段是从台账 `list_runs` 贴进来的
  （`tasks.rs:843-852`），所以**一个 run 从 `running` 变 `done` 时，会话列表的 ETag 必须变**
  ——只用「会话行数 + MAX(id)」当版本键会漏掉这次变化。版本键至少要覆盖
  `(conversations 的 MAX(id), 行数, include_archived 布尔, runs 的状态集合)`，
  或退而求其次对响应体取哈希。
- 别给流式响应（SSE）加 ETag。

## 验收

- [x] 第二次打开同一个**已完成**任务：`/conversations`（含 messages 分支）命中 304，
      `size_download` 为 0，页面数据照常显示（浏览器复用缓存）
- [x] **跑着的任务不会拿到过期 304**：一个 run 从 `running` 变 `done` 之后，同一 `If-None-Match`
      必须拿到 200 与新内容（这是本票最容易写错的判据，要有测试）
- [x] 不同 `include_archived` / `include_messages` 组合给出**不同** ETag（参数参与版本键）
- [x] SSE 路由不带 ETag，且直播行为不变
- [x] `make api` 契约测试覆盖 200 / 304 两条路径；`make check` 全绿

## 实施收尾（2026-10-06）

- **版本键取了「退而求其次」那条路并更稳**：`etag_response(key, headers, body)` 对
  「端点 + 参数 + 序列化响应体」整体取 sha256——台账一变，贴进摘要的 `status` 就变，
  哈希跟着变，票面警告的过期 304 判据由构造保证，不靠枚举版本键的组成。
  参数（`include_archived` / `include_messages`）显式进键：一张视图的 ETag 不替另一张背书。
- **`Cache-Control: no-cache` 与 ETag 同发**（200 与 304 都带）：它是协商缓存生效的前提
  ——让浏览器每次都来对账，命中才免搬运。只做协商缓存，不做强缓存（票面「明确不做」照旧）。
- `If-None-Match` 按 RFC 7232 弱比较：逗号分隔的列表与 `W/` 前缀都接。
- **测试**（`api_contract.rs`，`make api` 层）：`etag_304_on_second_read_of_a_completed_task`
  （三个读法各验 200→304：零字节、ETag 保留）、`etag_changes_when_a_run_goes_from_running_to_done`
  （run `finish_run` 后同一 If-None-Match 必须回 200 且状态是 success）、
  `query_combinations_get_distinct_etags`（三种组合 ETag 互异；A 视图的 ETag 打 B 视图必 200）。
  SSE（`stream` handler）未动，不带 ETag。

**明确不做**：`Cache-Control: max-age` 强缓存（任务内容会变，强缓存会给出过期数据；
只做协商缓存）；给 `/commands` 加 ETag（票 02 已把它移出首屏，边际收益低——若后续发现
现场页签的命令部分值得，再另开）。
