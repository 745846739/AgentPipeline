# 04: 排队发送——在飞时输入解锁，发出即入队，收口自动发

**What to build:** 对讲台输入坞改成 ZCode 式排队发送（用户 2026-09-29 拍板，替代
「在飞锁坞」方案）：一轮在飞时输入框解锁、回车可再发；发出的句子进**发送队列**，
当前轮收口后自动发出。队列**允许多条**、在坞里**可见、可编辑、可撤回**；
队列状态住 store（跨页面存活，与决策 275 同判据）。**当前轮死轮 / 中断时队列扣住等确认**
——不自动照发，把「它不会再来」的可见性留在人手里。值守轮插进来不算收口、不触发下一句。

**Blocked by:** 01（收口判据复用身份统一的守卫语义）

**Status:** done（已实现，决策 316）

- [x] `stores/talk.svelte.ts` 增发送队列：多条有序、push / 编辑 / 撤回三个动作，住 store
- [x] 输入坞解锁：`disabled={sending}` 改为只在配对缺失等真阻塞时锁；发送守卫放行在飞
- [x] 当前轮收口（settleTurn / syncFollowing 落地支）自动出队发送下一条；值守轮到达
      （foreign / 播报事件）不触发出队
- [x] 死轮（resolveFollowOutcome lost）与中断行：队列扣住，坞内明示「上一轮没回来，
      排队的话等你确认再发」；确认 / 撤回两个出口
- [x] 队列条 UI：每条可编辑（就地改文案）、可撤回；跨页面存活（切页回来队列原样）
- [ ] 单测：收口自动出队；死轮扣住；值守轮不触发；队列随 store 跨挂载存活
- [ ] 实测：连发三句（首句在飞），三句按序落进时间线，中途撤回第二条不影响其余
