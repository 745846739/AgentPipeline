# 22: 决策：界面正文里的内部决策编号怎么处置，可追溯性交给什么

**叠:** B-决策（一票只回答「怎么定」；本票不动任何代码）

**What to build:** 设置·项目、模型与密钥、阶段配置、指标、手机访问、技能市场——每一页都在
向使用者引用内部设计日志的编号。对维护者有用，对使用者是噪声，而且常常给的是**理由**而不是
**动作**（「删除有活跃任务的项目会被拒绝并给出原因（决策 101）」里，用户需要的是
「先去处理那 3 个任务」）。但现行视觉规格里有一条明文**要求**把某条编号渲染进界面，
所以这不是修 bug 而是改规格。这一票只回答「怎么定」：编号收到哪、可追溯性由什么承担、
跟那条明文要求怎么处理。

**Blocked by:** None（can start immediately）
