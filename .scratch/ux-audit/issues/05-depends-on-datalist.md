# 05: 「新建任务」的依赖任务 ID 给一个原生候选项列表

**叠:** A（不动规格）

**What to build:** 依赖任务现在要用户手打（或粘贴）一串 ULID——没有选择器、没有候选、
没有最近任务。改成在同一个输入框上挂一个原生候选项列表（不做完整选择器），候选来自
当前项目已有的任务，能靠标题区分；手打与粘贴的路径仍然可用。

**Blocked by:** None（can start immediately）

**Status:** done

- [ ] 输入框聚焦或输入时出现候选，候选是当前项目已有的任务，并带可区分的标题
- [ ] 选中候选项即填好该任务的 ID；直接手打 / 粘贴 ID 仍然成立
- [ ] 逗号分隔的多个依赖仍然成立，候选只对正在输入的那一段生效
- [ ] 可选：从任务详情的「加个依赖」路径也走到同一个输入体验（如果详情页有这个动作）
- [ ] e2e：新建任务时从候选里选一个依赖 → 提交 → 断言该任务带上了这个依赖
