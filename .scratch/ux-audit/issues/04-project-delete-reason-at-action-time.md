# 04: 项目页：删除被拒的理由挪到动手时出现，破坏性动作不再比中性动作轻

**叠:** A（不动规格）

**What to build:** 项目列表现在每一行**常驻**一条红字解释（「该项目有 3 个活跃任务，不能删除」），
用户还没动手就先看到报错。同一行里「删除」是 danger 样式（无投影、无描边），而「编辑 / 分析」
带 3px 硬投影，于是破坏性动作看上去比中性动作**更轻**。改成：理由在用户要动手时才出现，
被拒时给的是下一步该做什么（「先去处理那 3 个任务」）而不只是原因；破坏性动作在视觉上
不比中性动作轻。

**Blocked by:** None（can start immediately）

**Status:** done

- [x] 有活跃任务的项目，列表里不再常驻那条红字解释
- [x] 点删除被拒时给出可执行的下一步，而不只是「不能删除」的原因
- [x] 破坏性动作在视觉上不轻于中性动作（同一档量级：不更小、不更淡、不少一层描边）
- [x] e2e：一个有活跃任务的项目 → 断言未点删除时页面上没有那条红字 → 点删除 → 断言出现下一步说明
- [x] 计算样式断言：破坏性动作与中性动作的量级关系（照既有「在真应用上断言计算样式」的那类用例写）
