## 目标文件：`frontend/e2e/pixel-theme.spec.ts`（所有权在 T）

> **行号以文本匹配为准**（本 handoff 起草时该文件正被 T 并行增补，行号已漂过一轮：
> 桌面那句现在在 `:253`、移动款那句在 `:379`；按下面引的**原文**找，别按行号找）。

**要什么**

1. **「顶栏过滤是 34px 道具栏槽位（图标 + 计数徽章）」一段**（现 `:249-256`）：
   `expect(slotBox?.width).toBe(34)` 不再成立——桌面款七个槽**都带 12px 词**，宽度随词走
   （`.slot` 现在是 `min-width: 34px` 的图标 + 4px 间距 + 词）。请改成断言**高度仍 34px**
   且**宽度 ≥ 34px**（或断言首槽的宽度等于它的内容宽度），并把注释从「图标 + 计数徽章」
   改成「图标 + 词 + 计数徽章；**待处理槽不画徽章**（决策 201 的计数去重）」。
   `expect(await slot.locator('.cb').count()).toBe(1)` 仍成立（首槽是 `全部`，保留徽章）。
2. **移动款那一段**（现 `:377-379`）：`expect(slotBox?.width).toBe(34)` 同样不再无条件成立
   ——窄屏（<480px）**只给当前选中槽带词**，其余六槽是 34px 图标槽。缺省过滤是 `全部`，
   它**是**当前选中槽，故首槽在 430px 下带词、宽于 34px。请改成断言
   **当前未选中的槽仍为 34px**（例如第 2 个槽 `.slot:not(.on)`），或把断言改成「高度 34px、
   宽度 ≥ 34px」。
3. 可选但推荐：**新增一条断言**落在决策 201 的计数去重上——第 3 槽（`待处理` / sprite `alert`）
   `.cb` 计数为 0，而紧邻的「待处理 N」芯片仍在（那是 pending 数的唯一显示位）。

**为什么**

决策 201 把七个只有图元的过滤槽改成「图标 + 词」（34px 高度、共享 2px 边框、零圆角、
选中态一律照旧），并按「同一个数不得在相邻的两个控件上同时出现」去掉第 3 槽的计数徽章。
`pixel-theme.spec.ts` 这两条断言钉的是**改动前**的形态（只有图元、所以定宽 34px），
形态变更是规格变更（决策 201 裁决④），断言要跟着口径走——**高度、2px 描边、零圆角、
共享边框这些纪律一条不变，变的只是宽度不再恒定**。

实现侧（`frontend/src/components/layout/TopBar.svelte`）由 **N** 做，已在本次改动里落地。
