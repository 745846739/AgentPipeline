# DEC-IA → DEC-VIS / T（票 26 / 决策 201）：道具栏槽位的形态由「图标 + 计数徽章」改为「图标 + 词」

**目标文件**

- `design/theme-6-pixel.md`（§2.3 的「顶栏道具栏」一条，约 :141；§3 组件映射的「顶栏过滤」一行，
  约 :406；**文件所有权在 DEC-VIS**，请编排者按票面口径转交——票面点名实现侧由 **N** 做，
  视觉规格侧由 **DEC-VIS / T** 改）

**要什么**

1. **§2.3「顶栏道具栏」一条改写**：

   - 原文：`- **顶栏道具栏**：过滤项做成 34px 槽位（共享 2px 边框、图标 + 右下角计数徽章，hover 出 title 提示）；当前选中槽位 = 亮描边 + wash 底（游戏物品栏选中框）。`
   - 改为：`- **顶栏道具栏**：过滤项做成 34px 高槽位（共享 2px 边框、**图标 + 词 + 右下角计数徽章**，hover 出 title 提示）；词取 `FILTER_LABELS` 的七项（第 7 槽标签位用短式「已结束」），**待处理槽不画计数徽章**——那个数由紧邻的「待处理 N」芯片唯一承载（决策 201 的计数去重）；窄屏（<480px）只给当前选中槽带词；当前选中槽位 = 亮描边 + wash 底（游戏物品栏选中框）。`

   形态纪律不变：34px 高度、2px `--pane` 描边、相邻槽共享边框、零圆角、选中态照旧，
   **不新增图元 / 颜色 / 动画位**。

2. **§3 组件映射的「顶栏过滤」一行改写**：

   - 原文：`| 顶栏过滤 | **道具栏槽位**：图标 + 计数徽章；选中槽位 = 亮描边 + wash 底 |`
   - 改为：`| 顶栏过滤 | **道具栏槽位**：图标 + 词 + 计数徽章（待处理槽不画徽章，数在「待处理 N」芯片上；决策 201）；选中槽位 = 亮描边 + wash 底 |`

3. **两处各加一条修订标注**（措辞可改，决策号与「改规格不是修 bug」必须留）：

   > **修订决策 201（2026-09-16「ux-audit」审计票 26）：** 七个只有图元的槽位读不出
   > 「全部 / 执行中 / 待处理 / 等依赖 / 排队 / 已完成 / 已结束」这套词表，故槽位补上词；
   > 同时去掉待处理槽的计数徽章（它与紧邻的「待处理 N」芯片是同一个数——**同一个数不得在相邻的
   > 两个控件上同时出现**）。计数徽章、选中态、34px 与共享边框一律保留；**这是交互形态的规格变更，
   > 不是修 bug**（本文件由决策 169 升格为现行视觉规格时把交互与形态的改动划出了范围）。

4. **在「实现期与原型的有意偏离（已登记）」表（约 :450 起，表头 `| 处 | 原型 | 实现 | 依据 |`）
   里加一行**：

   | 处 | 原型 | 实现 | 依据 |
   |---|---|---|---|
   | 顶栏道具栏槽位 | 34px 图标槽 + 计数徽章（无词，七个槽都带徽章） | 34px 图标 + **词** + 计数徽章；**待处理槽不带徽章**（数在「待处理 N」芯片） | **决策 201**（词表要屏上可读；同一个数不在相邻控件上重复） |

   同一张表还要加决策 198 与决策 199 两行（见 `DEC-IA-20.md` / `DEC-IA-22.md`）——**三行一次性加完**。

**为什么**

审计的原始发现是：七个**只有图元**的槽位传达不了那套词表（`title` 与 `aria-label` 在触屏上等于
不存在），而紧邻的「待处理 N」芯片与第三个槽的徽章**是同一个数**、底部状态行再说一遍。
决策 201 的裁决是**图标 + 词**（否决「收进一处」与「只留悬停」）并把 pending 数收敛到芯片一处。
视觉规格那两行明文写着「图标 + 计数徽章」，与裁决冲突，故按惯例**追加修订决策并在原文处标注**；
DEC-IA 名下没有 `design/theme-6-pixel.md`（DEC-VIS 的文件），按 §一.1 走交接。

决策日志行 `.scratch/ux-audit/.rows/201.md`；票 `.scratch/ux-audit/issues/26-decision-filter-slots.md`。
