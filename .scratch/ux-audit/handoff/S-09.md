**口径来源**：`.scratch/ux-audit/issues/09-settings-subheading-level.md`（「小节标题与页面标题
当前同为最大一级字号（24px）→ 落到 12px 字距档」）；`parallel-brief.md` §一.1（app.css 是你的文件）。

---

## 目标文件：`frontend/src/app.css:540` 附近的 `.sub-head h2`

**现状**：基元是 24px——

```css
.sub-head h2 {
  font-size: 24px;
  color: var(--text-hi);
}
```

但这条基元**目前只剩两个用户，且都已经在本组件里覆盖成 12px 字距档**：

| 用户 | 处置 |
|---|---|
| `components/settings/AnalysisChecklist.svelte` | `.checklist .sub-head h2 { font-size: 12px }`（既有） |
| `routes/SettingsProviders.svelte` | 该段已随票 21 搬去 `#/settings/stages`（N 名下），本页不再有 h2 |

即：基元值与它的全部用户**互相矛盾**，读基元的人会以为「小节的默认是 24px」，
而实际渲染永远是 12px。这正是本 effort 要治的那类漂移（规则与实现对不上，没人发现）。

**要什么**（二选一，你定）：

1. 基元改成小节该有的那一档——`font-size: 12px; letter-spacing: 0.08em;`（与各页字号对齐），
   然后把 `AnalysisChecklist.svelte` 里那条重复的局部覆盖删掉（S 来做，你说一声就行）；
2. 或删掉这条基元（连同 `.sub-head` 的盒式规则若也无人用），只留各页的局部类。

**为什么**：票 09 的验收是「设置各页的小节标题明确小于页面标题，且不引入阶外字号」。
S 名下两页已在真应用上断言（`frontend/e2e/settings-empty-and-copy.spec.ts` 的
「设置页的小节标题明确小于页面标题」）；N 的 `#/settings/stages` 有自己的局部类与断言。
剩下这一条基元是死值，留着会让下一个加设置页的人照着它写出 24px 的小节标题。
