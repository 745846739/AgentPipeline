# S → T / 编排者（票 04）：`app.css` 的 `.btn.danger` 全站定档：破坏性动作不比中性动作轻

**口径来源（照抄别改）**：`.scratch/ux-audit/issues/04-project-delete-reason-at-action-time.md`
第 3 条验收「破坏性动作在视觉上不轻于中性动作（同一档量级：不更小、不更淡、不少一层描边）」；
用户故事 20（spec.md）「作为**扫一眼设置页**的人，我希望破坏性动作（删除）不要在视觉上比中性动作更轻」；
`parallel-brief.md` §三.1「组件里只许改用的 token」+ §一.1（他人的文件走 handoff）。

## 目标文件：`frontend/src/app.css`

**要什么**：把 `.btn.danger` 从「弱化的次级动作」写法拉回与 `.btn` 同一档量级：

```css
/* 现在（app.css：`.btn.quiet, .btn.danger` 那一组）——透明描边、无实底、无投影 */
.btn.danger {
  border-color: transparent;
  background: none;
  box-shadow: none;
  color: var(--stop);
}
```

改成（**只把描边与文字换成失败红，量级与 `.btn` 完全一致**）：

```css
.btn.danger {
  border: 2px solid var(--stop);
  background: var(--panel);
  color: var(--stop);
  box-shadow: 3px 3px 0 var(--ink);
}
.btn.danger:hover:not(:disabled) {
  border-color: var(--stop);
  color: var(--text-hi);
}
```

注：`.btn.quiet`（真正弱化的次级动作）**保持原样**——「取消」「测试连接」那些是次级动作，
它们轻是对的；这条票只针对**破坏性**动作。`.btn.danger:active:not(:disabled) { transform: none }`
那一行是否跟着中性钮按压位移，由你定（量级三要素是描边 / 投影 / 尺寸，按压手感不在验收里）。

**为什么**：S 名下的两个台账页（`SettingsProjects.svelte` / `SettingsProviders.svelte`）已就地
用局部规则把 `删除` 拉到与 `编辑` 同档（2px 描边 + 3px 硬投影 + 实底），e2e 也在真应用上
断言了这一条（`frontend/e2e/settings-empty-and-copy.spec.ts` 的「破坏性动作在视觉上不比中性动作轻」）。
但**全站**还有两处同样的并排比较没被覆盖，且它们与「扫一眼设置页的人」是同一诉求：

- `frontend/src/components/settings/SkillDeclList.svelte`：`信任此技能`（quiet）与 `移除`（danger）并排
  ——现在 `移除` 比一个**次级**动作还轻；
- `frontend/src/routes/SettingsMarket.svelte`：`覆盖安装`（danger，覆盖同名技能是不可逆的）。

app.css 是你的文件，S 不动。你定档之后，S 那两份局部规则可以删掉（重复的同一档值不冲突，
但不能留成两个事实源）。
