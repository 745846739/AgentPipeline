# UX 审计后的界面可读性与信息架构整备

**Status:** done（27 张票全部落地）

**Slug:** `ux-audit`

**来源:** 2026-09-16 对真应用做的一轮 UI/UX 审计（46 张截图与逐条证据留在本目录 `README.md`，
默认被 `.gitignore` 排除；用 `UX_AUDIT=1` 重跑 `frontend/e2e/ux-audit.spec.ts` 可重新生成）。

---

## Problem Statement

我要把这个工具**开源出去给其他人用**，但现在的界面是照着维护者自己的脑子写的。

陌生人的第一分钟会花在猜词上，而不是用工具：一打开看见七个只有图标的过滤槽，
八列工位里有三列在屏幕外（**最决定性的 merge 与 done 恰好是看不见的那两列**）；
指标页第一段是数据库字段名加内部决策日志的编号（「成功率 = done ÷（done+failed+cancelled）」、
「统计口径见 core metrics（决策 130 / 137）」）；两档灰字暗到看不清空列里的「下一步做什么」
（实测 `--text-3` 对底色 3.28:1、`--text-4` 2.25:1，门槛是 4.5:1）；「急停」「值班长」「工位」
「货箱」这套词在全站出现上百处，而**没有一处**告诉外来者它们分别是什么。

阻塞与异常也缺出口：点开「新建任务」按 Escape 关不掉（焦点没进对话框，而 Escape 处理器
挂在对话框上）；走进不存在的地址只有一行灰字「页面不存在：/nope」，没有回去的路；
「删除」按钮被禁用时旁边常驻一条红字解释，用户还没动手就先看到报错。

最刺眼的一处在拍板的时候：任务卡在合入前等人时，**同一份 diff 和同一对
「返回修改 / 合入」按钮在同一屏上出现两次**（主区 Diff 页签一份、右栏档案盒一份），
于是「哪个是真的」变成使用者必须思考的问题——而「合入」是全站最重要的一颗按钮。

## Solution

打开就是三件事：**对讲台、指标、设置**。

看板先看见结论：`merge` 与 `done` 钉在右侧，中间六列的过程可以拖——宽屏钉住、窄档不钉但
打开时的滚动位置就落在 `merge`。指标页第一段改成说人话的口径说明，任务级指标不再要求
手打一个 ULID。每块设置有自己的位置，不再挤在同一页里。

界面上的字都读得清、说的是人话：灰字提到可读的档位并配一条机器门（这次的规则当初**写在
规格里、后来整节被丢掉、没人发现**）；「决策 NN」这类内部编号从正文退到悬停提示，
可追溯性交给一张「行为/规则 → 实现位置」的表；车间隐喻保留，但每个词在首次出现处给一次
平实说法，顶栏与「新建任务」这类第一屏控件直接用平实词。

阻塞都有出口：对话框按 Escape 能关、焦点进得去也出不来；404 页给回看板的路；
「删除」被拒时说清下一步而不只是报错。

## User Stories

1. 作为第一次打开这个工具的人，我希望顶栏只有三件事（对讲台 / 指标 / 设置），
   这样我不需要先学会这个项目的内部词表才能开始用
2. 作为第一次打开的人，我希望「新建任务」「看板」这类第一屏控件用平实的词，
   这样我第一分钟花在做事上而不是猜词上
3. 作为第一次看到「急停」的人，我希望在它首次出现的地方看到一次平实说法
   （等你拍板的阻塞），这样我知道它要我做决定而不是出了故障
4. 作为第一次看到「值班长」的人，我希望立刻知道那是跟我对话的 AI，
   这样我不会以为在跟某个人类同事说话
5. 作为第一次看到「工位」的人，我希望知道那是流水线的阶段而不是一个人，
   这样列的语义不会错位
6. 作为看板前的使用者，我希望 `merge` 与 `done` 两列钉在右侧，
   这样我在 1440px 的屏上也能一眼看到「谁在等我拍板」与「谁跑完了」
7. 作为小屏笔电或平板上的使用者，我希望打开看板时的滚动位置就落在 `merge`，
   这样我不必先把六列过程拖过去才看见结论
8. 作为看板前的使用者，我希望知道右边还有列没显示，
   这样我不会以为这个流水线只有六站
9. 作为看板前的使用者，我希望脊线上那个数字说清它是「累计到过这一站」而不是「此刻在这一站」，
   这样它跟列头那个数字不会被我当成同一件事
10. 作为读列头的人，我希望并行分支那两个站名标签的遮罩真的遮住传送带（而不是比原型窄一圈
    所以站名被链节吞掉），这样这两个站名一眼可读
11. 作为在夜里看这个界面的人，我希望次级文字（列头、说明行、元信息）对比度达标，
    这样弱光下也读得出「下一步做什么」
12. 作为读空列提示的人，我希望那句引导话术是可读的档位而不是装饰档，
    这样它不是摆在那里好看
13. 作为点开「新建任务」的人，我希望按 Escape 能关掉对话框，
    这样我知道怎么退出来
14. 作为用键盘的人，我希望打开对话框后焦点就在第一个输入框里、并且 Tab 不会跑到背后的页面上，
    这样我能一路填完不用摸鼠标
15. 作为用读屏的人，我希望对话框被当作对话框播报（而不是一段无名的排版），
    这样我知道自己进了一个模态
16. 作为在等拍板的人，我希望右栏档案盒不要和 Diff 页签重复渲染同一份 diff，
    这样「哪个是真的」不会变成我要思考的问题
17. 作为在等拍板的人，我希望「合入」这颗按钮在我看得见的地方（右栏）始终在，
    这样我不必先切页签才能拍板
18. 作为点错地址的人，我希望 404 页给一条回看板的路，这样我不必去翻浏览器历史
19. 作为删不掉项目的使用者，我希望「为什么不能删」在我要动手时出现，
    而不是每次打开这一页都先看到一条红字
20. 作为扫一眼设置页的人，我希望破坏性动作（删除）不要在视觉上比中性动作（编辑）更轻
21. 作为看指标的人，我希望第一段就说清成功率、重试率、逃逸事件、首过率分别是什么意思，
    而不是先看到字段名与内部编号
22. 作为看指标的人，我希望页面说清每个数是怎么算的、以及某个比值暂时没有意义时说清为什么
    （而不是只给一条没有解释的横线），这样我不必猜这个数是坏了还是本来就不适用
23. 作为想看某个任务指标的人，我希望从任务详情直接跳过去，
    而不是手打一个我根本记不住的 ULID
24. 作为在项目页想分析项目的人，我希望从任务卡上就能找到那个入口，
    而不是必须先在设置里找到项目
25. 作为读界面文案的人，我希望正文说的是「会发生什么」和「你该做什么」，
    内部决策编号收在悬停提示里，这样追溯性还在但不再占我的注意力
26. 作为这个项目的维护者，我希望有一条从「决策」到「实现位置」的路径，
    这样我改代码前能知道哪几条决定约束着它
27. 作为未来的贡献者，我希望设置类入口按用途分类（谁能进来 / 怎么跑），
    这样我加一块新设置时知道它该放哪
28. 作为找阶段配置的人，我希望它有自己的页面与位置，而不是埋在「模型与密钥」页的一大段里
29. 作为读设置页的人，我希望小节的标题不要和页面标题一样大，这样层级是分明的
30. 作为从手机看的人，我希望窄屏下的动作坞不遮住我要拍板的内容
31. 作为把仓库开源出去的维护者，我希望设计规格、决策日志与原型一起公开，
    这样界面文案里的引用不指向读者看不到的东西
32. 作为开源前的维护者，我希望公开前过一次敏感信息检查，这样不会连本机路径或凭据处理细节一起发出去
33. 作为改色板的人，我希望有一条机器门拦住「对比度改差了」，
    这样这次的「规则被丢、没人发现」不会再来一次
34. 作为加新设置页的人，我希望行为映射表里指不到文件的引用会变红，
    这样索引不会建完就悄悄烂掉
35. 作为想确认这批改动做完了的人，我希望每条发现都有对应的票与验收点，
    这样交付是可数的而不是「看着差不多了」

## Implementation Decisions

**票集分两叠，节奏不同，不混在一个列表里**

- **A 叠（不动规格，纯实现修正）**：一发现一票，互不阻塞，可以并行。
- **B 叠（要动规格）**：每项先出一张**决策票**——一票只回答「怎么定」；定了再出实现票。
  与规格文本冲突的地方，按修订决策追加记录（本项目决策日志只追加、编号只增不改）。
- **补拍证据那一票挂最前**：它决定「琥珀语义」与「空态」两条该落进哪一叠。

**对比度（这是本 effort 的根因修复）**

- 现行视觉规格里 `对比度` / `无障碍` 已无任何要求，而本项目早先的版本有
  「正文 ≥ 7:1、弱文本 ≥ 4.5:1」这一节——**改版时整节丢了**。先补回这一节。
- 阈值按 token 职责分档，不采用「正文 ≥ 7:1」：那会把整站拉亮并压平信号色的相对关系
  （失败红现在才 5.64:1，正文 7:1 会盖过它）。
  - `--text-2`：次文本，保持 ≥ 4.5:1
  - `--text-3`：**重新定位为「次级必读」**，提到 ≥ 4.5:1
  - `--text-4`：定性为**纯装饰**，门里豁免，并附「凡用到它的地方不得承载必读信息」的用法规约
- 把现在用错档的地方逐处归位：页面导入语、空列的引导句、待处理下拉里的原因文字、
  输入框占位符、任务卡的时长。
- 深浅两套的 token 值是**手工镜像**（契约模块 ↔ 全局样式表），值是**逐条机器比对**的，
  所以改值必须成对改、一次改全，否则护栏立刻变红。
- `--done` 与 `--text-3` 当前共用同一个字面值但不是同一个 token，改值时明确两者的进退关系。

**看板溢出**

- ≥ 1400px：`merge` 与 `done` 钉在右侧，中间六列横滚。
- < 1400px：不钉右，但**初始滚动位置落在 `merge`**，右缘留一条「还有列」的指示。
- 移动款（< 480px）不受影响，那里本来就是纵向站点带。
- 现行规格里有一句「看板列 264px，所以高密度信息仍是同屏的」是**错的**，随本项一并改写；
  264px 列宽本身不动。
- 注意脊线坐标与列宽是**手工对齐**的，改任何几何都要同步改坐标——这一处没有任何测试兜底，
  要在这项里补一条守护。

**脊线**

- 站名下的数字保留「累计到过这一站」的口径，但**加一个小字标明**（它与列头的「此刻在这一列」
  是两个量，同屏出现且长得一样）。规格对口径从未定义，这属于补定义。
- 并行分支的站名标签在原型里就带背景遮罩，实现漏掉了 `padding`，补回；补完再看站名与
  传送带的层叠是否还需要动——**站名被压穿是原型继承的几何，不是实现回归**，这轮先接受并记录。

**模态框（三个一起改）**

新建任务 / 拆任务 / 覆盖模型三个模态框是同一份复制粘贴的写法，一次改三处：
打开时焦点进第一个输入框、Escape 一律可关、焦点关在框内、对话框本身有可被播报的语义。

**设置的信息架构**

- 新增一个设置落地页，按用途分类（谁能进来 / 怎么跑），各项仍是独立路由。
- 顶栏因此从六项收到三项：对讲台 / 指标 / 设置。这是有意的——顶栏正是「第一屏必须懂」的那处。
- 「手机访问」那条「只在本机给入口」的规则跟着挪到落地页里那一项上，行为不变。
- 被拆出来的东西各有其位：技能归技能、阶段配置独立、provider 台账留在原处。
- 顺带修层级：「阶段配置」的小节标题当前与页面标题同为 24px，落到 12px 字距档。

**文案与可追溯性**

- 界面正文里的内部决策编号全部去掉，正文只留**动作与后果**。
- 可追溯性交给一张新增的「**行为 / 规则 → 实现位置**」表，放在**交互规格**里而不是视觉规格里
  （视觉规格只管视觉；行为塞进去会让它同时承担两件事）。
  这张表与视觉规格既有的那张「视图 → 组件」表同形，**不新建文件**。
- 配一条**悬空引用检查**：表里指不到实现位置的条目变红。索引最大的失败形态不是没建，
  是建完之后悄悄烂掉——这次的对比度规则就是这么没的。
- 注意：现行视觉规格里有一条明文**要求**把 `决策 103` 渲染进界面，与上面这条直接冲突，
  属于要改写的那一处。
- 车间隐喻保留（它是整个主题的投资），但每个词在**首次出现处**给一次平实说法；
  顶栏与「新建任务」等第一屏控件直接用平实词。

**输入与入口**

- 依赖任务 ID 给一个原生 `datalist`（不做完整选择器）。
- 指标页的任务级入口给一条从任务详情过来的路，不再要求手打 ULID。
- 项目分析入口在任务侧给出落点。

**开源落地**

- `design/`（两份规格 + 四个原型）与决策日志随仓库公开。
- 公开前过一次敏感信息检查（本机路径、凭据处理细节、内部环境）。

## Testing Decisions

**好测试的判据**：只测外部行为，不测实现细节。断言落在「用户看到/点到什么」与
「计算样式是什么」上，不落在 class 名、组件内部状态或文件结构上；文案精确匹配只用在
**契约性**字符串上（按钮名、状态词），不用于说明性段落。

**复用既有接缝，零条新接缝**

本项目已有一张权威的可测试性接缝表（决策 143，经 177 / 194 修订，共五条 + 主题契约）。
本 effort **不新增任何替换点、不改任何生产代码来让测试可写**，全部落在既有两条上：

- **主题契约模块**（决策 169 那条接缝）——token、几何常量、状态映射的唯一事实源。
  对比度的阈值与门、看板几何、脊线常量都从这里进出。它的既有形态就是
  「纯数据断言 + 读全局样式表逐条比对 + 扫描组件禁止裸十六进制颜色」，
  本 effort 新增的两条检查属于**同一家族**（静态扫描），不是新接缝。
- **前端 E2E harness**（真二进制 + 内嵌产物 + 真后端 + 真浏览器，决策 151 / 155 / 166）
  ——所有交互行为改动的验收都走这里。它已经承担着看板、详情、对讲台、台账页、市场页的
  端到端验收，本 effort 的每一条 A 叠改动都在它的覆盖形状之内。

**哪一层测什么**

- 纯函数层（vitest）：脊线的累计口径与其标注、几何坐标与列宽的对齐关系。
- 计算样式层（浏览器）：对比度门、token 值与全局样式表的镜像一致、像素纪律扫描。
- 端到端层（playwright + 真后端）：看板的钉右与初始滚动位置、模态框的键盘与语义、
  404 的出口、档案盒不再重复渲染 diff、设置落地页的导航与顶栏项数、指标页与项目页的入口。

**Prior art（照着这些写）**

- 主题契约的两条既有测试是本 effort 新检查的直接模板。
- `pixel-theme.spec.ts` 是「在真应用上断言计算样式与几何尺寸」的模板（含移动断点那一档）。
- 各条主流程 e2e（创建流程、待办恢复、评审分支、并发、对讲台）是「真后端 + 真浏览器 +
  按用户动作断言」的模板。
- 截图类用例（默认跳过、由环境变量开启）是本 effort 产出审计证据的模板——**证据不是门**，
  新加的审计截图同样默认跳过，不进质量闸门。

**要留意的脆弱点**：右栏档案盒的动作行被六个 e2e 文件里的多处定位依赖着。
「去掉重复」只去掉**重复的那份 diff**，**动作行保留**——这是被测合约的一部分，不是冗余。

## Out of Scope

- 264px 列宽本身、主题六的色彩体系与形状纪律（2px 描边 / 零圆角 / 12 的倍数字阶）。
- 车间隐喻体系本身——只加首次翻译，不推翻。
- 移动款的纵向站点带版面（它已由既有决策覆盖）。**用户故事 30（窄屏动作坞不遮住拍板内容）
  随之推后**：常驻底部动作坞是视觉规格 §5 里有意的设计形态，改它属于移动款版面变更；
  本轮只保证 08「不重复渲染 diff」不把它改坏。
- 「配对之后从手机看」这一档的验收截图（推后，只影响文案类发现）。
- 把设置再拆成更多页面、把依赖任务 ID 做成完整选择器——等开源后真有反馈再说。
- `docs/backlog-v2.md` 里的 v2 预留项（MCP、对话 agent、通知渠道、沙箱、密钥加密等）。
