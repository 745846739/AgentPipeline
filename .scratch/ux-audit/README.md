## 二、问题清单

### P1 · 两档灰字达不到 WCAG AA，而它们承载必读内容

实测对比度（`--bg` = 深色 #1b1d2c / 浅色 #e8e6dc）：

| token | 深色 on bg | 深色 on panel | 浅色 on bg | AA 门槛 |
|---|---|---|---|---|
| `--text-2` | 5.22 | 4.67 | 5.74 | 4.5 ✅ |
| `--text-3` | **3.28** | **2.93** | **3.32** | 4.5 ❌ |
| `--text-4` | **2.25** | **2.01** | **2.19** | 4.5 ❌（连 3:1 都不到） |

`app.css:26-27` 的设计意图是「`--text-3` 弱文本 / `--text-4` 占位、装饰刻度，**不承载必读信息**」，
但实际用到这两档的地方里有一大批是用户在读的内容：

- `.hintline`（app.css:428，`--text-3`）——每个设置页的整段说明；技能市场那一页整整 6 行全在这一档
- `.dd-msg`（TopBar.svelte:426，`--text-3`）——待处理下拉里「为什么卡住」的原因文字
- `.crumb`（app.css:405）——返回看板的入口
- `.reg-sub` / `.reg-l2`（app.css:486/489）——项目与 provider 的语言、闸门命令、base_url
- `.col-empty`（BoardColumn.svelte:169，`--text-4`）——空列的「下一步做什么」引导
- `.input::placeholder`（app.css:304，`--text-4`）
- `.dur`（TaskCard.svelte:258）、`.reg-head .n`、`.slot .cb`、状态行全部标签

仓库里有 `css-parity.test.ts` 锁 token **取值**，但没有任何东西锁**可读性**——这两档偏暗
没有任何测试会报警。修法有两条：把 `--text-3` 提到 ≥4.5:1（深色约需 #8A88A0 一档），
或把承载内容的地方改回 `--text-2` 并给 `--text-3/4` 加一条「只许装饰」的用法规约 + 检查。

### P1 · 看板上两组数字长得一样、意思不同

同一时刻实测：**脊线**在 init / architect / develop 上显示 3、review 上显示 2；**列头**显示
0 / 0 / 0 / 1 / 0 / 0（另 2 个在屏幕外的 merge 列）。

- 脊线：`buildSpineStations`（`lib/pipeline.ts:498-518`）数的是 `dots[i] !== 'idle'` —— **累计**
  到过这一站的任务数（漏斗）
- 列头：`BoardColumn.svelte:85` 渲染 `tasks.length` —— **此刻**停在这一列的任务数

两处都是「站名 + 一个小方框里的数字」，没有标签、没有量纲说明。用户无法从界面上分辨哪个是
「流量」哪个是「存量」，而它们在同一屏上相差一倍。至少要给脊线那个加一个词（如「累计」），
或换成漏斗形状的视觉区分。

### P1 · 看板一次看不全，且横向滚动没有可见提示

`.hinner` 固定 2162px（`Board.svelte:93`），`.panes` 2130px。1440px 视口下**只有 5 列可见**，
第 6 列被从词中间切断（截图里「评审通过的任…」），而 **merge 与 done 这两个最决定性的列完全在屏外**。
macOS 的 overlay 滚动条不滚动不出现，所以唯一的提示就是那个被切断的列。

固定列宽来自原型（`theme-6-pixel.md` 冻结值），改起来是规格变更；但至少可以：把 merge / done
钉在右侧、给 `.hscroll` 加一条常驻的滚动条样式、或在右缘加一个「还有 3 列 ▸」的指示。

### P2 · 脊线的站名被传送带图形压穿

放大截图（`/tmp` 里那张 crop）看得很清楚：`architect-design`、`test-design` 的文字被两行
蓝色链节横穿；`dev-design` 与 `test-design` 两个标签只隔约 30px，挤在一起。脊线整体占掉
列区上方约 110px 的竖向空间，是全页视觉噪声最大的元素。

### P2 · pending 详情页把同一份 diff 和同一对动作渲染了两遍

`TaskDetail.svelte`：主区 Diff 页签渲染一份（:311-327），右栏档案盒再渲染一份（:337-358）。
截图 `detail-tab-diff.png` 上「+3 −1 · 2 个文件 / 重新加载 diff / 两段 hunk / 返回修改 / 合入」
在同一屏出现两次。而且「合入」是**全站最重要的一颗按钮**，出现两次会让「点哪个」变成问题。

档案盒的存在理由是「不切页签也能拍板」；那当用户已经在 Diff 页签里时，右栏应该收成一个
不重复内容的状态摘要。

### P2 · 新建任务对话框：Escape 关不掉、焦点没有进对话框、没有 dialog 语义

`NewTaskDialog.svelte:60-68` 的 Escape 处理挂在 overlay 的 `onkeydown` 上，但
**没有 autofocus、也没有焦点陷阱**，所以点完「新建任务」之后焦点还在按钮上（overlay 之外）。

实测（`ux-audit.spec.ts` 的键盘可达性用例）：

```
dialog before=1  afterEsc=1  afterEscFocused=0  focus=BUTTON.btn btn-new
```

即：点开对话框 → 按 Escape → **仍然开着**；先把焦点放进输入框 → 按 Escape → 才关得掉。
同一段代码还用了 `role="presentation"`，没有 `role="dialog"` / `aria-modal`，
键盘用户可以一路 Tab 到弹窗背后的页面。

鼠标用户不受影响（点遮罩和「取消」都能关）。修法：`autofocus` 到标题输入框 + `role="dialog"`
+ `aria-modal="true"` + 焦点陷阱，或直接把 Escape 提到 `window` 上。

### P2 · 指标页用实现术语当首屏文案，任务级指标要用户手抄 ULID

`Metrics.svelte:80-87` 的开场是一整段：

> 统计口径见 core metrics（决策 130 / 137）：成功率 = done ÷（done+failed+cancelled）；
> 重试率 = attempt > 1 的 run 占比；逃逸事件 = trigger = kickback 的流转数；
> 首过率 = validate_output 首次 attempt 即通过的比例。

这是数据库/状态机层词汇 + 决策日志编号，用最低对比度的那一档灰排版，摆在页面最上方；
同一段里还有原始字段名（`total_tokens` / `calls`），页脚还有一句「已从轨道图排除站点阶段
（决策 107）：sync-check」。

**（同日更正，见下「补充更正」第 4 条）** 原稿在这里写了「比例类的图没有数字、读者只能靠条长猜」
——**这条是错的**。重看截图：各阶段耗时与各阶段重试率每一列都带数值（`29ms` / `44ms` / `0.0%` …），
首过率也显示 `100.0%`。屏幕上唯一的 `—` 是**成功率**，而它显示横线是因为当时 3 个任务里
一个都没完成、分母为 0。所以真问题不是「缺数字」，是**「一条横线不说为什么」**：
读者分不清是坏了、还是本来就没有意义。

任务级指标（`Metrics.svelte:150-166`）要用户**手打一个 ULID**——没有选择器、没有从任务详情
跳过来的链接、没有最近任务列表。项目页的「分析」也是同理：它是项目级的动作，但任务卡上
没有任何地方指向它。

### P2 · `决策 NN` 出现在面向用户的文案里

设置·项目（决策 29 / 61 / 101）、模型与密钥（决策 111 / 112 / §12.14）、
