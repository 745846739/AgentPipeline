# 设置的诚实性：删的删、接的接、钉的钉（settings-honesty）

**状态（2026-09-23）：票 01–03 已实现，`make check` 全绿。** 本目录来自一次架构评审（`improve-codebase-architecture`）
的候选 9「设置没有注册表：一个字段手接六处」，经三轮拷问（Q1–Q13）定下范围与判据。评审报告是
临时的、不入库；设计结论以本文件与决策 **256–258** 为准。

同一轮评审的候选 1 / 2 / 3 / 4 / 5 / 6 / 7 / 8 / 10 已由决策 245–255 落地。**本目录只处理候选 9。**
**候选 9 是本轮评审中唯一没有人碰过的一条**——其余九条在报告写完之后、拷问开始之前，已经由
并行的几批工作落地了（这也是本轮最值得记的一件事：评审报告写下的那一刻就已经在过期）。

## 一、候选 9 在报告里的写法不准，核完事实后它裂成三件不同的事

报告原话是「加一个设置要碰 core、storage、routes、frontend 六处」。**核对下来这是假的**：

- `Settings`（`config.rs:19`）**从不序列化给前端**——全仓 grep `Json<Settings>` / `to_value(&settings`
  零命中，前端也**没有** `Settings` 这个类型；
- 把 `watch_debounce_sec` / `max_concurrent_tasks` / `tick_interval_sec` / `node_idle_timeout_sec` /
  `egress_allow_all` 逐个在前端搜，**全零命中**；
- **应用从不写 `config.toml`**（所有 `fs::write` 都落在 task 目录 / worktree / 测试 fixture）。

所以「六处」实际是**同一个文件里的四处**（`Settings` 字段 + `default` + `PipelineOverrides` 字段 +
`set!` 宏清单），而真正宽的 seam 在**另一侧**——`stage_configs` 那条 UI 可改的路（`types.ts` 的
102 个类型、`PSEUDO_STAGE_KEYS`、`STAGE_KEYS` 等五处手抄镜像）。**那一侧是决策 253 的活**，
本轮不重复做。

于是候选 9 裂成三件，判据是**「这份不一致今天伤到谁」**：

| | 是什么 | 今天的痛 |
|---|---|---|
| **(C) 惰性设置** | `conflict_overlap_threshold` 有字段、有默认、有覆盖层，**零生产读者**，而三处文档描述它的作用 | **现在的**——用户照文档调它，连报错都没有 |
| **(B) 漏掉的读路径** | `Store::market_repos_override()` **零调用方**，界面保存的仓名单重启就丢 | **现在的**——用户已经看得见的数据丢失 |
| **(A) 静默的平行清单** | `Settings` 32 / `PipelineOverrides` 32 / `set!` 宏 **31**，四份清单，只有宏那份漏写是**静默**的 | **潜在的**——今天没漂，但没有测试拦 |

**(A) 为什么值得做而不是「等它漂了再说」**：四份里只有宏清单静默——字段加进两个 struct 却忘进
宏清单，该键在 `config.toml` 里写了**读回来还是默认值**，而没有任何测试会红
（`defaults_match_design_table` 只断言 23 项、`toml_override_only_touches_named_fields` 只断言 3 个
字段；`PipelineOverrides` 全仓只有 `config.rs` 里 4 处引用）。另外三份漏写是**编译错误**。
这正是本仓最怕的形状：配了、看不出没生效。

## 二、三件事的处置各不相同，判据是「改的是字段还是文档」

- **(C) 删字段 + 订正三处文档**：那个字段唯一有意义的取值是 `> 0`，至今没人需要；留着它等于留一个
  「看起来能调、调了没用」的旋钮，**比没有更坏**（用户会以为调它能改冲突判定）。默认 `0` 恰是现状，
  故**行为零变化**。删一个**决策正文里点过名**的参数，要在决策日志行内标注修订（决策 53 那行）。
- **(B) 接上读路径**：这不是取舍而是**实现漏掉的一步**——存储层的 doc（`market_repos.rs:12-19`）
  明写「`Some(vec![])` = 显式清空；`None` = 没保存过，读配置」，并注明「这条区分是迁移 0009 的注释里
  已经写明的，**不在新表上丢掉**」；`server_bind_override` **是同构且被读的**（`serve.rs:429`）。
- **(A) 加一条定值探针**：不立设置注册表、不做代码生成、**不设豁免表**——豁免表本身就是一份会漂的
  清单，而本条的整个目的就是消灭会漂的清单。

## 三、本轮造的两个词（已落 `docs/glossary.md` 配置相关一节）

- **惰性设置**：有字段有默认有覆盖层、却没有任何生产读者的设置。**与「预留项」不同**——预留项明说
  自己是预留，惰性设置是文档**当成已实现对它承诺**。清理只有两条合法的路（删 + 订正，或补实现）；
  **不含**「留着字段只把文档改成预留」。**同类但要分清**：有读者、但文档把它描述成另一件事的
  （`tool_timeout_sec`），**只订正文档，不删字段**。
- **清单同一性**：同一字段集写在多份平行清单里时，用一条会红的测试钉住相等。跨语言的用共享表
  （决策 246 / 250 / 253），单语言内的用**定值探针**（决策 258）。

## 五、明确不做

- **不立设置注册表**（把 32×4 重写成声明式表示）——这不是同一件事，且当前**没有一次真实漂移**
  需要它。报告把它当成「六处手接」的证据，核完不成立。
- **不给 32 个全局设置做界面**（(B) 的另一半意思）——那顶撞决策 56 的刻意边界；`env_mode` 的注释
  明写「改它等于改全机所有阶段的行为，那是一次深思熟虑的编辑，不是一次点击」。若要重开，走 ADR。
- **不动 `stage_configs` 那一侧的跨语言镜像**——决策 253 票 02 / 03 已覆盖。
- **不删 `tool_timeout_sec`**——它是活的（`effective_run_command_timeout` 的二选一分支），只订正文档。

## 六、对本次评审报告原话的订正（记账，供下一轮评审引用）

1. **「加一个设置要碰六处」不成立**——四处，同一个文件里，且三处是编译期可查的。
2. **「报告里的候选 5 是一条安全缺陷」在拷问开始时已经修好**——决策 246 把回环判定收敛成
   `host_policy::is_loopback`，`egress.rs` 的 `starts_with("127.")` 已退场。报告写下时它是对的，
   核对时已经不是。
3. **「`EnvMode` 没有 `impl Deserialize`，故 `env_mode` 只能走 `Option<String>`」是错的**——
   `types.rs:1403` 有 `#[derive(Deserialize)]`。真实理由是**报错质量**（`"Auto"` 走枚举会得到一句
   难读的 serde 错误），由 `the_global_tier_accepts_auto_and_deny_but_not_ask`（`config.rs:1266`）
   钉住文案。故 `env_mode` 的豁免是**有理由的**，不是漂移。
4. **「`overview.md` §3 缺 3 行」应为 2 行**——`env_mode` 有自己的词条（`glossary.md`「权限档位」），
   口径在别处；补进 §3 会制造第二份。真正缺的是 `egress_allow_hosts` / `egress_allow_all`。
5. **「候选 9 是唯一剩下的一条」是本轮最重要的发现，也是一条流程教训**——报告写完到拷问开始之间，
   另外九条候选已被 245–255 十一批提交落地。**下一轮评审应在动笔写报告前先核对 HEAD**。
