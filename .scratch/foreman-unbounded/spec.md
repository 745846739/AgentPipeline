## 一、现状的账（2026-09-26 实测）

那天对讲台一轮跑了 30 分钟、23 次模型调用**全部成功**，然后被砍掉，只落一行「没跑起来」。逐条查下来：

| 事实 | 读数 | 出处 |
|---|---|---|
| 一轮的成本 = 生成 token ÷ provider 吞吐 | 24 次调用生成 85,135 token；三个链（人的两轮 + 值守轮）实测都稳定在 ~45 token/s，与上下文大小无关 → 需要 ~31 分钟 | 请求 832–871 |
| 上下文只增不减 | 6.1k → 121,089 token（provider 窗口 128k 的 **94.6%**）；单条工具结果截 12k 字符，但整轮累加 | `foreman.rs:742`、`foreman.rs:1819` |
| 墙钟那条路不要成果 | 23 次成功调用、146 万 prompt token、8.5 万生成 token 整段丢弃，只落一条失败账 | `foreman.rs:1519-1525` |
| 那套抢救路径够不着 | 「部分结论落库 +【未收口】」只挂在**轮数上限**（缺省 300）那一支，而墙钟在第 24 次调用就到了 | `foreman.rs:1823-1871` |
| 同会话两轮并行 | 值守轮 11:35:10 起跑（同任务 30 分钟冷却到期那一刻放行），与人的那一轮并行 7.8 分钟 | `FOREMAN_TURNS` 是**计数**，`foreman.rs:103-147` |
| 值守轮在库里没有身份 | 与人的回话同为 `assistant` 行，靠正文前缀区分；wire 上的 `kind`/`proactive` 是路由层**现推**的 | `routes/foreman.rs:1147-1178` |
| 值守轮没有任何开关 | 循环无条件 spawn；`watch_*` 五个数只住 config.toml，界面零入口 | `serve.rs:555`、`config.rs:132-136` |
| 已有机器没接线 | 流水线的窗口预算（软硬限 / L3 压缩 / `OUTPUT_RESERVE`）对讲台**一次都没读**；L2 卸载的会话维度目录早已通，只有台账三件被跳过；`idle_timeout_sec` 画在设置页却不被读取 | `model_request.rs:219-314`、`tools.rs:866-874`、`scheduler/mod.rs:198-203` |
| 循环检测全仓没有 | 唯一的护栏 `degeneration.rs` 只扫**流式 content 的尾部重复**（周期 3–48 字符、≥5 次、≥60 字符）；同参重复 / 无进展检测一处都没有 | `degeneration.rs:17-83` |
| 人这一轮没有中止入口 | `POST /foreman/messages` 把轮 spawn 到独立 task 后 await；路由表里没有 cancel/stop | `routes/foreman.rs:962` |

一句话：**不是 prompt 也不是权限，是「一轮的界」与「一轮的真实成本」不同量级，而且所有已造好的机器都没接到对讲台这条路上。**

## 二、裁决（拷问 Q1–Q16）

1. **「向 zcode 看齐」的范围** = 去墙钟 + 上下文只受模型窗口限制 + 循环检测，外加为兑现前两条所必需的配套（卸载回读、轮内压缩、撞墙恢复）；可中断与只读子代理**也做，但排在后面**。
2. **值守轮数据分家**：它有自己的时间线与入口，人的对话里不再落播报；**仍读得到人的话**；人在跑时值守轮**排队**，不并行。
3. **开关**：全局一个，语义是「关掉**跑**」（跑都不跑自然不吵）；沿用任务级托管；**不做**班次级；缺省开；设置页要显眼。
4. **值守轮权限面不动**：四件工具（读会话原文 / 跑命令 / 提问 / 外发）照旧摘掉。这次放开的是它**能查多久**，不是**能查什么**。
5. **时间界**：值班长一轮**不再有整轮墙钟**；唯一的时间界是**逐调用按字节的空闲判死**（复用 foreman 行的 `idle_timeout_sec`，缺省取与节点同数 300s），判死只杀**这一次调用**并重试一次。前端不再把本地 5 分钟放弃渲染成失败轮。
6. **窗口界**：卸载（人的那一轮放开台账三件；值守轮保持诊断包**摘要**形态）+ 轮内压缩（复用流水线那套容量算术）+ 撞墙恢复（provider 报超长 → 压缩后重试一次这一次调用）。
7. **停止条件**：token 预算**分档**——人的那一轮无硬界（终点由人决定）；值守轮 120k 生成 token 硬界（落 foreman 行，可见可改）。**所有非正常结束**（触顶 / 空闲判死 / 取消 / panic）都走「部分结论落库 + 标注」。成本软告警只落账不拦。
8. **循环检测**：判据两条——同一工具 + 同一**完整参数**连续重复 N 次；连续 N 次调用无新信息。动作两级——先注入一条带标记的 user 轮提醒（一次），再犯强制收口。本批只做值班长这一轮。
9. **三个停止标记同族可分**：`【未收口】`（触顶）/`【未收口·在打转】`（循环）/`【已停】`（人按停）。
10. **停钮只管人这一轮**；值守轮归开关。被停在半路那一轮提的悬空提议**保留**（修订 233③）。
11. **值守时间线是只读的一本账** + 每条一个「转去对话」动作；人的那一轮读到一份值守**摘要**（不是整本流水账）——否则会出现「人指着播报说『处理一下』，模型不知道你在说哪件事」。
12. **存量不回填**：历史的播报留在原会话里，只有新产生的进值守时间线。回填要重写已归档会话的归属，代价大而收益只是「历史也分家」；旧行的 `proactive` 已能让界面标对。
13. **流水线侧的「超长仍盲目重试」另立一张小票**（票 10），不塞进对讲台那张票——否则对讲台的验收面会被 executor 的测试面污染。

## 四、Out of Scope（记档，等真实诉求再立票）

- **流水线节点的循环检测**（08 的同款，另一个工具循环 `model_invoke.rs:636-700`）：节点只有成功/失败两态，「先提醒再收口」在那里没有落点。另立票。
- **值班长的权限面调整**（新增写动作 / 放开四件工具）：本轮一字不改，理由见裁决 4。
- **班次级值守开关**：没人会调的旋钮（决策 256 的尺子）。
- **值守时间线做成可对话**：对着播报说话的需求用「转去对话」接住，不动人的说话面只有一处这条形态。
- **对讲台的多会话并行**（几个班次同时回话）：与本次的两条时间线是两件事。
