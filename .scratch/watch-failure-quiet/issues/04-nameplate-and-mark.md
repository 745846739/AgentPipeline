# 04: 名牌与标记——`【值守没跑起来】` + `proactive` 派生 + 播报标记只加一次

**What to build:** 值守轮的失败账在时间线上不再冒充「发送失败」；播报标记只加一次，
且静默判据不受模型自己写的前缀干扰。

**为什么**（2026-09-25 实测，两处）：

1. 那 37 行失败账的名牌是「发送失败」——值班经理一个字节都没发出去，读起来却像是他的话发不出去。
   线上形态里 `kind = "failed"` 只有一档，分不出「人的轮」与「值守的轮」。
2. 重启后那条播报库里存成 `【值守播报】【值守播报】**无需你处置。**…`——模型从历史里学会了
   这个前缀自己写了一遍；且因为回话不再以 `【无需处理】` 开头，本该静默的一轮被当成播报发了出去。

**形状**：

- 新前缀常量 `FOREMAN_WATCH_FAILED_TURN_MARK = "【值守没跑起来】"`；值守轮的失败账用它
  （人的轮仍是 `【没跑起来】`）。
- `message_wire`：`kind` 两支都算 `failed`；`proactive` 派生扩一支
  （`system` + 值守失败前缀 → `true`）。**字段集不动**——这正是决策 252③ 说的
  「分开写，将来要显示时不必再改线」。
- 前端名牌抽成纯函数 `turnName(turn)`：`failed && proactive` → 「值守 · 没跑起来」；
  `failed && !proactive` → 「发送失败」；其余照旧。
- `respond()` 加标记之前先剥掉模型自己写的那一份（`trim_start` 后剥），**静默判据在剥完之后判**。

**实施收尾（2026-09-25）:**

- **剥一遍 + 判一遍，两处同源**：`respond` 里剥完的正文既进静默判据、也进落库那一行、也作为
  `ForemanTurn.reply` 返回；`watch()` 那边决定「唤醒账记静默还是播报」时再判一次——两处看的是
  同一个 `turn.reply`（剥过的），不会出现「后端认为静默、唤醒账记成播报」。
- **剥的只是我们自己写的前缀**：模型若以别的字样开头（含「**无需你处置。**」这种转述），照常
  播报——§2.4「判据偏向播报」一个字不动。这一条写进了注释，免得后来者顺手把哨兵判宽。
- **`proactive` 的派生仍只在后端写的前缀上成立**：助理轮看 `【值守播报】`、`system` 行看
  `【值守没跑起来】`；用户行永不算（人可能恰好引用那个标记）。**没有新增字段、没有新枚举值**，
  决策 252③ 的字段集原样。
- **名牌抽成 `lib/talkTurns.ts::turnName`**（决策 199 / 252 的姿势：判断归模块、模板只渲染）：
  `Talk.svelte` 里那段嵌套三元式退场，五档文案由 `talkTurns.test.ts` 逐档钉住
  （`delegation-scan.test.ts` 那两条「前端不许解析正文哨兵」的断言照样绿）。
- **`§12.3` 加一行**（「名牌那五个词是一张规格」），失败轮那一行的括号补上
  `【值守没跑起来】`；`behavior-map.test.ts` 的悬空引用检查通过（符号名进备注列、
  实现位置列只留真实路径——这条格式约束踩过一次，记在这儿）。
- **明确不做**：不在简报里叮嘱模型「别自己写前缀」（后端剥一遍就够；prompt 效果回归属 v2 离线 eval）。
