# 03: 同批同类失败**只落一行** + 恢复时一条汇总

**What to build:** 一批连续失败里，同一类别只落第一行；恢复时落一条汇总说清「这批有多少次、
从哪个类别到哪个类别、最后一次什么时候」。

**为什么**：退避把频率压住了，但「失败了几次」这件事仍要在台账上读得出来。逐条落行是刷屏，
一条不落是丢账——一行首行 + 一行收口，两头都在。

**形状**：

- 首行（**每批每类别一次**）：照旧 `【没跑起来】…（kind）：<原因>`，末尾补一句
  `（此后同类失败不再逐条落账）`——读的人立刻知道为什么只看到一行。
- 换类别 → 新的一行（「余额不足」与「连不上」是两个修法，不许合并成一行）。
- 恢复（退避之后**第一次成功**的那一轮）→ 一条 `system` 汇总：
  `【值守】已恢复：上一批连续失败 N 次（kind → kind），最后一次 <时刻>。`
- 判据只在内存（与票 02 同一张状态表）。进程被杀则汇总不出现——首行仍在，那是诚实的不完整。

**Blocked by:** 02

**Status:** done

- [x] `record_failed_turn` 收一个「这一轮是不是值守轮的」形状参数（票 04 用它写前缀）
- [x] 首行只在「本批第一次 / 换了类别」时落；其余只更新内存计数
- [x] 成功那一轮落汇总行（含次数、类别链、最后一次时刻），然后清空这批
- [x] 用例：连失三次 → 台账里**只有一行**失败账（首行带「不再逐条落账」那句）
- [x] 用例：两次失败换个类别 → **两行**（类别各自一行）
- [x] 用例：恢复之后 → 多一条汇总行，且次数与类别链都对

**实施收尾（2026-09-25）:**

- **`record_failed_turn` 收了两个参数**：`from_watch`（写哪个前缀——票 04）与 `note_row`
  （这一次要不要落行）。**「作废悬空提议」不受 `note_row` 影响**——那是这一轮失败的后果
  （决策 233③），与要不要再写一行无关：一个失败轮照样可能提过提议。
- **类别链去重保序**（`burst_kinds`）：一次断供里「余额不足 → 连不上」两个类别会各落一行，
  汇总那一行把链完整说出来（`llm_quota → llm_network`），读的人一眼看出这次断供换过性质。
- **恢复行落在播报行之后**（`respond` 先落播报、`watch` 再落汇总）：时间线上读起来是
  「值守播报：…」→「【值守】已恢复：上一批连续失败 2 次（llm_network），最后一次 …」。
  静默那一轮只有汇总行——那正是「provider 通了」最该被记下的一刻。
- **类别链的来源是 `turn_failure_reason`**（既有那一个函数，`Error::LlmClassified` 的 kind；
  未归类的 `Error::Llm` 仍是 `llm_network`）——不新造第二处分类。
- 用例覆盖面比票面多一格：**「连失三次」那条同时钉住「翻倍窗口差一秒不许试」**（第二次失败后
  60s 才允许），故 `a_failing_watch_backs_off_and_notes_the_burst_once` 一条里有 8 个断言。
