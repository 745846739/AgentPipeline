# 02: 值守轮失败的**分档退避**

**What to build:** 失败之后，下一次尝试要等——等多久按失败类别分两档，成功一次即归零。

**为什么**：值守轮每 10 秒一趟、失败不消费待办、失败又不计入每小时唤醒上限（那片账只记成功与触顶）
——provider 一天不通，对讲台就一天每 10 秒多一行。见 `spec.md` §1 的 37 行实测。

**形状**：

- 状态住在 `ForemanRunner`（`Mutex<WatchFailureState>`）：连续失败次数 + 下一次允许尝试的时刻。
  **只在内存**：退避是「这一次进程的运行节奏」，不是跨重启的账。
- 两档：**瞬时类** 30s → 60s → 120s → 240s → 480s → 600s 封顶；
  **等也不会好类**（`llm_auth` / `llm_model_not_found` / `llm_quota` / `llm_context_window` / `config`）
  300s → 600s → 1200s → 1800s 封顶。
- 退避期内 `watch()` 立刻 `Ok(None)`：**不问、不看不说话**（零模型调用、零落账）。
- 退避**只挡值守轮**：`say()` 一个字不动（人随时可以自己再试一次）。
- 取值不扩配置项（照决策 224 的姿态）：常量住在 `foreman.rs`，与 `FOREMAN_MAX_ROUNDS` 同址。

**实施收尾（2026-09-25）:**

- **判断放在 `watch()` 的最前一行**（在扫待办表之前）：provider 不通时「有没有待办」这个问题的
  答案不影响结论，先问这一趟该不该开口最省——退避期内连一次数据库读都不做。
- **状态与 `compaction` 同一把锁的姿态**（`std::sync::Mutex`，临界区里没有 await）：
  改状态的地方只有两处（失败时记一次、成功时取走一批），都在 `await` 之前算完。
- **翻倍用移位而不是循环乘**：`base << min(consecutive-1, 6)`——第 7 次之后恒为封顶值，
  不会溢出也不会绕回。
- **日志文案改了**：「下一趟重试」→「按退避窗口重试」（`crates/app/src/runtime.rs` 的
  `Err(e)` 那一支），否则读日志的人会以为它还在每 10 秒试。
- **牙齿检查**：把两个基数临时改成 0 → 两条退避用例**当场变红**（瞬时类那条在「退避期内零模型
  调用」上红、账单类那条在「30s 仍不许试」上红），改回即绿。
- **明确不做**：退避**不**挡 `say()`（人的轮）；人轮成功**不**去重置值守退避（收益只是恢复早几分钟，
  代价是两条路互相写状态）。
