# 节点内消息级恢复（消息级重试）

**一句话**：服务在节点执行中途被强杀后重新起来，agent 节点从**最后一条已记录的消息**接着跑，
而不是像今天这样拿一份空转录从头重跑；已完成的工具副作用不再重做。

本文是 grilling 收敛出的共识（2026-10-07），票在 `issues/`。

## 为什么

今天 LLM 节点的会话是**循环退出之后**一次性写成一整块 `messages_json` 的（成功路径与
`record_failed_attempt` 失败路径各一处），`kanban_node_runs.step` 明确写着「LLM 节点没有步边界」。
所以被 kill -9 那一刻，这个节点烧掉的**全部**对话一个字都不在库里。

更关键的是启动恢复**不写任何续接原因**，于是 `take_continuation` 返回 `None`、承接转录为空——
中断的节点从零重跑，它做过的全部工具副作用会**重做一遍**。而超时梯子（决策 320）早就有这个能力：
把上一轮转录当承接内容重放、模型接着走，不重复执行工具。本功能本质上是**让崩溃路径拿到超时梯子已有的能力**。

## 定下来的设计

**恢复语义：重放式。** 把日志读成消息数组当作承接内容交给新一轮 attempt，模型自己接着走。
不回到循环里机械续跑剩余工具调用。

**写入粒度：每条消息一行。** 顺序保证「收到 assistant 响应 → 落行并提交 → 才开始执行这一批工具」，
所以每次崩溃最多丢一条还没落库的模型响应。

**合成回执。** 工具是顺序执行的，所以未配齐的调用里只有第一个真歧义：第一个写「进程重启，
这次调用被中断，**可能已部分生效**」，其余写「进程重启，这次调用没有执行」。回执**落库并打标记**——
这个仓对假读数的姿态是既定的（决策 226③ 的「照实记」、talk-replay 03 宁可标 interrupted 也不假装还活着），
回执要能被人一眼认出是合成件。

**日志形状：每个 run 自包含。** 一行一条消息，attempt 开始时把承接的转录前缀批量落行，与决策 99 的
「一条 run 至多一条会话行」同形。日志记**原始转录**（append-only，压缩完全不碰它，因此不需要任何压缩事件）；
观测面那一份继续记压缩后的、继续截断。**查找键保持现有语义** `(task_id, stage, node, agent_type='main')`
取 id 最大的 run——因为 `goto` 是在同一条游标行上改 `(stage, node)`，按游标找会把 develop 的对话喂给 architect。

**恢复源统一。** 新日志成为**所有**续接场景的转录来源（超时梯子、人按 resume、崩溃恢复），
会话表退回纯观测归档。新增 `ResumeCause::ProcessRestart` 进续接判定表。这一步顺手修掉梯子今天读
**可能被截断**的转录这个隐患：`truncate_messages_json` 从最旧一端整条丢消息，切口落在轮中间时留下的
孤儿 tool 消息会被 `sanitize_tool_sequence` 静默吃掉工具输出（`context.rs:491` 记的就是同类事故）。

**run 归属。** 新开一条 run，`continued_from_run_id` 指向被杀的那条。不动 attempt 计数，也不动超时梯子
（`cancel_origin='restart'` 已经在 `trailing_timeout_streak` 里「既不计数也不清零」）。

**止损。** 给重启续接一条**独立的连击计数**，到 N 次降成简报档或转 pending。不给
`trailing_timeout_streak` 加计数——票 02① 那条「重启不冒充超时」的语义要保住。

**生命周期。** 日志与 `conversation_retention_days` 同一把尺子（决策 182④ / 204⑦ 已经吃过两把尺的亏）。
**删除时点不能是「run 判终态」**——启动恢复第一件事就是把被 kill 的 run 标终态，那正是最需要日志的时刻。

## 明确出范围

- 只覆盖 **agent 节点主循环**。子代理、伪阶段、项目分析 run 都不进（子代理是决策里的非目标）。
- SSE 过程中的消息不保留：`AgentResponse` 是拼完整条才返回的，日志里天然只有整条消息，所以不需要
  可续 SSE、不需要落增量 delta。
- 恢复时 system / user prompt **按当前配置重新装配**（与梯子今天的行为一致）。逐字复用要独立一票，
  理由是「改配置不该打断在跑的节点」——不该被这件恢复功能顺手捎带。
- 被 kill 的 run 的 **token 记账丢失**不修：重放前缀那部分会如实记在新 run 上，被杀那一轮烧掉的查不回来。
