# 02: 续接源换成日志（含半轮回执）

**What to build:** 所有续接场景（超时梯子、人按 resume）的转录来源从会话表换成新日志，于是续接用的是
**未截断**的转录；新增一个「进程重启」续接原因并进判定表（答案为「续接」）。日志断在半轮时
（assistant 已落、工具结果没配齐）补齐回执后交给新一轮：第一个未配齐的调用收到的回执说
「可能已部分生效」，其余说「没有执行」。**两条按「承接的转录非空」就往末尾追加 user turn 的逻辑，
判据必须从「非空」换成按续接原因判定**——统一之后任何一次恢复都会让承接转录非空，不改的话
一次普通崩溃会在 develop 节点上凭空插一条 review 反馈 turn。

**Blocked by:** 01（日志表与写入路径）

**Status:** ready-for-agent

- [ ] 续接取数改读日志，**查找键保持** `(任务, 阶段, 节点, agent_type='main')` 取 id 最大的那条 run 的行。
      按游标找是错的：`goto` 在同一条游标行上改 (阶段, 节点)，会拿到上一个节点的行——
      有一条测试钉住「goto 换节点不串味」
- [ ] 未配齐的调用补合成回执，两种文案分得开；回执**落库**并打上「合成」标记，下一轮重放时还在
- [ ] 新增「进程重启」续接原因进判定表（答案为续接）。原因是穷尽 match，漏写编译不过
- [ ] 两条 turn 注入的判据按续接原因，不按「承接转录非空」：补充输入（决策 279）与 review 打回反馈
      （决策 387）各有一条测试，断言「一次普通恢复不会注入它们」
- [ ] 既有超时续接用例照旧绿（决策 320 的梯子：前两次续接、第三次空白带简报、第四次挂起）

      （带工具调用的 assistant 消息后面每个调用都有结果），且已完成的调用**不会被重放**
