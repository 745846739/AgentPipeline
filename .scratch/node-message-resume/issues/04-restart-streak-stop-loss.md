# 04: 重启连击止损

**What to build:** 同一个节点因为重启反复续接、始终没有进展时，不再无限重放同一份转录——
到 N 次降档（改空白重跑 + 现场简报）或直接转 pending 交回人工。计数**独立**，
不污染超时梯子的既有口径。

为什么需要：如果这个节点每次跑到同一处就把服务搞崩（OOM、不返回的调用），重启恢复会无限重放同一份
转录，既不会升档、也不会交回人工。超时梯子当初就是为这一类「续接救不回来」造的（决策 320）。

**Blocked by:** 03（崩溃路径接通之后才谈得上连击）

**Status:** ready-for-agent

- [ ] 重启续接的连击计数独立成一条，**不并入** `trailing_timeout_streak` 的「跳过不清零」语义——
      票 02① 那条「重启不冒充超时」（一次重启既不是节点恢复的证据，也不是人介入）要保持原样
- [ ] 到上限后的动作二选一并写进决策、说明为什么选它：降成空白档（带现场简报，与超时梯子第 3 档同形）
      或直接转 pending
- [ ] 测试：连续 N 次重启续接后行为按设计变化；一次人工介入之后计数重新起算
- [ ] 测试：重启本身**不**让超时梯子升档，也不让它清零（既有口径不变）
- [ ] 决策日志追加一条，交代它与决策 320 梯子的分工：各管一类「续不回来」，判据不同、计数不同
