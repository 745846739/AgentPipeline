# 01: decisions.md 表格改每条决策一节（机械转换 + 措辞校正 + 校验）

**What to build:** [docs/decisions.md](../../../docs/decisions.md) 从「一行一条」的
markdown 表格重构为「每条决策一个小节」的多行结构（`### 决策 N · 标题`，正文按需分
「裁决 / 起因 / 证据」段）。动机是 **git diff 可审性**：表格形态下修订任何一条老决策，
diff 就是一整行 2k–11k 字符的删 + 加，review 无法逐字核对；改成小节后，单条修订的 diff
只触及该条小节。对 LLM 的收益（引用锚点、grep 定位、避免超长行被工具截断）是顺带的。

## 硬约束（三条，违反任何一条即返工）

1. **正文逐字不变**。只改结构（表格行 → 小节），不改一个字的决策内容。转换必须用
   一次性脚本完成，转完用脚本校验：剥除表格管道符 / 分隔行等结构标记后，正文逐字节
   一致，且 364 条决策（#1–365，#318 空缺）一条不少、恰好一节。校验输出留档。
2. **修订措辞跟着换参照系**。文件里几十处以「行」为参照的表述——「本行原文保留」
   「该行尚未落表」「见 176 行」「四条修复见 226 行」等——转成小节后全部批量校正为
   以「条目 / 节」为参照（如「本条原文保留」「见决策 176」）。校正同样走脚本 +
   全文清单核对，不允许手工逐处改。个别语义拿不准的，宁可在清单里标「待人工确认」
   也不要猜。
3. **追加纪律与周边引用不破坏**。「只追加、修订就地标注」的纪律保持；顶部
   「现行有效性导读」节原样保留；[docs/README.md](../../../docs/README.md) 对
   decisions.md 的引用是整文件级（§13），预期无需改，但转换后要验证无悬空。
