# 部署与修复轮抢同一条分支（deploy-divergence）

**一句话**：值班长的修复轮把 `[repair]` 提交落在**部署检出本身**（`/opt/AgentPipeline`）的
`main` 上，而部署走 `git pull --ff-only`——一次修复就让后续每一次部署失败在拉取那一步。

**实证**：2026-10-08 部署决策 406–410 那五票时踩到，见
`.scratch/monitor-01M4CD59Y977ZQ0GMY9MPSFFMX.md` 的「收尾 · 二」一节与
[issues/01](issues/01-repair-commit-blocks-deploy.md)。

**为什么值得单独立账**：两端各自都「按自己的规矩做对了」——修复轮只做产品让它做的事
（在项目仓落提交），部署只做它被设计成做的事（只吃 ff）。矛盾出在**同一个目录同时扮演
两个角色**，而失败面（部署）离原因（有人在这仓里提交过）隔着两层，报错只说「拉不下来」。
