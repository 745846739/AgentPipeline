# 值班长对自己做过什么的记录（foreman-work-record）

**一句话**：值班长的收口句是它**下一轮**认识「我做过什么」的唯一读物——工具痕迹（`traces_json`）
从不回灌进 prompt，而收口句在判停那一支里会把本轮的改动清单丢掉。于是**刚改了二十来个文件**的下一轮
会如实汇报「**仍未动一行代码**」。

**实证**：2026-10-08 的对讲台班次 `01M4CDY9EC9M9FSSE236GJXYZC`（08:17–11:09 CST，31 行台账、
输入 1217.3 万 / 输出 21.8 万 token），全账见 [incident-2026-10-08.md](incident-2026-10-08.md)。

**为什么值得单独立账**：三处症状（自述失真 / 跨轮失忆 / 判停把进展记录抹掉）看着是三件事，
其实只有一条因果链——库里的 `content` 是唯一读物，而它在本轮改过文件时可以完全不含这件事。

**它是决策 311 的下一代**：决策 311（票 `foreman-burns-without-guard/issues/03`）已经把
「收场文案按**实际提议数**说话」立成纪律，并留下一条待办口子——「排查同一收口路径里是否还有别处
默认『提议必然存在』……不代表只有这一句」。本族补的正是同一类：**收口句对「本轮干了什么」的
断言，如今只有提议数这一个来源，而改动文件完全没有**。

**本族装着两件事**：① 收口行的**内容与时刻**（票 01–03）；② 收口的**对象**——它对准的是
人真正问的那句吗（票 04，`push` 那一轮就是没对准）。
