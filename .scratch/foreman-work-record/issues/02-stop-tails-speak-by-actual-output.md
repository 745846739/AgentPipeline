# 02: 五条收场尾句都按实际产出说话（显式续写决策 311）

**What to build:** 作为值班经理，我要**每一种停法**的收场尾句都只说自己真的算得出来的事。
今天只有「人按停」那一条会问库（决策 311 的 `proposal_note`），其余四条**连提议数都不提**，
更不提这一轮改了哪些文件——而 394 / 405 那两句恰恰出自「在打转」那条。

**为什么**：

- 五条尾句是硬编码字符串，落在 `runner.rs:1352-1399`：预算触顶 `:1360`、**在打转 `:1368`**、
  人按停 `:1378`、中途断流 `:1388`、轮数上限 `:1399`。
- 决策 311 的成品 `proposal_note` 只接在**第 3 条**（人按停，`:1378`）上——见
  `runner.rs:1312-1333` 那句注释「收场文案要按实际提议数说话（决策 311，票 foreman-burns 03）」。
- 后果实测：394 与 405 两轮（都在「在打转」那一支）尾句**逐字相同**：
  「……以上是已经确定的部分。**要接着查可以让我再来一轮（换个线索）。**」——而这两轮正是
  改了东西的那两轮，用户在 394 之前刚说过「直接改完啊」。
- 已有测试**逐字钉**着那句：`crates/core/tests/integration/foreman.rs:826` 断言
  `turn.reply.contains("换个线索")`——本票必须**成对改**它。

**形状**：

1. **把 `proposal_note` 升级成「产出注记」**：内容 = 提议数 ∪ 改动文件数（改动文件用票 01 的汇总器，
   两处共用一份判据）。四种组合各有措辞（0/0、>0/0、0/>0、>0/>0），**五条尾句全部接上它**——
   不是只接第三条。
2. **「在打转」那条尾句按「本轮有没有动过文件」分支**：
   - **动过** → 不再说「要接着查可以让我再来一轮（换个线索）」，改说「**已经改过的文件见上；
     要接着改说一声**」——一轮改了东西却建议「换个线索再查」是把修复轮说成研究轮；
   - **没动过** → 原文保留（对「确实查不下去」那一支，「换个线索」是对的）。
3. **五种停法的标记与归属一字不动**：`【未收口】` / `【未收口·在打转】` / `【已停】` /
   `【没跑起来】` 一眼分得开是裁决 9 的兑现点。
4. **范围**：只动值班长这一轮的五条尾句；值守轮那条（`FOREMAN_WATCH_FAILED_TURN_MARK`）不在本票内。
