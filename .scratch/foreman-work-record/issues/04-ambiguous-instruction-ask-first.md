# 04: 一条指令有两种读法时，先说出读法（最后一轮的 `push` 变成了「没人回答你」）

**Status:** needs-triage
**Blocked by:** None (can start immediately)

**What happened（2026-10-08，班次 `01M4CDY9EC9M9FSSE236GJXYZC` 的最后一轮）**：

- 11:08:26 系统：**提议已执行：合入修复分支 `repair/01M4CEFYE8XBZ3R98TKDFY3ZCV` → main**。
- 11:08:37 用户：`push`（4 个字符）。
- 11:08:37 助手：落一张 `task {action: resume, resume_action: continue, task_id: 01M4CD59…}` 的卡。
  它的推理原文自己写着 *Ambiguous. Should first get board?* ——**标出了歧义，然后选了「推进任务」**。
- 11:09:21.62 那个任务**自己**从 `pending` 变 `running`（`architect-design.execute attempt 2` 起跑，
  见 `kanban_node_runs` 376）；11:09:30 那份提议被判「现在的情况已经不是它当时说的那样」——
  `claimed_at` 为空，**从提出到作废都没能被按下**。
- 会话到此为止：既没有回答 `push` 指什么，也没有追问。

**两种读法当时都活着**：屏幕上是「已合入 → main」（本仓里合入之后紧接着的 push 就是
`git push origin main`，部署流程的第一步；而部署检出恰好会被这条本地提交堵住——同一场事故的
另一半见 `deploy-divergence/`）；而上一轮（407）结尾刚说过「要续跑我提 `resume: continue`，等你按」
——两种读法都有前文，**而它没有问**。

**为什么值得立票**：这一轮的终点是「**没有人在回答你**」，而代价是不对称的——猜错方向会去动
另一个任务的游标，问一句几乎零成本。它自己也知道歧义（推理原文在手）。

**形状（待分诊，我荐的方向）**：

- **(a) 行为层：多义指令先把读法说出来再动**——一轮只做了「猜」，卡片落地前没有任何一处
  表明它理解成了什么。**荐**，它治根且不必改数据形状。
- **(b) 产品层：提议卡面上写明「我按哪种读法理解的、依据哪一句」**——把 (a) 从「要求模型自觉」
  变成「按键前我看得见」。**荐**，与 (a) 一起做才闭环（(a) 治根，(b) 兜底）。
- (c) 提议因态势变化作废之后**自动重提或唤醒一次**（今天作废就没了，而这条卡作废时
  系统的动作已经发生过）——**不塞进本票**：那是值守唤醒面的事，范围另算。
