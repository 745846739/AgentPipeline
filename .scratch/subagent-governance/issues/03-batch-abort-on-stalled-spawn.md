# 03: 同批 spawn 先「未收口 / 超时」即刹车

**What to build:** 一条 assistant 消息派了多个 `spawn_sub_agent` 时，第一个以
**未收口 / 超时**收场的调用之后，**同批其余同类调用不再执行**——立刻补一条合成回执
（「同批前一个子代理未收口，本次未执行」）并落行，父轮随后照常收口。

**为什么**：2026-10-08 三个 spawn 是**同一条消息里的并行调用**，工具顺序执行、且
同批里一个失败不取消其余——于是「失败一个、又起一个」，三个都以同一句收场，
共烧 51.5 万 prompt token。同一批派出的子任务形态相近，第一个打满说明这一类活当前
做不成，剩下两个几乎必然同样打满。

**形状**：

- 判据**类别化**，不认报文字样（决策 259）：`ToolOutcome` 长一个
  `batch_abort: Option<BatchAbort>`（工具名 + 原因），由 `spawn_sub_agent` 在
  **未收口 / 超时**两种收场时挂上；「被中止」**不**挂（那是父节点自己的事）。
- 消费点：`model_invoke` 的工具批循环——已挂 `batch_abort` 时，后续 `call.name`
  相同的调用**跳过执行**，补合成回执（写明「未执行」与原因）并 `log.append`，
  与真回执同形；别的工具（`read_file` 等）**不受影响**，照常执行。
- 别的失败（传输类、参数类）**不刹车**——偶发失败不该误杀正当的并行探查。

**Blocked by:** 01（消费它引入的类型化收场）

**Status:** ready-for-agent

- [ ] 用例：一条消息两个 spawn → 第一个未收口 → 第二个**未执行**且拿到合成回执，
      run 行只有一条子代理 run
- [ ] 用例：第一个**成功**时不刹车，两个都真跑
- [ ] 用例：`read_file` 等非同类工具不受刹车影响（同批里照常执行）
- [ ] 用例：传输类失败不触发刹车（不误杀并行探查）
