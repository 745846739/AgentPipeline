# 对讲台的空间预算重排

**Status:** ready-for-agent

**Slug:** `talk-mobile-space`

**日期:** 2026-09-18　**决策:** [218](../../docs/decisions.md)（空间预算重排，含对 182 / 183 / 192 / 204③ / 215 的修订）＋ [220](../../docs/decisions.md)（回话中允许换班次 + 班次列表两枚标记，修订 204③ / 192）
**来源:** 用户诉求——「移动端空间较宝贵，考虑把对讲台能折叠的元素做成可折叠，能挪到其他页面的挪到其他页面，新增对话等元素固定在最下方（避免会话太长时往上翻很久）」＋「桌面端也需要固定住新建对话这些而不是随着对话上移」＋「把新班次也放在三个点中；去掉『说的每句话都会记进审计』」＋「钉住三个点的这一行」＋「回话中允许换班次，在会话列表中通过标记标识哪个会话有新回答、哪个会话正在运行」。
**方法:** 先拷问定形（Q1–Q17 + 决策 220 的 Q1–Q3），再实测取证（真二进制 + 真后端 + 真浏览器，430×900 与 375×667 逐块 `getBoundingClientRect`），并用一张**会自我核对**的原型（[prototype/talk-next.html](prototype/talk-next.html)，高度由页面现量、合计必须等于视口）把账画出来，最后裁决。**不动任何视觉规格**（像素风格 / 2px 描边 / 12px 字阶 / 264px 列宽）。

---

## 一、实测出来的问题（证据等级：实测）

430×900，对讲台，单张急停挂着：

```
viewport                      900
− 顶栏（sticky）              138
− 底栏（fixed）                42
= 可支配                      720
  ├ 上内边距                   10
  ├ 页头 .talk-head            38.4   ← h1 的 24px 行高是主体
  ├ 行距                       14
  ├ 值班板灯条 .crew           29.4   ← 8 工位 × 名称 × 计数
  ├ 行距                       14
  ├ 状态区 .zone-status        93.9   （折叠摘要条本身 65.9）
  ├ 行距                       14
  ├ 对话区 .timeline          352.6   ← 其中班次行又吃掉 36
  ├ 行距                       14
  ├ 输入坞上外边距             26
  └ 输入坞 .typer             113.6
```

**真正看得到话的地方：316.6px。框架吃掉 383px。**

四条同一装置上的读数：

| 发现 | 数字 | 这为什么是问题 |
|---|---|---|
| 班次行随对话上移 | 滚到底时它在屏幕上方 **320.2px**（375×667 上 **553.2px**） | 这就是用户说的「往上翻很久」 |
| 班次芯片触控目标 | 实测 **20px** 高（审计 R2-19 记的「约 27px」偏大） | 全站最小的可点控件，比审计已经在抱怨的还小 |
| 375×667（iPhone SE） | 对话区只剩 **156.8px**，且**静置态整页就溢出 37px** | 决策 192 的「能放下」只在 430 宽上成立过，这一档从没被量过 |
| 顶栏 8 格工位灯 | 在 `#/talk` 上 **8/8 无靶子**（`jumpToStation` 找的 `#s-<key>` 只存在于看板 `BoardColumn.svelte:75`），点灯滚位不动 | 看着可点、按了没反应 |

## 二、处置（逐块，全部写死在决策 218）

| 块 | 处置 | 收益 |
|---|---|---|
| 页头 `.talk-head` | `≤899`：`<h1>` 转 `visually-hidden`，收成一行 `班次名 · 值班中 · 本次会话 N tok · 看板` + 右端 ⋯，**并钉住**（44px 行 + 2px 下框 = 46px 带子，`top: 138px`） | −7.6px（38.4 → 46），换「全菜单恒可达」 |
| 值班板灯条 `.talk-side.crew` | `≤899` **删**（同一份读数在看板 8 列与顶栏灯带上各有一份，这是第三份）；桌面右栏不动 | +43.4px |
| 班次行 `.runrow` | `≤899` 收进页头右端的 ⋯（**含「+ 新班次」** / 切换 / 改名 / 归档）；**桌面移出滚动容器**、挂到页头那一行右端 | 窄档 +36px；桌面白得 36px |
| 坞的提示语行 | `≤899` **整行撤掉**（「说的每句话都会记进审计」这句不再显示——纪律不动，只是不再告知） | +25.2px（坞 113.6 → 88.4） |
| 顶栏 8 格灯 | 接通：`#/talk` 上点灯 → 去 `#/` 并定位到那一列 | 0 |
| 工位回执 `<details open>` | `≤899` 默认收起（内容一个字不删） | 长会话每轮 30–60px |
| 急停摘要条 | 折叠态**不画名牌**、上内边距归 0（93.9 → 73.9）；**一张急停都没有时整块退场**（≤899）；名牌只在展开那一张上（桌面款照旧） | +20px（有急停时）／+65px（没急停时） |
| 急停摘要条 / 对话 / 底栏 | 其余不动（急停摘要条的**钉位**从 138 挪到 184，见下） | — |

**预期收益**（实测基准推算）：430×900 上对话内容区 **316.6 → 427.7px（+35%）**；375×667 上 **156.8 → 约 195px**，并且静置态那 37px 溢出随之消失。
**钉住物的账要一起看**：窄档从两只变**三只**（页头带子 46 + 急停条 93.9 + 坞 88.4，加顶栏 138 与底栏 42 = 408.3px），换来的是班次动作（含开新对话）**恒在手边**——这正是最初那句诉求指向的东西。急停摘要条的钉位因此从 `top: 138` 挪到 `184`，`toggleStop` 的 `scroll-margin-top` 从 148 挪到 194（两处都是决策 192 的定值，属修订）。

## 三、四条不显然的裁决（这也是本叠最容易被后人改坏的地方）

1. **「固定」在两档价格不同。** 桌面上固定是免费的——整页本来就是不滚的框架，只有时间线在滚，所以班次行的病根不是「没东西钉」而是**它长在了滚动容器里面**，搬出来即可、一像素不花。窄屏上固定是拿对话区**永久**换的，所以窄档只钉该钉的三样：页头那一行（46px 带子——班次动作含开新对话因此恒在手边）、急停摘要条、输入坞；代价是对话区 46px。
2. **钉住一条带子会连带两处常量搬家。** 页头钉在 `top: 138px` 之后，急停摘要条的钉位必须从 **138 挪到 184**，`toggleStop` 回视野用的 `scroll-margin-top` 必须从 **148 挪到 194**——两个都是决策 192 的定值，不改就是「点开一张急停、而它藏在带子底下」。同时页头与状态区之间那道通用行距（14px）**要省掉**：带子自带 2px 下框，再叠行距是白给；`.talk` 的间距因此从统一 `gap: 14px` 改成逐块外边距（其余几对原样，坞前那 40px 也原样）。
3. **撤掉坞里那句「说的每句话都会记进审计」，撤的是告知、不是纪律。** 那句话是决策 192 ③/④ 特意留的一行（它拿 19.2px 的常驻死白换「坞不上下跳」），所以撤它要写清：决策 182 §3.3 纪律 4 的「说的每句话都进审计」**照旧成立**，审计照旧全量落库——只是不再在坞里说。但那一行同时是「值班长正在回话…」与「流断了…」两句瞬时状态的落点，而**这两句的命运不同**（决策 220④）：前者**删**——流式尾随光标已经在说这件事；后者**留，而且删不得**——它是全页唯一的传输层断线告知（`streamStatus` 在仓里只有这一个消费者），「实时流断了不能静静不更新」是审计 R2-18 的既有能力，只把它改成**不常驻**（空闲不占高、断线时才出现）。
4. **急停摘要条上方那 20px 只在「展开那一张」里才是名牌的位子。** 名牌 22px 高、向上悬出卡片框沿 **14px**（实测），所以只要画名牌就至少要 14px 净空——折叠态因此**不画名牌**（183 裁决③给摘要条定的三块里本来就没有它），上内边距归 0；展开态才把名牌与那 20px 一起拿回来。**一张急停都没有时整块退场**，词表里「急停」的首现平实说法随之搬到摘要条自己的琥珀标签上（译文跟着词走：没词就没有要翻译的词）。照旧提醒：**「急停（等你拍板的阻塞）」与那个 20px 是绑在一起的**，谁要动其中之一，先把另一处的几何量一遍。
