# 06: 工位回执窄档默认收起

**叠:** A（不动规格；**但本票在窄档一档反转决策 182 的一条纪律**，实现时必须按票 08 的清单在原决策处标注）

**来源:** 决策 218 ②/Q11

**What to build:** 每一轮的「工位回执」`<details class="rcpts" open>`（`Talk.svelte:1239`）默认展开，每轮 30–60px 不等——长会话里这是最大的隐性纵向开销，而且它恰好是「往上翻很久」的累加项。窄档默认收起，**内容一个字不删**：出处按一下就在，只是不再默认占屏。

**Blocked by:** 01

**Status:** done（回执按档默认收起已落地；「展开后不被流式增量打回」e2e 全绿）

- [ ] `≤899px` 默认收起（`open` 不写死），桌面（`≥900px`）照旧默认展开——这是**分档**的差别，不是全站改口径
- [ ] 收起后 `summary` 仍要把**出处与条数**说全（现在是「工位回执 N 次台账查读 ▸」），因为「可追溯性不因对话而丢失」这条纪律在窄档只是**换了个开销方式**，不是作废
- [ ] **展开态必须由本地状态按 `turn.key` 受控**：流式增量会在同一轮上反复重渲染，不得把使用者手动展开的那一轮关回去（这是本条最容易出错的地方，也是最容易写成「默认收起 → 每收一次增量就跳回收起」的地方）
- [ ] 跨刷新不记忆（与决策 217 的口径一致：折叠态不进 URL / localStorage）
- [ ] 改动处写清楚这是**决策 218 对 182 纪律在窄档一档的反转**，并给出理由（窄档的纵向空间是拿钉住物之间的残渣换的）
- [ ] e2e（430×900）：新的一轮默认**收起**（回执内容不可见、summary 可见且有「N 次台账查读」）；点一下后内容可见
- [ ] e2e（430×900）：手动展开后**再收到一次流式增量**，那一轮仍是展开的
- [ ] e2e（1280×720）：桌面仍默认展开（分档判据成立）
- [ ] 回归：窄屏「静置版面」与「长对话滚到底」两组全绿；`.timeline` 的几何断言按新基线（票 03 定稿值）不走样

**边界.** 不动修复提议那份补丁的 `<details class="rcpts">`（它本来就是收起，`Talk.svelte:1134`）；不动 `.rcpt` 的呈现形状（左缘 4px 亮度阶 + 无框）；不动「转述不是发言」那条形状区分。

## 实现记录（2026-09-18）

- 折行档（`≤899`）的工位回执默认收起：`<details class="rcpts" open={receiptIsOpen(turn.key)}>`，`receiptIsOpen(key) => receiptOpen[key] ?? !folded`——桌面仍默认展开，人手动展开过的那一轮**不被流式增量打回**（e2e 把 POST 拖住 2.5s 验的正是这件事）。
- `.rcpt` 的形状（左缘 4px 亮度阶 + `--panel` 底、无框）与修复提议那份补丁的 `<details>` 都没动；内容一个字没删。
