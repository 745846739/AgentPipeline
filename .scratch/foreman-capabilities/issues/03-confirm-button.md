# 03: 确认钮——提议渲染成一颗钮，按下走既有端点

**What to build:** 确认钮**内联在对话时间线的那一轮里**（决策 207），复用急停轮的 `.warn` 形态与
`board/PendingActions.svelte` 的渲染，**不新开第三个按钮面**；同一个动作若已在状态区的急停轮里有
`allowed_actions` 的钮，**只渲染指路、不画第二颗**——决策 176④ 的原顾虑（「同一个动作两个位置各一颗钮」
会让「哪颗是真的」变成用户的问题）由此保留，而 188 要的「写操作要人按确认钮」也满足。

- `Talk.svelte` 的 `turns` 归约（`:157-206`）里加一种轮：**提议轮**（工具名、参数摘要、一句话说明、
  过期倒计时）。
- 按「执行」→ `POST /foreman/proposals/{id}/execute`；按「拒绝」→ reject。两者结果**都回灌成一轮对话**
  （成功失败都进时间线，不弹窗、不 toast——与 `send()` 的失败处理同一姿态）。
- 过期：按钮变灰并说明原因，**那一轮仍在时间线**（审计）。
- **断言改写（本票的硬要求）**：`frontend/e2e/talk.spec.ts:400-401` 与 `:664` 的「回话里没有按钮」改为
  「回话里**只有确认钮**，且它不直接改状态」；`:656` 那条「状态区为空时零按钮」的断言**保留**。
- **视觉**：确认钮**不新开一档「响」**（决策 203：全站唯一告警仍是急停）；档位由
  `design/theme-6-pixel.md` §3.3 裁决（`run-command-permissions/04` 落笔）。

## 交付

- **渲染判据全在 `frontend/src/lib/proposals.ts`**（纯函数，18 条 L1 钉住）：`proposalState`
  （**过期由前端按 `expires_at` 自己算**——等后端每小时那趟清扫会让按钮在过期后还亮着最长一小时）、
  `proposalStateLabel` / `proposalShortLabel`（长说法与 `dtag` 的短说法分开，同一轮里不重复读同一句）、
  `proposalPointerOnly`（**同一个动作已在 `allowed_actions` 里就只指路**，而**详情没到时不指路**
  ——那会把「还没读到」说成「已经有了」，于是两颗钮都没有）、`proposalToolLabel`（认不出的工具名原样显示）。
- **落地在 `Talk.svelte` 的时间线那一轮**：类名 `.turn.prop`（**不叫 `.warn`**，决策 203），
  名牌「操作台」，`dtag` = 状态 + 工具 + 倒计时（只给分钟一档），`<details>` 里是**参数原文**
  （按键之前要看得出它到底要什么），两颗钮 = 执行 / 拒绝。过期只让两颗钮变灰 + 一句原因，**那一轮留在
  时间线**；终态（执行过 / 被拒绝）收掉两颗钮、保留那一轮（**先判终态再判指路**）。
- **按下走既有端点**：`POST /foreman/proposals/{id}/execute|reject`，结果一律回灌成一轮
  （**不弹窗、不 toast**），失败就地挂在**那一轮**下面（报错带 id，同时挂两条提议时不会串台）。
- **`role = system` 的行单独成一种轮**（`.turn.console`，名牌「操作台」）：提议的执行结果**不是**
  值班长说的话——挂在它的名牌下等于替它认领了它没做的事（与后端把它落成系统轮、转写进模型对话时
  加 `【操作台】` 标记是同一件事的两端）。
- **e2e**：`talk.spec.ts` 由 15 条增至 17 条。⑦ 那条「回话里没有按钮」改写成
  「回话里没有按钮 + 时间线上**唯一**的钮是操作台提议轮里的确认钮」；新增两条：按下执行
  （**文件真的落到磁盘上**、结果回灌成一轮、两颗钮收掉）与按下拒绝（作废、明确写「没有执行任何动作」）。
  空看板那条的「零按钮」断言保留，并收窄到 `.timeline .turn`（时间线里还有班次 chip 行那四颗钮）。
- 一处版面事实记录在用例里：状态区占 46vh，720px 的窗口下时间线只剩一条缝，确认钮在缝里点不到；
  两条新用例显式设 `1280×1000`（与窄屏用例显式设 430×900 同一手法），真人窗口比这高。
