## 一、这一轮的实测底稿（全部有落点，可复核）

### 1.1 现场：一条新任务三次 execute 全挂

任务 `01M2VSNJ11W5VYPNFGY7FC6HXM`（描述就是上面的诉求，开了托管），2026-09-19：

| run | 结果 | 耗时 | prompt_tokens | error |
|---|---|---|---|---|
| 24 init.execute | success | 93.8s | 0 | — |
| 25 architect-design.validate_input | success | 91.1s | 476,081 | — |
| 26 architect-design.execute（1） | **failed** | 739.4s | **3,772,456** | `provider 模型不可用` |
| 27 architect-design.execute（2） | **failed** | 1,509.8s | **3,453,614** | 同上 |
| 28 architect-design.execute（3） | **failed** | 522.9s | **2,280,377** | 同上 |

任务 `total_tokens = 10,489,286`。唯一 provider 的 `context_window = 128,000`。

**两次读法上的收获**：

- **「0 token」这个形状在这次没有复现，而原因本身就是决策 226③ 的功劳**：旧构建的失败路径给
  `finish_run` 传 `RunTokens::default()`，任何失败 run 都记 0；226 让它照实记账，于是同一个 bug
  第一次露出了真数字（几百万）。**昨夜「零 token 定不死」的一半答案是记账，不是缺证据。**
- 但**另一件更贵的事没有被任何人看见**：三次尝试合计 1,050 万 prompt token，**值守轮一次都没醒**。
  `scheduler_no_effect` / `task_pending` 都不成立（失败后游标自动重试、任务始终 `running`），
  而 `AttentionKind` 里**没有「run 失败/重试」这一类**。这正是 09-18「8h51m 无人知晓」的形状原样复现。

### 1.2 它自己的失败：证据有了，归位不了

第三轮回话里它报的是**活栈**（`sample` 连采两次、`pgrep -fl git` 零命中排除 git、`lsof` 看到两条
Cloudflare 连接、叶子 `__recvfrom`），链条落到
`Executor::agent_node → agent_attempt_inner → LlmClient::complete → parse_chunk → serde_json`——
**方法完全正确**。

但它把这套证据记在 **run 26** 名下，而 run 26 在 `03:14:54` 就已经 failed 了；采样时刻是 `03:19:15`，
那个栈是 **run 27** 的。它甚至自己写了「起止时刻对不齐…中间有没有重发，栈里看不出」，**摸到了洞
却没发现自己用错了 run**。

结构性原因（核过）：`kanban_node_commands` 有 `run_id`（节点命令第 317 条挂在 run 27 上），
值班长自己的命令有 `session_id`（第 363 / 372 条）——**命令可归位**；而**模型请求那一层完全没有身份**
（全库没有模型请求表，`kanban_node_runs` 也没有请求级字段）。栈里没有任何东西写着它是哪个 run 的。

### 1.4 已经具备的（免得只说缺口）

`logs/` 读得到（决策 226 生效）；证据边界诚实（自己报出「这份日志 16 行、没有一条逐 run/逐节点行，
零 token 在这份证据面上无解」）；排他法用得对（`pgrep git` + 栈里 `wait4/posix_spawn` 帧数 = 0 排除 git）；
在飞 run 的 `prompt_tokens = 0` 它自己判为「初值，不能当 stall 证据」。

## 三、票序与不可换的顺序（提案，设计已收敛）

设计树的 frontier 已空（四轮 13 问）。下面是把这十三条裁定落成代码的顺序，**前四条不可换**：

1. **231 请求级表 + 日志三行 + 进诊断包** —— 唯一动数据模型的一条（一条迁移），也是「归位」与
   「量速」共同的地基。**必须与决策 230 判据的用例同批**：判据没有可测的读数就是一句空话。
2. **237 `run_readonly`（含先改冻结断言）** —— 把「自主轮能取证」从话变成能力。与 1 互相独立，
   但两者都在读面，并批省一次构建。
3. **235 + 238 归因结构块（哨兵段 + 解析点 + 用例 + 界面标记）** —— 判据的可校验面。排在 1 之后
   才有正收益：没有请求级读数，它多半只会产出「未定位」，而那条结论本身没错、却毫无用处。
4. **236 `node_overrides` 回显 + 校验** —— 决策 228 的前置，任何「动作面」的工作都得先有它。
5. **234 两类关注项** —— 最便宜的一条（两个枚举 + 两处 `note_attention` + 节流用例），
   且立刻止住「烧掉一千万 token 而值守不知情」。
6. **233 + 239 收尾语义三件** —— 与其余都不冲突，可随时并入。

**明确不做**（三条都是本批边缘上被主动切掉的，改主意要重开一条）：228(c) 重打壳那一公里；
229 授权扩张（托管自动集 / D 层免按键）；236(d)「整条替换 → 局部合并」。
