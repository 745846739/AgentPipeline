# 03: 归因结构块（哨兵段 + 解析点 + 界面标记）

**What to build:** 回话里**机器可读的一段**（哨兵式，后端解析），至少含 `attribution`，
取值是决策 227 的四类之一（宿主环境 / 流水线运行 / 目标项目代码 / prompt 与配置）；
**四类之外不许收口**，「根本没给」与「四类之外」由**同一个解析点**判（决策 235 / 238）。
落地面三处：① 界面在播报那一轮显示类别标记；② 用例钉「四类之外不许收口」；③ `read_diagnosis`
顺手带出最近一次的归因类别。

**为什么必须有**：决策 227 把归因类别定成播报必填，而写在人格里的「必填」**没有校验点**——
2026-09-19 实测里一次「格式漂亮但归错 run」的回话，行文与引用格式都合规，没有任何断言拦得下它。

**Blocked by:** 票 01（没有请求级读数，它多半只会产出「未定位」——结论没错却毫无用处）

**Status:** pending

- [ ] 人格与 `power_discipline` 里写清「每一轮播报都要带这一段」（后端不认识就意味着未定位）
