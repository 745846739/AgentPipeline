# 推荐面板的「启用」半条链（agentpipeline-recommend-enable）

**Status:** 三张票全部落地（01 / 02 前端 + 后端，03 追溯与决策落表）。

用户诉求（2026-09-17）：「今天做的一键安装推荐技能的需求，我在页面没找到按钮」。

## 现状盘点（实机诊断，不是纸面推的）

按钮的代码在、构建也在，被**渲染条件**整片挡掉了：

| 事实 | 证据 |
|---|---|
| 面板挂在「设置 · 模型与密钥」页最下方，不在技能市场页 | `frontend/src/routes/SettingsProviders.svelte:265` |
| 按钮只在**未安装**的行上渲染 | `frontend/src/components/settings/StageRecommendations.svelte:52` 的 `{#if !skill.installed}` |
| 该机 10 行推荐**全部已安装** → 渲染出的按钮数 **0** | 实机 `GET /skills/recommendations`：10 行 `installed: true`；`~/.agentpipeline/skills` 里 8 个推荐技能全在 |
| 不是构建陈旧 | `frontend/dist`（22:59）与 `/Applications/AgentPipeline.app`（23:03）都含该面板 |

**真正缺的是「启用」那半。** 票 16 第 14 条写的是「未安装的项带「安装」按钮，**已安装的可直接启用**」
——这是两件事。后端两条路都实现了（`POST /skills/install` 撞上「已在技能根里」时只写配置、`note` 说明
未重新下载，`one_click_install_enables_an_already_installed_skill` 有用例），**界面这一半从来没写**：
组件里只有「安装」，没有任何「启用」控件。

影响面不止「少一个钮」：`develop` 行的 `tdd` 现在显示「已启用：阶段 test-design」——在 develop 行上读
起来是误导的。按「本阶段是否声明」放控件，本机应看到 `develop` 与 `test` 两行的 `tdd` 变成「启用」。

## 一句话范围

把票 16 那句「已安装的可直接启用」在界面上落地：推荐行按「未装 / 已装未在本阶段启用 / 已启用」三态渲染，
并在界面上标出这份推荐是哪个仓的哪一份。

| 文件 | 内容 |
|---|---|
| `issues/01` | 推荐行区分「已装未启用」，就地启用（后端判定字段 + 界面三态 + 两端用例） |
| `issues/02` | 推荐行标出「这是哪个仓的哪一份」（决策 194 的定位字段落地到界面） |
| `issues/03` | 收尾：行为映射表、用例目录与决策落表 |
