# 前端像素主题替换（agentpipeline-pixel-theme）

**Status:** ready-for-agent

> 来源：2026-09-13 用户诉求「把本项目前端替换成像素主题」。素材已在仓库中：
> 规格 [design/theme-6-pixel.md](../../design/theme-6-pixel.md)（提案）与四份原型
> [prototype-pixel.html](../../design/prototype-pixel.html) /
> [prototype-pixel-light.html](../../design/prototype-pixel-light.html) /
> [prototype-pixel-mobile.html](../../design/prototype-pixel-mobile.html) /
> [prototype-pixel-mobile-light.html](../../design/prototype-pixel-mobile-light.html)。
> 本 spec 把「提案 → 现行视觉」的选型、落地范围与验收口径定死。

## Problem Statement

当前前端的视觉是主题三「终端 · 调度电报」（磷光绿黑底、Fira Code、字符线路行、方括号按钮）。
这套语言的问题是它把「状态」编码成字符与亮度阶——用户要读懂 `◆`/`●`/`○`、`[dev]`/`[tst]`
和方括号按钮才能看懂页面，机械感来自字符串而非界面物件。它不像一台**在运转的机器**：
没有实体、没有材质、没有「哪台机器停了」的直觉。

素材侧的问题是**提案不是交付**。像素主题的规格与四份原型（深浅 × 桌面/移动）已完成并截图
验证，但它停在 `design/` 里；仓库里同时挂着两套视觉方向（主题三实现 + 主题六提案），
`frontend-design.md` §6 仍写「视觉方向以主题三为准」。用户看到的前端与原型不是一回事。

## Solution

把主题六「像素机房 · 夜班流水线」落到前端实现，作为**唯一现行视觉**，并让主题三退役为历史。

领域转译（theme-6-pixel.md §1）：任务是传送带上的**货箱**，列是**工位**，轨道是**传送带**，
状态是**信号灯**，pending 是**急停**，dossier 是**操作台对话框**，折返线是**回流带**，
并行分支是**双带并轨**。四条原则：像素纪律（0 圆角 / 2px 描边 / 4px 硬投影 / 唯一 dither）、
灯即状态、急停对话框是主角、帧步进无缓动。

交互与信息架构**一律不动**：路由、五页签、列语义、pending dossier、
`allowed_actions` 纯渲染（决策 69/101）、异步按钮、卡片禁拖、sync-check 全站不展示（决策 107）
全部沿用 `frontend-design.md` §4–§7。本 effort 只替换该骨架上的视觉语言，以及为承载像素语汇
所需的**表现层**新元素（sprite、量表、横幅、道具栏槽位）。

## 已确认的四个选型（本 spec 的边界）

| # | 决策 | 含义 |
|---|---|---|
| A | **完整对齐原型** | 落地 theme-6-pixel.md §2–§3 全部，不止 token/字体层：包含 sprite 图标、列头挥锤小人、token HP 量表、boss 战尝试条、道具栏过滤槽位、急停 RPG 对话框、任务完成横幅。原型即验收参照 |
| B | **主题三退役为历史** | 像素主题成为唯一现行视觉；主题三规格与原型移入 `design/deprecated/`（沿用「夜间调度台」退役先例）；深/浅双色变体保留 |
| C | **单接缝 + 两层现有验证** | 新增唯一接缝 = 主题契约模块（token + sprite + 几何常量），被 CSS/组件/两层测试共同消费；验证复用 vitest 与既有 playwright harness，不新建测试层 |
| D | **字体自托管入库** | Fusion Pixel 12px Monospaced 的 78 个 woff2 子集（实测 ~860KB）随仓入库并内嵌进单二进制（决策 155），离线可用；随附 MIT AND OFL-1.1 许可文本 |

## User Stories

1. 作为在自己机器上跑流水线的开发者，我想打开界面就看见一台还在运转的 8-bit 流水线，所以我能凭直觉看出哪里在跑、哪里停了。
2. 作为开发者，我想 pending 是全站唯一「响」的东西，所以在没有等人决策的页面上我能安静地看数据。
3. 作为深夜使用的开发者，我想底色是带蓝紫色温的厂房夜灯靛而不是纯黑，所以长时间盯屏不刺眼。
4. 作为白班/日光下使用的开发者，我想在浅色「掌机背光」变体里得到同一套语言（背光灰纸 + 墨青字），所以强光下也读得清。
5. 作为有色觉障碍的开发者，我想状态不只靠色相区分（灯 + 描边 + 文字双编码），所以红绿不分时我也能判断失败与执行。
6. 作为开启 `prefers-reduced-motion` 的开发者，我想全站动画静止，所以界面不再有位移与闪烁。
7. 作为开发者，我想看板卡上的迷你轨是一条传送带、游标处的链节点亮，所以我能一眼看出任务跑到了第几站。
8. 作为开发者，我想运行中工位两侧的链节以离散步进走动，所以我能确认「这台机器真的在动」而不是界面卡死。
9. 作为开发者，我想每张货箱的 token 消耗量化成 16 段 HP 条，所以成本是可视的刻度而不是一串数字。
10. 作为开发者，我想运行中的货箱显示 boss 战尝试进度条，所以我知道这个阶段还剩几次机会、是不是最后一次。
11. 作为开发者，我想顶栏过滤是 34px 道具栏槽位（图标 + 计数徽章），所以切过滤像翻物品栏，且计数就长在槽位上。
12. 作为开发者，我想点开 pending 时看到的是一条双线框 + ▼ 闪烁光标的急停对话框，所以我立刻明白「在等我按键」。
13. 作为开发者，我想 dossier 对话框左侧坐着 16×16 工头头像，所以「谁在等我」这件事有面孔而不是纯文本。
14. 作为开发者，我想恢复动作是对话框里的菜单项按钮、主动作带 `▶` 前缀，所以我知道按哪个是推进。
15. 作为开发者，我想任务进入 done 时顶部居中弹出奖杯横幅并给出 diff 摘要，所以完成有明确的收束感。
16. 作为开发者，我想那面完成横幅不自动消失、由我点「收下」关闭，所以它不会在我读完之前溜走。
17. 作为手机用户，我想看板把横向传送带竖过来、一次只放一站，所以窄屏不需要横向找位置。
18. 作为手机用户，我想道具栏槽位不缩、放不下就横滚，所以状态过滤项都点得到。
19. 作为手机用户，我想 pending 的动作沉到常驻底部动作坞（琥珀顶框 + ▼），所以单手就能做决策。
20. 作为手机用户，我想挥锤小人挂在站头、详情页只在当前站出现，所以我能看出哪一站是活的。
21. 作为手机用户，我想页面导航行与顶栏同 sticky，所以滚长列表时我也能换页。
22. 作为开发者，我想任务详情的轨道 hero 是同一条传送带的放大版（节点用灯表达亮 / 半亮 / 空 / 琥珀 / 红），所以列表与详情是同一台机器。
23. 作为开发者，我想五个页签是工位标签盒（active = wash 实底 + 描边上浮、禁用 = dither 底），所以页签与工位是同一套材质。
24. 作为开发者，我想命令、路径、diff、ID、token 数字仍是等宽的、连字关闭、tabular-nums，所以可执行物逐字符可读（这是全站唯一字族，不是退步）。
25. 作为开发者，我想项目管理 / 模型与密钥 / 全局指标 / 手机访问四个台账页与看板同一套 2px 描边盒 + 硬投影，所以设置页不像另一个应用。
26. 作为开发者，我想全局指标仍是挂在轨道站点下的分段条形图（不是 KPI 卡片横排），所以「轨道即导航」在指标页也成立。
27. 作为开发者，我想不受支持的 vendor 行仍整行灰显 + 琥珀告警而不是崩溃（决策 103），所以拼错配置不会白屏。
28. 作为手机用户，我想手机访问页的二维码恒白底（扫描器依赖明暗对比，浅色主题也不例外）、地址可切换可复制，所以扫码能成功。
29. 作为手机用户，我想仅回环绑定时看到 `--host 0.0.0.0` 指引块而不是无效二维码（决策 167），所以我知道该怎么让手机连上。
30. 作为离线/局域网用户，我想像素字体随二进制内嵌，所以无外网时主题身份不丢（不会静默回退成系统 monospace）。
31. 作为开发者，我想深/浅切换瞬时生效并跨会话记忆、首屏不闪回深色，所以主题选择是我的偏好而不是每次重选。
32. 作为键盘用户，我想焦点环是 2px 硬描边且可见，所以我能看见自己在哪里。
33. 作为开发者，我想按钮按压是位移消影（`translate(4px,4px)` + 去投影），所以点击有实体触感。
34. 作为开发者，我想长耗时按钮仍是点击即 loading 禁用、SSE 回执后复位，所以异步动作不会被重复提交。
35. 作为开发者，我想动作提交失败仍有可见横幅（决策 159），所以按钮不会成为静默死路。
36. 作为开发者，我想看板卡上的动作按钮仍然可点（决策 164 的 z-index 修复不得回退），所以换主题不重新引入那个缺陷。
37. 作为维护者（agent），我想视觉 token 有唯一事实源，所以改一处不会在 CSS 与组件间漂移。
38. 作为维护者，我想像素图元只允许来自受控 sprite 表、新增要回规格修订，所以主题不会被零散图标侵蚀。
39. 作为维护者，我想既有 17 条 playwright 与 96 条 vitest 全绿，所以视觉改造不悄悄改掉行为。
40. 作为维护者，我想终端主题明确退役进 `design/deprecated/` 而不是两套并存，所以新组件只需写一遍。
41. 作为维护者，我想 e2e 对像素主题有真断言（计算样式、像素图元数量），而不是只换了个 class 也算过。
42. 作为维护者，我想仓库里不存在 token 之外的裸十六进制颜色，所以「像素纪律」是可机器检查的。
43. 作为产品/评审，我想原型即验收参照、真应用截图可重新生成，所以「实现对不对」不靠争论。
44. 作为开发者，我想顶栏待办计数仍是全站唯一动态计数入口、点击下拉列出 pending 任务（决策 92），所以换皮不改交互契约。
45. 作为开发者，我想内容区最宽约 1000px、dossier 右栏约 320px、看板列 264px，所以高密度信息仍是同屏的。

## Implementation Decisions

### 1. 视觉方向权威变更与主题三退役

- `design/theme-6-pixel.md` 由**提案**升格为**现行视觉规格**（状态行改写），并补一节「实现映射」
  登记与实现的对应关系（原型 class ↔ 组件）。
- `design/frontend-design.md`：§3「视觉语言 / Design Tokens」重写为指向主题六；§6 那句
  「视觉方向以主题三为准」改为以主题六为准。**§4–§7、§9.2 的交互骨架与前端约束清单逐字保留**
  ——它们是本 effort 的不变量（决策 69/79/84/92/101/105/107/153）。
- 主题三退役：`design/theme-3-terminal.md` 与四份 `prototype-terminal*.html` 移入
  `design/deprecated/`，并在该目录的既有 README/清单中登记退役原因与日期（沿用
  「夜间调度台」先例）。终端专属 token 从 `app.css` 删除，不留两套并存。
- `docs/decisions.md` 追加一条决策，登记：视觉方向切换、主题三退役、单接缝、字体自托管四项，
  以及第 4 条列出的与决策 84 的关系。

### 2. 主题契约模块（唯一新接缝）

新增一个**主题契约模块**，是 token、sprite 与几何常量的唯一事实源，导出三类内容：

- **几何常量**：描边 2px、硬投影 `4px 4px 0`、圆角 0、字阶 `[12, 24, 36]`、dither 周期 4px、
  token 量表 16 段、boss 条 20 段、道具槽 34px、看板列 264px、dossier 320px、详情 max 1000px、
  货箱顶盖 dither 带 6px、传送带 8px、移动断点 480px。
- **色彩 token 名表**：深浅两套的 token 名与值，与 `theme-6-pixel.md` §2.1 / §2.4 的表逐行一致。
- **sprite 表**：15 枚图元（`flag` / `gem` / `hammer` / `flask` / `gear` / `lens` / `shield` /
  `merge` / `trophy` / `chest` / `alert` / `chart` / `key` / `phone` / `foreman`），
  每枚 = viewBox（8×8，`foreman` 为 16×16）+ rect 列表，从原型 `SPRITES` 机械搬运。
- **状态映射**：灯色 token 名、描边 token 名、小人节奏（run 0.6s / wait 1.8s / idle 静止）
  与状态（running / pending / failed / done / queued / waiting）的对应表。

`sprite` 表与几何常量以 TS 数据形式提供，组件直接消费；**色彩 token 由 `app.css` 手工镜像**
（不引入代码生成步骤），由第 3 条的解析测试锁死一致性。理由：`app.css` 还承载全站基元与移动版
规则，把它整体生成化会让「手改 CSS」变成危险操作；镜像 + 测试得到同等防漂移保证且更简单。

### 3. `app.css` 重写为像素 token 契约

- 保留语义命名（`--bg` / `--panel` / `--wash` / `--pane` / `--text-hi` / `--text` /
  `--text-2` / `--text-3` / `--text-4` / `--go` / `--go-ink` / `--pending` / `--stop` /
  `--done` / `--diff-add*` / `--diff-del*` / `--input` / `--overlay` / `--pending-tint` /
  `--r-panel` / `--r-pill` / `--rail-col-width` / `--detail-max` / `--safeb`），
  使组件与既有测试的语义口不变。
- 新增像素 token：`--ink`（硬投影墨色）、`--belt-lit`、`--branch-dev` / `--branch-tst`
  （仅徽章）、`--hairline`（浅色移动款弱分隔）。
- 删除终端专属 token：`--br` / `--br-done` / `--lit` / `--dash` / `--spin*` / `--mask-bg` /
  `--rail-band*` / `--head-band` / `--bar-band` / `--bracket` / `--go-hi` 若无人消费则删。
- 深色为 `:root` 默认，浅色经 `html[data-theme='light']` 覆盖（**沿用现有属性与
  `localStorage` 键 `agentpipeline.theme` 不变**，`index.html` 的防闪回内联脚本保留）。
- 全站基元：圆角 0；描边只有 2px 一档；阴影只允许 `4px 4px 0 var(--ink)`；按压
  `translate(4px,4px)` + 去投影；`-webkit-font-smoothing: none`；`b`/`strong` 只提亮不加粗
  （像素字体无字重轴）；字号只取 12 / 24 / 36。
- dither 是**全站唯一的「渐变」**，只允许出现在货箱顶盖带与已归档工位两处。
- 四个字族变量（`--font-code` / `--font-ui` / `--font-cond` / `--font-mono`）全部指向同一像素字族，
  连字继续关闭、数字继续 tabular-nums。

### 4. 状态语义不变（与既有决策的关系）

- 五色信号语义逐条沿用：绿 = 执行、琥珀 = 等人（全站唯一告警）、红 = 失败、灰 = 归档、
  蓝 / 紫 = 分支徽章。一张货箱 = 一枚灯 + 一种描边色；灯是实心像素方块，绝不作大面积底色。
- **与决策 84 的显式标注**：决策 84 要求「pending 药丸按分支着色、动作集独立下发」；主题三
  的实现把它落成 `[dev]`/`[tst]` 文字标签（不用色相）。像素主题改为**徽章色相
  （`--branch-dev` 蓝 / `--branch-tst` 紫）+ 文字双编码**——分支消歧语义与动作集下发的实现
  不变，变更的只是消歧的视觉手段。此项须在决策登记与票面显式标注，并同步更新 e2e 中对
  `[dev]`/`[test]` 字面量的断言（见 Testing Decisions）。
- 决策 92（列归属 / 焦点游标）、101（`allowed_actions` 纯渲染、archived 默认不可见）、
  107（sync-check 全站不展示）、103（不受支持 vendor 灰显）、112（密钥掩码）、
  167（`/server-info` 与二维码由后端渲染，前端不引 QR 库）**逐字不变**。

### 5. 组件改造清单（theme-6-pixel.md §3 / §3.1 的落地）

按映射表逐个组件改造，每项以原型同名元素为参照：

- **顶栏**：wordmark 24px + `3px 3px 0` 硬投影（全站唯一带投影的文字）；过滤项 = 34px 道具栏槽位
  （图标 + 右下计数徽章，选中 = 亮描边 + wash 底）；待处理计数入口与下拉保持决策 92 的语义与
  交互，仅换材质。
- **轨道脊线（`PipelineRail` 三变奏）**：字符线路行（`○ ● ◆`）一律替换为像素灯与链节；
  传送带 8px、`repeating-linear-gradient` 画链节，运行中工位两侧链节 `steps()` 步进；
  站点 = 12px 信号灯方块 + 工位名（12px + `letter-spacing: 0.08em`）；并行区间画成双带并轨
  （徽章蓝 / 紫），在 develop 前合流；折返为回流带虚线。
- **列头**：8×8 工位 sprite（旗 / 菱形规锤 / 锤 / 烧瓶 / 齿轮 / 放大镜 / 盾 / 汇流 / 奖杯）
  + 工位名 + **挥锤小人**（run 快挥 / wait 慢挥 / idle 静止，帧切换为离散 opacity 翻转）。
- **看板卡（货箱）**：2px 描边盒 + 6px dither 顶盖带 + `4px 4px 0` 硬投影；
  meta 行带 16 段 token HP 量表；运行中另带 20 段 boss 战尝试条（最后一次尝试整条转红）；
  pending = 琥珀描边 + `?!` 灯 + 琥珀 2px 左缘条；hover = 描边亮一档；**卡片仍禁拖**，
  整卡导航链接与动作按钮的层级关系保持决策 164 的修复结果。
- **急停对话框（pending 理由 / dossier）**：奶油双线框 + 压在框沿上的琥珀**名牌 tab**
  + ▼ 闪烁光标；dossier 左侧 16×16 工头头像；恢复动作 = 对话框菜单项按钮，两类动作视觉分组、
  旁路动作弱化（决策 69/70）。
- **按钮**：像素钮（2px 描边 + 3px 硬投影 + 按压位移）；主动作 = go 实心 + `▶` 前缀；
  异步 loading 语义不变。
- **详情轨道 hero**：同一条传送带放大版，节点状态用灯（亮 / 半亮 / 空 / 琥珀 / 红）。
- **Tab**：工位标签盒（active = wash 实底 + 描边上浮；禁用 = dither 底）。
- **底部状态行**：车间看板条（2px 顶描边 + token 总量量表 + 分隔符 `▪`），主题切换钮并入此行。
- **完成反馈**：顶部居中任务完成横幅（奖杯 sprite + 「任务完成」+ diff 摘要 + 「收下」按钮），
  **无入场动画**，点「收下」关闭。
- **四个台账页（项目 / 模型与密钥 / 全局指标 / 手机访问）**：同一套 `crumb` + `p-title` +
  右侧动作钮 + `hintline` 导入语；台账表 = 2px 描边盒（`reg-head` / `reg-row` / `reg-l1` /
  `reg-l2`）；核对清单 = 描边盒两列网格（缺项写「未探测到」，不假装通过）；
  指标页 = `chart` 盒 + `plot` 链节 + 9 站点列（标签 / 12px 灯 / 10px track 横条 / 数值），
  首过率缺数据时整条改用一句话说明而不画 0（`frontend-design.md` §7）；
  手机访问页 = 恒白底 `qrbox`（后端渲染，决策 167）+ 地址块 + 复制钮，仅回环绑定时改用 `gate`
  指引块（`--host 0.0.0.0` / `AGENTPIPELINE_LAN=1`）；伪阶段行 = 左缘 4px 亮度阶 + 「（伪阶段）」
  后缀（不用分支色相，决策 84）。

### 6. 移动版转写（theme-6-pixel.md §5）

沿用 480px 单断点与 `matchMedia` 切换（桌面临界不换 DOM），落实五条转写：

1. **传送带竖转**：站点脊线 = 6px 纵向链节，三态与桌面同色（未点亮 pane / 已通过 belt-lit /
   急停琥珀半透明）；站头 12px 信号灯压在脊线上。
2. **道具栏横滚**：槽位 34px 不缩，放不下横向滚动；筛选时空站收拢但脊线保持连续。
3. **pending 动作坞**：对话框内容（含工头头像）留在正文流，恢复动作下沉为固定底部动作坞
   （琥珀顶框 + ▼），异步按钮点击即禁用。
4. **小人随站**：挥锤小人挂站头；详情页只在当前站出现。
5. **页面导航进顶栏**：`.pagenav` 横向滚动行与顶栏同 sticky（顶栏长到约 138px）；
   连带定值：站点带 `scroll-margin-top` 96 → 148px、完成横幅 `top` 104 → 148px，
   否则横幅被顶栏压住。

台账页移动款三处差异：台账行折成纵向（动作钮另起一行均分）；指标 9 站 `plot` 横向滚动、
站点不缩不折；手机访问二维码与地址纵向堆叠、地址项 44px 触控行。

### 7. 动画预算与降级

全站动画只有四处：运行中链节步进、对话框 ▼ 光标闪烁、流式输出方块光标闪烁、列头小人挥锤 /
摆臂。帧切换一律离散（`steps()` 或 opacity 翻转），**禁止 ease / cubic-bezier 缓动与淡入滑入**；
任务完成横幅无入场动画。`prefers-reduced-motion: reduce` 下全部静止。新增动画位需回
theme-6-pixel.md 修订。

### 8. 字体自托管（选型 D）

- 把 Fusion Pixel 12px Monospaced 的 latin 与 zh_hans 两份 CSS 及其引用的 **78 个 woff2 子集**
  入库到前端静态资产目录，随 `vite build` 进入 `dist`，进而被编译期内嵌进单二进制（决策 155），
  同源托管（无需放行任何 origin，决策 167）。
- `index.html` 移除 Google Fonts 的 Fira Code 预连接与样式表；保留 `data-theme` 防闪回脚本与
  `color-scheme` meta（深色 `dark` / 浅色 `light`）。
- `font-display` 用 `block`（字体随二进制本地加载，毫秒级），避免首帧闪回退字体——
  像素身份不能靠「先系统 monospace 再换」实现。
- 随附许可文本（字体为 `MIT AND OFL-1.1`）并在 README 或资产目录注明来源与版本。
- 字体栈回退仍保留系统 monospace，纯防御性。

### 9. 既有 e2e 断言的更新（必须显式改，不得静默）

主题三把状态编码进**文字字面量**，因此有若干 e2e 断言直接断言终端字形。像素主题下这些断言
必须改成断言同一**行为**的新表达（而不是删掉断言）：

| 位置 | 现断言 | 像素主题下的改法 |
|---|---|---|
| `pending-resume.spec.ts` / `happy-path.spec.ts` / `concurrent.spec.ts` | `.pending-count .c` 文本匹配 `/\*1/`、`/\*2/`、`/\*0/` | 计数徽章的文本形态（数字 + 待处理语义），`*` 字面量不再要求 |
| `concurrent.spec.ts` | `.head-label` 文本等于 `['[dev]','[test]']` | 分支徽章的分支身份（蓝 / 紫徽章 + 文字双编码），断言语义而非方括号 |
| `happy-path.spec.ts` / `logs-reload.spec.ts` | 页签文本 `[Diff]`、`[命令与输出 0]`、`[时间线]` 等 | 工位标签盒的可访问名（去掉方括号后的标签文本） |
| `pending-resume.spec.ts` | `.dtag` 计算色 `rgb(255, 180, 84)` | 琥珀仍须是全站唯一告警色：改为断言**像素主题的琥珀 token 值**（深色 `#FFB545`），保持「pending 面板是琥珀」这条行为断言不丢 |

其余断言（`.card` / `.dossier` / `.msg` / `.reason` / `.fileview .list` / 中文文案 /
`getByRole('button', {name})`）是结构与语义级，预期不需要改；跑一遍确认。

## Testing Decisions

**什么算好测试：** 只测外部行为——浏览器实际渲染出的**计算样式、可见图元、可访问名**，
不测 class 名、不测内部结构、不测 CSS 源码措辞。视觉改造的「外部行为」就是用户看到的东西，
所以断言落在 token 的实际取值与图元的实际存在上。反例（不做）：断言某个组件用了某个变量、
断言 style 块包含某段字符串。

**测哪些模块 + 用什么层（复用现有两层，不新建测试层）：**

1. **主题契约模块（vitest 单测，新文件）**——纯数据断言，最快的失败面：
   几何常量与 `theme-6-pixel.md` §2.3 逐项一致；15 枚 sprite 全部有 viewBox 与非空 rect；
   状态映射覆盖 running / pending / failed / done / queued / waiting；深浅两套色彩 token
   覆盖同一组 token 名。
2. **`app.css` ↔ 契约一致性（vitest 解析测试，新文件）**——读 `app.css`，抽出 `:root` 与
   `html[data-theme='light']` 两个块，逐 token 比对契约中的值；同时扫描全部组件 style 块，
   **禁止 token 块之外出现裸十六进制颜色**（像素纪律的可机器检查形式）。
   这条是防漂移护栏：它不替代第 3 条，只让「改了一边忘了另一边」在毫秒级变红。
3. **组件渲染（vitest + DOM，扩展现有组件测试）**——货箱渲染出 16 段量表与正确点亮段数；
   boss 条 20 段且最后一次尝试整条转红；列头小人按状态取到 run / wait / idle 节奏；
   sprite 组件按名字渲染出非空 SVG 且用 `currentColor`。
4. **真实应用渲染（playwright，扩展既有 spec + 新增像素主题 spec）**——在既有 harness
   （真后端 + 同源内嵌产物 + 临时 home，决策 151/155/166）上断言：
   `--bg` / `--pending` / `--text-hi` 的计算值符合像素 token；货箱有 2px 描边与
   `4px 4px 0` 硬投影；圆角为 0；页签激活态是实底 + 上浮描边；完成横幅出现并可「收下」关闭；
   深色与浅色两套都断言同一组关键 token（验证 `data-theme` 切换真的换了 token）；
   并断言全站无未捕获页面错误（延续票 01 的做法）。
5. **真应用截图（人审，非闸门）**——扩展 `.scratch/shots/` 的截图脚本到**真应用**：
   用 playwright 驱动既有 harness，覆盖 7 个路由 × 深浅（另加移动款关键视图），
   产出可重新生成的截图供评审对照原型。**不做字节级 golden 回放**（像素字体跨机渲染差异
   会引入 flaky 门），截图是证据不是门。

**先例（prior art）：**
- 计算样式断言：`frontend/e2e/pending-resume.spec.ts:70` 已用 `toHaveCSS('color', …)` 断言琥珀。
- 组件 DOM 断言：`components/board/PendingActions.test.ts`、`StalledBadge.test.ts`、
  `components/task/DiffReviewPanel.test.ts`。
- 纯数据/归约单测：`src/lib/*.test.ts`、`src/realtime/reduce.test.ts`。
- 参照物的机器校验先例：`scripts/derive-light.mjs` 的「每处替换必须命中」与
  `scripts/e2e-artifacts.sh` 的两层新鲜度守卫（决策 166）。

**回归基线：** 现为 vitest 96 passed / playwright 17 passed / `svelte-check` 0 error 0 warning
（决策 166）。改造后**所有既有 spec 必须全绿**，用例数只增不减；闸门仍为 `make check`
（lint + test + frontend + e2e，决策 168）。

## Out of Scope

- **交互与信息架构改动**：路由、五页签、列语义、`allowed_actions` 纯渲染、pending dossier 的
  持久面板形态、异步按钮、卡片禁拖、顶栏待办计数入口——全部照旧（决策 69/79/84/92/101/105/107）。
- **后端与 API 改动**：本 effort 是纯前端视觉替换；`/server-info` 与二维码继续由后端渲染
  （决策 167），像素主题不改任何端点。
- **新 sprite 与新动画位**：图元只允许来自受控 sprite 表，动画预算只有四处；新增一律回
  theme-6-pixel.md 修订后再实现。
- **新增响应式断点**：仍是 480px 单断点（补齐原型已有的移动款视图，不做平板/中间断点）。
- **自建字体子集或字体改造**：用现成的 78 子集，不裁剪、不重建、不换字族。
- **第三套配色**：只有深色「夜班靛」与浅色「掌机背光」两套。
- **v2 候选**：PWA、令牌鉴权、真机移动手势等既有 v2 项（决策 167 已登记）。
