# 11: 装前预览与信任标记

**What to build:** 安装前列出 ① 该技能会被推荐到哪些 Stage / Node；② 注入模式与信任态；
③ 正文中是否出现 `run_command`、网络调用、密钥路径字样。新装技能默认 `trusted: false`，
**不得**以全文模式注入；用户显式确认后转为已信任。

第 ③ 项是「市场准入自带可见性」的落点：摘要校验只能证明「没被改过」，证明不了「内容是善意的」。

**Blocked by:** 05（二档注入与技能字段形态——信任态是字段的一部分）、09（技能导入——预览发生在导入前）

**Status:** ready-for-agent

- [ ] 预览端点/界面返回三项内容：推荐去向（Stage / Node）、注入模式与信任态、正文特征扫描结果
- [ ] 特征扫描：检出 `run_command`、网络调用（curl/wget/HTTP URL）、密钥路径（`.env` / `.ssh` /
      `*.pem` / `credentials` 等）字样并**列出命中行**（不是布尔「有风险」）
- [ ] 新装技能默认 `trusted: false`，且**保存为全文模式被拒**（票 05 的约束在此有 UI 入口）
- [ ] 显式「信任此技能」操作可把信任态转为已信任，转换是**显式动作**而非默认
- [ ] 未信任技能仍可用于名字态（正文只由 `Skill` 工具按需拉取）
- [ ] 契约用例：预览返回三项 / 特征命中列出具体行 / 未信任 + 全文被拒 / 信任转换生效

**Notes（实现提示）:**
- **明确不做**：用正则拦正文的静态安全扫描（拒绝安装）。既拦不住变形又会误伤合法技能，风险由
  预览 + 信任标记 + 工具层出口控制（票 12）承担。特征扫描**只用于告知**，不做准入判定。
- 上游兼容性事实可作为界面提示的素材，但不要在预览里硬编码：27 个技能中 14 个带
  `disable-model-invocation`、7 个正文提到 `Skill tool`、6 个以子代理为前提。
