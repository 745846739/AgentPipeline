# v2 技能运行时与技能市场（agentpipeline-v2-skills）

**Status:** done

来源：2026-09-14 用户诉求「给架构设计阶段配置一个 grill-me 和 to-spec 的 skill」（决策 170）
经 20 轮拷问后暴露的真实目标——不是配两个技能，而是**把 Agent Skills 生态整体接进来用**。
规格见 [spec.md](spec.md)。

## 范围一句话

技能从「内嵌的两个流水线原生改写版」升级为**可安装、可推荐的生态**：新增 `Skill` 工具 +
只读子代理 + 渐进披露使上游技能**无需改写即可运行**；配本地导入与远程 registry 的技能市场；
设置页按阶段推荐并一键安装。内嵌技能整体退场。

## 已确认的六个选型

| # | 决策 |
|---|---|
| A | **不内嵌**——`EMBEDDED_SKILLS` 与内嵌改写版整体移除，推荐默认由配置界面承载；同时解掉上游内容的再分发授权问题 |
| B | **不要求适配**——加载器不检查正文语义、不因内容拒绝任何合法 markdown |
| C | **补齐运行时**——`Skill` 工具（同名使 `Call the Skill tool` 直接可执行）+ 只读子代理 + 渐进披露 + 兄弟文件一级展开 |
| D | **二档注入 + 信任标记**——全文 / 仅名字可配；`disable-model-invocation` 默认不自动注入；未信任技能不得全文注入 |
| E | **市场与出口控制同批**——装前预览 + `sha256` + 来源白名单；`run_command` 加工具层网络策略，残余风险显式记账（不做 OS 沙箱） |
| F | **会话续接参数化**——pending → resume 是否续接上一轮对话由参数决定，默认关 |

## 为什么这件事比它看起来大

原始诉求是「配两个技能」，但让它真正可用的前提横跨三个子系统，这是拷问过程中被逐条逼出来的：

- **上游技能在本系统里跑不起来**——7 个技能的正文写着 `Call the Skill tool with "..."`（本系统无
  Skill 工具）；6 个以子代理为前提（决策 154 曾是「v1 无实现」）；兄弟文件（`tdd/tests.md`、
  `prototype/UI.md` 等）既不进 prompt、agent 也读不到（`FileToolPolicy` 只放行 worktree +
  任务目录）——这些引用是双向死指针。
- **正文全量注入不可扩展**——技能正文每轮常驻 system prompt，27 个技能约 128KB，单是
  `wayfinder` 就 11.9KB；且 `prompt_template_hash` 对正文敏感（决策 137），改技能即失效 prompt cache。
- **市场 = 不可信输入**——`run_command` 无沙箱、shell 不受限（决策 19 修订 / 104 有意接受），
  而四家主流 agent（Claude Code / Codex / Cursor / Copilot）都靠网络出口控制兜底，本仓
  **零出口控制**。故选型 E 把出口控制与市场绑在同批。

## 关键约束

- **技能名是唯一身份**，`只增不减`不变量（有效集 = 基线 ∪ 阶段 ∪ 节点）保持不变；卸载仍被引用的
  技能必须 fail fast，不得静默降级为工具型技能。
- **契约迁移**：现存 50 处按名字钉住 `grilling` / `to-spec` 的断言须改为对**真实的用户目录技能**
  断言（临时 home 写入 `skills/{name}/SKILL.md`），保留原断言意图。
- **续接开关默认关**，且必须连带三项：`context_overflow` 退出路径补写会话行、token 双算防护、
  压缩锚点修正。这三条是「让 2 正确」的必要条件，不是加固项。
- **接缝只新增一条**（市场客户端 trait）；技能目录隔离复用 `AGENTPIPELINE_HOME`，技能拉取复用
  `LlmClient` / FakeAgent，超时复用 `Clock`。
- 与决策冲突时必须显式标注决策编号（AGENTS.md）。本批权威裁决为**决策 172**，修订 170 / 154 / 47。
- 质量闸门：`cargo fmt --check`、`clippy --workspace --all-targets -- -D warnings`、
  `cargo test --workspace`；涉及前端加跑 vitest / svelte-check / build。

当前可用面：**技能来自用户目录、PATH 工具或远程 registry**（后者需在 `[market] allowed_sources`
显式放行来源），可在**阶段级与节点级**声明为全文态或名字态（设置页为结构化控件），未受信任的
技能不得全文注入；模型能经目录发现并通过 `Skill` 工具按需拉取正文（含一级兄弟文件展开），
也能派**只读子代理**分担检索。安装前有**三项预览**（推荐去向 / 注入模式与信任态 / 正文特征
逐行命中），市场侧还有 `sha256` + 来源白名单；`run_command` 加了一道**工具层出口策略**
（默认只放行回环，**不是安全边界**，残余风险见 `operations.md` §12.15）。会话续接是
**默认关闭**的阶段 / 节点级开关。
