**上一轮:** [talk-mobile-space](../talk-mobile-space/README.md)（决策 218 / 220，已收口）——那一轮把版面内能省的省完了：值班板整块不渲染、过程/回执/思考默认收起、hint 行空闲高度 0、页头收成一行、dvh。本轮动的是**版面之外**的两层：浏览器壳与输入坞。

## 一、现状的账（2026-09-25 评估，iPhone 390×844 浏览器内打开）

```
对话区 ≈ 屏高
  − 底部堆叠约 100px（状态条 42 + 页签栏 58，决策 243，全站共享）
  − 页头带子 46px（决策 218④：44px 触控行 + 2px 下框，已压到触控底线）
  − 输入坞约 85px（textarea rows=2 固定）+ 名牌悬出净空 40px（决策 218④）
  − 急停摘要条（有急停时约 70px，钉住是「急停不滚出视野」不变式，不动）
```

版面内已无可省项（每轮 26px 名牌净空 = 悬出 16 + 呼吸 10，恰好；Fullscreen API 在 iPhone Safari 不存在；底部堆叠与页头带子各有裁决压着）。**剩下的大头在两层**：

| 层 | 手段 | 收益 | 性质 |
|---|---|---|---|
| 浏览器壳 | manifest + apple meta → 「添加到主屏幕」standalone 打开，Safari 上下 chrome 整体让位 | **约 +60~90px，全站受益**（看板/详情同享） | 壳层让位，不翻任何版面决策 |
| 浏览器壳 | viewport meta 加 `interactive-widget=resizes-content`：安卓键盘弹出时版面真收缩 | 钉底输入坞不再被键盘压住（iPhone 由 WebKit 自理） | 一行 meta |
| 输入坞 | textarea 1 行起步、随内容自长至封顶（现固定 rows=2，空着也占两行） | 空态/单行 **约 +19px**（88→约 69，1 行行高被发送钮 44px 底线抬住）；长句不再挤在两行小框里滚 | 修 218④ 的坞形状口径 |
| 输入坞 | 名牌悬出净空 40 → **24px**（悬出 14 实测 + 呼吸 10） | **+16px** | 显式修订 218④ 的 40px 常量 |

## 三、Out of Scope（记档，等真实诉求再立票）

- **阅读模式**（读长回话时输入坞收成一条，约 +60~80px）：动的是决策 218④「钉住三样」的口径边缘、属新增交互——用户已裁**暂不立票**，出现真实诉求时单独走拷问。
- **页头带子自动隐藏**（向下滚收起、向上滚出，+46px）：与决策 218④ 正面冲突（页头钉住的理由就是班次动作的 ⋯ 是唯一入口），**拒绝**，理由随票 01 记进决策。
- **底部堆叠**（状态条 + 页签栏）：决策 243 的全站共享件，本叠无权动。
- **桌面款（≥900）**：版面逐像素不变（textarea 自长只落在折行档 ≤899）。
