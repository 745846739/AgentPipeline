## 2. 工头 agent 的实现设计（决策 182）

### 2.1 身份：第 4 个伪 key，不动 `Stage` 枚举

`Stage` 是 kebab-case 序列化的公开契约（DB 列 / SSE 载荷 / 前端联合类型），且
`pipeline/graph.rs` 遍历 `const ALL_STAGES: [Stage; 10]` 建流水线图——加变体要么编译失败
（6 处穷尽 match），要么让它变成流水线的一个阶段去建节点连边。**不动它。**

值此之故，工头按 `project_analysis` 已经走通的路子存在：

| 项 | 值 |
|---|---|
| 配置 key（`stage_configs.stage`，TEXT 主键） | `"foreman"` |
| `agent_type` / SSE 载荷里的身份 | `"foreman"` |
| 人格 | 内嵌一段，可被 `~/.agentpipeline/prompts/` 覆盖（决策 7 同款） |
| 收口方式 | **不用 `submit_metadata`**——模型不再调工具即返回自由文本，形态同只读子代理 |
| 注册点 | 后端 `PSEUDO_STAGE_KEYS`（`crates/app/src/routes/stage_configs.rs:26-33`）+ 前端镜像（`frontend/src/lib/stageConfigs.ts:17-28`） |

**`resolve_provider` 的适配**：它按 `request.stage.as_str()` 读配置，工头借用占位的
`Stage::Init`，另按 `"foreman"` key 单独读配置并把 `provider_id` / `temperature` /
`max_tokens` 从请求的第二级塞进去——与 `executor.rs:1635-1670` 完全同款。因此
**`Stage` 类型一行不改，`stage_configs` 里没有 `"foreman"` 行时也能正常降级**到
任务级覆盖 / 首个 enabled provider。

### 2.2 端点

| 方法 + 路径 | 用途 |
|---|---|
| `GET /foreman/messages` | 读会话（含每轮 token 与工具痕迹摘要、本次会话合计 token） |
| `POST /foreman/messages` | 发一句话；触发一次工头回话（长任务，回复经 SSE 流出） |
| `GET /foreman/stream` | SSE；按 `agent_type == "foreman"` 过滤 |

- **全部任务无关、项目无关**。空 home 可用。
- SSE 复用既有 `SseBus`（同一个全局广播），发 `ConversationDelta` 带
  `task_id = ""` / `branch = ""` / `run_id = 0` / `agent_type = "foreman"`。
  **不新增 `SseEvent` 变体**；既有 `/tasks/{id}/stream` 按 `task_id` 精确匹配，
  空串永不等于真实任务 id，**零干扰**（`project_analysis` 今天就是这么做的）。
- `run_id = 0` 使心跳更新落在 `WHERE id = 0` 上成为**无害空操作**——工头没有 run 行，
  也不需要空闲超时判定（HTTP 请求本身就是活性信号）。

### 2.3 存储：`kanban_foreman_messages` 定稿

`crates/core/src/storage/migrations/0005_foreman_messages.sql` 改为：

```sql
CREATE TABLE IF NOT EXISTS kanban_foreman_messages (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    role              TEXT NOT NULL,              -- user / assistant
    content           TEXT NOT NULL,
    prompt_tokens     INTEGER NOT NULL DEFAULT 0,
    completion_tokens INTEGER NOT NULL DEFAULT 0,
    briefing_json     TEXT,                       -- 该轮注入的夜班态势快照
    traces_json       TEXT,                       -- 该轮的工具调用痕迹（新增，决策 182）
    created_at        TEXT NOT NULL
);
```

- **可以改**：本机 dev 库的 `_sqlx_migrations` 只有 1–4，0005 尚未被任何库应用过，
  不存在 checksum 风险。**定稿后立即 commit**——它现在未被 git 跟踪，而并行会话的
  0006 已提交，这个状态会让新克隆乱序应用。
- **不落 `kanban_node_runs`**：那张表的 CHECK 是「task / project 恰好一个非空」
  （`0004_project_level_runs.sql:47`），工头两者皆无，落不进去。放宽它会让
  `stage_aggregation` 混进无阶段行，代价大于收益。
- **保留期**：接进既有清理作业（`crates/core/src/scheduler/mod.rs:490`，按
  `conversation_retention_days`，默认 30 天）。对讲台不做全仓唯一不设保留期的表。

### 2.4 上下文组装

每轮 = **人格（system）** + **夜班态势快照（每轮重取）** + **历史窗口**。

快照只装「需要有人管的」，不装全量看板：

- 待拍板：任务标题、阶段、节点、**`pending_reason.message` 原文**（不可省略——
  没有它工头只能说枚举名）；
- 在跑：标题、阶段、节点；
- 失败：标题、阶段、失败摘要；
- 项目列表 + 已完成计数。

历史按**既有字符预算口径**（`conversation_max_chars`，默认 200k）裁剪，
不硬编码轮数——与既有会话压缩同一套口径。被裁掉的历史不进 prompt，但**留在库里**。

### 2.5 工具（只有两个，都只读）

| 工具 | 作用 |
|---|---|
| `read_task` | 某任务的详情（状态、阶段、节点、pending 原因、依赖） |
| `read_conversation` | 某任务某次运行/某 stage 的会话回执 |

- 复用 `ToolExecutor`：新增两个分支进 `crates/core/src/agent/tools.rs:285-307` 的分发，
  **白名单在执行点强制**（`ToolExecutor::with_allowed_tools`，同只读子代理的做法），
  不是在工具定义层过滤。
- 轮数上限照 `SUB_AGENT_MAX_ROUNDS`（12）的量级自定一个常量。
- **不给 `read_file` / `list_dir`**：工头的输入是人可以随便打的任意文本，而子代理的
  调用方是流水线自己的代码。边界要窄。

### 2.6 前端改造（`frontend/src/routes/Talk.svelte`）

**版面换成上下分区**：

```
┌─ 页头：对讲台 · 值班中 · 本次会话 N tok ────────────┐
├─ 状态区（钉第一屏，不随时间线滚动）─────────────────┤
│   · 当前急停轮（.turn.warn，含后端下发的恢复动作）  │
│   · 值班板：8 工位灯（桌面右栏 / 窄屏顶部横向灯条） │
├─ 对话区（滚动）───────────────────────────────────┤

│   · 工位回执 rcpt（转述，无框，左缘亮度阶）        │
│   · 流式：.streaming 方块光标（既有动画位）        │
├─ 输入坞（钉底，桌面与移动同位置）──────────────────┤
│   textarea + Enter 发送 / Shift+Enter 换行 + ▶     │
└──────────────────────────────────────────────────┘
```

- 空态不再降级成 dead shell：无任务时值班长照样能对话，并提示可去看板开工
  （见 §4 的待点头项 ①）。
- **值班长的回复不渲染任何按钮**（Q25）。写动作只在状态区的急停轮里。
- `talk-side` 的值班板保持只读，不新增交互。
- 文案与语气按 Q20：冷静、短句、只报事实与建议。

### 2.7 令牌与局域网护栏（切片③）

| 项 | 设计 |
|---|---|
| 生成与存储 | 服务端生成，持久化（重启不失效） |
| 生效条件 | **仅 `AGENTPIPELINE_LAN` / 非回环绑定时生效**；默认本机形态零摩擦 |
| 护的范围 | **所有写请求 + 工头端点**；GET 只读端点（看板、会话、指标、分享页）不护 |
| 读取点 | 新增一处**仅回环可读**的读取端点（供桌面窗口 / 本机浏览器取令牌） |
| 传递 | 二维码 URL 带 `?t=<token>`；前端启动时读取、存 localStorage、从地址栏抹掉，之后作为请求头带上 |
| 重置 | 一个删行端点 + 设置页一颗「重新配对」 |
| 失败表现 | 缺失 / 不匹配 → 403，前端提示「这台设备还没配对」并给出配对入口 |

**必需的前置改动**：`crates/app/src/serve.rs:181-188` 现在用裸 router 起服务，
**处理器拿不到对端地址**。需改为 `into_make_service_with_connect_info::<SocketAddr>()`，
「仅回环」才判定得了。

### 2.8 口径与指标

- 工头的 token **不计入** `GET /metrics` 的 `total_tokens` / `total_calls`。
- 因此 `/metrics` 的口径注释要改成「**流水线执行 + 伪阶段，不含面向人的对话**」——
  今天 project_analysis 的 run 是**计入**全局指标的（`all_runs()` 无 WHERE，
  单测 `total_calls_counts_project_level_pseudo_run` 钉住），「流水线执行」四个字
  与事实已经对不上，这次一并说清。
- 对话成本由对讲台自报「本次会话 N tok」，**可见，只是不混口径**。

## 4. 我推导出来、需要你点头的三处

这三处不是新决策，是上面裁决的**后果**，但都会改动既有行为，故显式列出。

**① 空 home 时的「开工」入口。** Q25(a) 定了写动作只在急停轮渲染，而空 home 没有急停轮，
于是没有按钮。我的处理：空态里保留一个**跳去 `#/` 的导航钮**（现状就有），并明确它
**不是**「后端下发的动作钮」——导航与动作是两类东西，前者不进入 `allowed_actions` 契约。
值班长可以**说**「去看板新建一个」，但按钮由页面固定提供，不由模型决定。

**② 二维码端点要放宽校验。** 它现在把 `url` 参数与一份地址白名单**精确匹配**
（`crates/app/src/routes/server_info.rs:74-90`），带 `?t=` 的 URL 会被 400。需放宽为
「origin 必须落在白名单内，允许追加 query」。**不构成泄露**：该端点不生成也不返回令牌，
调用方得先持有令牌才能构造出带令牌的 URL；它仍然拒绝把二维码渲染成任意外站地址。

**③ 令牌只在非回环绑定时生效。** 默认形态（`127.0.0.1`）不要求令牌，你日常本机使用
零摩擦；只有 `AGENTPIPELINE_LAN=1` 才启用配对。这偏离了「令牌总是生效」的最简读法，
是我为了保住你本机体验做的取舍——如果你更想要「任何时候都一致」，说一声，我改成总是生效。

> 人类开发者改称**值班员**（§1 已同步改写）。落点维持**顶层路由**（与看板并列，非任务详情
> 页签）——任务是「任务无关的对话」在任务详情里无处安放。同时**修订决策 79**：对讲台纳入 v1
> （与决策 50 / 附录 B.2 的 v2 对话 agent 同批的工作由本决策提前落地）。

**这一页是「你和值班长说话」，不是「状态的可视化」。** 三层内容各有归属：

| 层 | 内容 | 出处 | 为什么 |
|---|---|---|---|
| **状态直陈** | 当前急停（含恢复动作）、值班板 8 工位灯 | 后端确定性下发（`allowed_actions`，决策 69/101） | 不经 LLM 转手——§1 原则 2「不能只有人说、没有状态」的落点，也是最硬的信号 |
| **对话** | 值班长的话、你的话 | LLM（快照 + 历史窗口 + 两个只读工具） | 需要解释与追问的地方 |
| **转述** | 工位回执 `rcpt` | `GET /tasks/{id}/conversations` 读数 | 转述不是发言（纪律 3） |

**版面按这三层分区**：上半是第一屏**钉死**的**状态区**（急停轮 + 值班板），下半是**对话
时间线**，输入坞钉底。急停**不随时间线滚动**——一个两小时前挂起的急停滚出视野，是本页
最不能出的错。窄屏下值班板收成顶栏灯条（`crew`），状态区仍在对话之上。

**边界（重要）：值班长只说话，不按按钮。** 写动作（resume / retry / 拍板 / merge / 建任务）
**一律**以急停轮里的后端下发动作钮呈现，必须由你点；**值班长的回复里永远没有按钮**，
它只能给建议文字。理由有二：决策 69/101 的「`allowed_actions` 后端下发、前端从不计算」
是全站唯一的防错误放大接缝，让 LLM 的判断直接接到状态机上等于把它拆了；且两个位置各
渲染一颗同样的钮，会让「哪个是真的」变成你必须思考的问题。

**值班长的工具只有两个，都是只读的**：`read_task`（某任务详情）、`read_conversation`
（某任务某次运行的会话回执）。**不给文件系统读权限**——它的输入是人可以随便打的任意文本，
而流水线自身调用的只读子代理不需要面对这个。

**实现要点（两处非显然的坑，已修）**：

1. **详情必须随待办集合变化重拉，不能只在 `onMount` 拉一次**——`board.init()` 是异步的
   （`App.svelte` 的 `onMount` 发起），本页 `onMount` 时 `board.tasks` 往往还空着；只拉一次
   会让 `details` 永远为空，页面安静退化成「打开任务详情」按钮，**把后端下发的恢复动作整片
   吞掉**（e2e ⑩ 打红即此）。现以实现 `pendingKey` 指纹（id + pending 类型 + 阶段）驱动
   `$effect` 重拉：集合不变不重拉，一变（装载完成 / resume 后翻转 / `pending_updated` 换理由）才重取。
2. **导航 chip 里的 `foreman` 头像必须缩到 16px**——它的契约显示尺寸是 48px（dossier 用），
   塞进 34px 页签盒会撑到 52px，连带移动端顶栏从 **138px 涨到 156px**，压坏 §5 两处
   148px 定值（`scroll-margin-top` 与横幅 `top`）。已用 `.chip .ic svg.sprite{width:16px}`
   收住，**实测顶栏仍为 138px**（e2e ⑩ 与 ⑨ 各有一条断言钉住）。

**设计取向：不造聊天组件，把操作台对话框竖起来排。** 全站视觉权重最高的东西是急停对话框
（§1 原则 3），对讲台直接复用它作为发言单元：**压在框沿上的名牌 tab 就是发言者**，故不再
另加一行 `who`，也不做左右交替的气泡。一列对话 = 一叠对话框，身份由名牌承载而非位置。

| 区块 | 实现 | 纪律 |
|---|---|---|
| 值班长 `turn` | 挂 `.dialog`（复用双线框 + `.dname` 名牌 tab），只改停靠与留白 | 框色收在 `--pane`；值班长**不占** `.warn` |
| 我（值班员）`turn.mine` | 同一 `.dialog`，名牌 `right:6px` + `--t2` | 明暗区分，不引入第二套色或第二套形状 |
| 工位回执 `rcpt` | 左缘 4px `--pane` 亮度阶 + `--panel` 底，**无框** | 回执是**转述不是发言**：行内 sprite + 工位名 + 状态；与命令输出同一手法 |
| 输入口 `typer` | 对话框形（双线框），描边 `--pane`、名牌收 `--t3`；textarea + 实心 `▶` 发送 | 输入口虽有边框但刻意安静；不新增动画位 |
| 值班板 `brows` | 右栏 340px，复用台账盒（`.reg` / `reg-head`）+ 8px 信号灯方块 | 桌面 `sticky`；窄屏收成顶栏下横向灯条 `crew` |
| 急停轮 `.warn` | 唯一挂琥珀的轮次，内联**后端下发**的恢复动作 | 全站唯一的响仍只在这一处 |
| 流式 | 沿用既有方块光标 `.streaming`（▊） | 不新增光标 |
| diff / 产出 | 沿用 `.dfile` / `.dbody` 原语 | 不新造 diff 渲染 |

**四条纪律**（都由「boldness 只花在一处」推出）：

1. **对话是竖排的对话框，不是气泡。** 身份靠名牌，不靠左右位置；故 `turn.mine` 只移动
   名牌并提亮正文，**不换底色、不换圆角、不加箭头**。
2. **全站唯一的响仍只在急停一处。** 待拍板那轮挂 `.warn`（琥珀框 + ▼ + 恢复动作），
   其余轮次一律 `--pane`——**包括值班长的每一句话**。对讲台**不新增第二个响点**，
   也不新增第五个动画位。
3. **回执是转述，不是发言。** 工位自述用左缘亮度阶（`.rcpt`），与值班长所说的话在形状上
   就不同；值班长引用工位结论时，该结论必须标出**来源工位**（像素本身不可考，靠 sprite +
   工位名文字双编码）。
4. **可追溯性不因对话而丢失。** 你说的话、值班长的话、**它当时看到的夜班态势快照**、
   **它调用的工具痕迹**都进审计（`kanban_foreman_messages`）；界面上「谁说的」永远可见
   ——这是本主题对 §1 原则 2 的延续。

**回归门**：`frontend/e2e/talk.spec.ts`（原 4 条 + 新增「空看板也能对话」一条）、
`router.test.ts` 钉住 `#/talk` 与 `#v-talk` 都解析为 `talk`、后端 L3 契约测试钉住
`/foreman/*` 三个端点与空 home 可用、`/metrics` 不因对话变化的断言。
