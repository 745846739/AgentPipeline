# 对讲台：与工头（值班长）对话（agentpipeline-foreman-talk）

**Status:** ready-for-agent

> 来源：用户诉求「结合已实现的像素主题前端，加一个对话界面，可以展示为和工头对话」，

## Problem Statement

看板告诉我**什么状态**，不告诉我**为什么**、也不告诉我**该怎么办**。想知道某个货箱为什么卡住，
得自己在看板、任务详情的页签、会话回执、指标页之间来回拼——而这些信息在夜里只有我一个人读。

更难受的是**对讲台**这个页面。它叫「和工头对话」，但我不能说话，对面也没有人：

- **它是一堵墙。** 没有任务在跑时，页面上只有一句「夜班安静。当前没有在跑的任务，也没有等
  你拍板的事。」外加一个「去看板新建任务」的按钮。
- **输入框是假的。** 它不是输入框，是一段说明文字，写着「自由对话需要一个会说话的工头
  agent——决策 50 / 附录 B.2 把它排在 v2」。
- **每一轮发言都被任务门控。** 没有 pending、没有在跑，就没有任何可说的东西——而这个页面
  存在的意义恰恰是「我想问的时候随时能问」。
- **它其实是「状态的可视化被排成了对话的形状」**，不是对话。

另外，页面与规格里**有两个「工头」**：规格 §1 说工头是人类开发者本人，而页面按用户诉求把
工头摆成对话的另一方。同一个词指两个人，文档与实现各说各话，谁也不能引用。

最后，我确实需要用**手机**跟它说话（局域网扫码那条路已经能用），但那意味着同网段的任何设备
也能调用全部接口——包括触发真实 LLM 花费的写操作。看板时代最坏的情况是别人点了我的 resume，
对话时代的代价是没有上界的花费。

## Solution

把对讲台从「状态的可视化」变成一个**真的能说话、也真的能读台账的值班长**：

1. **一个任务无关的对话 agent。** 你在任何时候打开对讲台都能说话——有任务在跑时它报在跑的
   事，什么都没跑时它也能答你的问题、并引导你开工。它不再依赖任何任务的存在。
2. **它说得准，因为它读的是真台账。** 每一轮它都拿到一份夜班态势快照（待拍板的原因原文、
   在跑、失败），需要深挖时还能自己调用两个只读工具去查某个货箱的详情与工位回执。
3. **它不动手。** 写动作（resume / retry / 拍板 / merge / 建任务）仍然由后端下发、由你按下；
   值班长的回复里**永远不会出现按钮**。它只给建议。
4. **它说的话可追溯。** 你说的话、它的话、它当时看到的那份快照、它调用过的工具，一起进审计。
5. **手机上只有你自己能用。** 非回环绑定时启用配对令牌：看的随便看（看板、会话、指标、分享页
   照旧可分享），**动手和花钱要凭据**。

视觉上不新造任何东西：不造聊天组件（把全站视觉权重最高的操作台对话框竖起来排成一列），
不新增色彩、字体、sprite 或动画位。

## User Stories

1. 作为值班员，我想在没有任何任务在跑的时候也能跟值班长说话，这样它就不会在夜里变成一堵墙。
2. 作为值班员，我想在它开口第一句就说准当前夜班态势，这样我不必先自己描述一遍。
3. 作为值班员，我想问「那个货箱卡哪儿了」并得到具体回答，这样我不必自己翻页签拼信息。
4. 作为值班员，我想让它引用某个工位的原始回执作为结论依据，这样我知道它的话有出处。
5. 作为值班员，我想在它说「建议 resume」时就地看到后端下发的动作钮，这样我不用来回找。
6. 作为值班员，我想让写操作必须由我按下、它自己不能改状态，这样我不必赌它的判断力。
7. 作为值班员，我想看着回复逐字流出来，这样十几秒的空白不会被误当成卡死。
8. 作为值班员，我想在它出错或没配 provider 时看到一条明确的错误轮、说的话不丢，这样我能改
   几个字重发而不是重打一遍。
9. 作为值班员，我想看到本次会话花了多少 token，这样成本可见。
10. 作为值班员，我想事后查得到「谁说的、依据哪份快照、调了哪些工具」，而不是只看到一段文本。
11. 作为值班员，我想在一台全新机器上（没有项目、没有任务）第一次打开就能和它对话并被引导
    去开工，这样首启不是死路。
12. 作为值班员，我想在手机上也能和值班长对话（局域网扫码那条路），这样我不必回到电脑前。
13. 作为值班员，我想让同网段别人的设备不能替我花钱、不能改我的任务，这样局域网不是敞开的。
14. 作为值班员，我想在手机上首次配对之后不用每次重扫，这样安全设计不会因为我嫌麻烦而被绕过。
15. 作为值班员，我想在怀疑令牌泄露时一键重置配对，这样引入令牌才有意义。
16. 作为值班员，我想让看板 / 会话 / 指标这些只读页在局域网里照旧能直接分享，因为那是我本来
    就打算给同事看的信息。
17. 作为值班员，我想让对讲台的视觉与全站一致——不出现第二套聊天组件、不新增色彩与动画位，
    这样它不像一个外挂进来的页面。
18. 作为值班员，我想让急停始终钉在第一屏，不管对话滚多远，因为那是全站唯一该响的信号。
19. 作为值班员，我想让「工位回执」在形状上一眼就与「发言」不同，这样我知道那是转述。
20. 作为值班员，我想让它的话短、不说废话、不寒暄，这样我扫一眼就能拿到信息。
21. 作为值班员，我想让对讲台在窄屏上同样可用：输入坞钉底、状态收成横向灯条。
22. 作为值班员，我想让它只读台账、读不到我的文件系统，因为我可以对它说任何话。
23. 作为值班员，我想让对话不计入流水线指标，这样指标口径不被闲聊污染。
24. 作为值班员，我想让对话记录到期自动清理、跟会话同一个保留口径，这样对讲台不是唯一不设
    保留期的表。
25. 作为值班员，我想让它不主动插话，这样对话流不会被系统事件切碎。
26. 作为值班员，我想让规格里的身份说法与页面一致（工头 = 值班长、我是值班员），这样文档与
    实现能互相引用，不再有两个「工头」。
27. 作为值班员，我想在空看板时从对讲台一键回到看板新建任务，这样开工这条路的入口还在。
28. 作为实现者，我想让工头的身份只占一个配置 key、不新增阶段枚举变体，这样流水线图、阶段聚合
    与前端阶段类型都不用为一个对话角色改动。

## Implementation Decisions

### 身份与 provider 解析

1. **工头不新增阶段枚举变体，而是作为第 4 个配置 key 存在**（key `"foreman"`，
   运行/事件里的身份串 `"foreman"`）。原因：阶段枚举是 kebab-case 序列化的公开契约（落库列、
   SSE 载荷、前端联合类型），且流水线图是遍历「全部阶段」这个定长数组构建的——加一个变体会
   让工头要么被静默漏掉、要么被当成流水线的一个阶段去建节点连边。
2. **provider 解析沿用项目分析伪阶段已经走通的路子**：借用占位阶段让既有解析链跑通，另按
   `"foreman"` key 单独读阶段配置，把 provider / temperature / max_tokens 从请求的第二级传入。
   阶段配置里没有这一行时正常降级到任务级覆盖或首个启用 provider——**不配置也能用**。
3. **注册点**：后端与前端各有一份伪阶段 key 名单（阶段配置的 key 校验用），两处都要加上
   `"foreman"`。
4. **会话循环复用只读子代理的形态**：模型不再调用工具即返回自由文本收口，**不用**
   `submit_metadata`；轮数有上限。人格内嵌一段，可被家目录提示词覆盖（沿用既有的 persona
   覆盖机制）。

### 端点与流式

5. **三个端点，全部任务无关、项目无关**：读会话（含每轮 token 与工具痕迹摘要、本次会话合计
   token）、发一句话（触发一次回话）、订阅流。
6. **流式复用既有 SSE 总线，不新增事件变体**：发既有的对话增量事件，带空 task_id 与
   `agent_type = "foreman"`。既有任务级 SSE 路由按 task id 精确匹配，空串永不等于真实任务 id，
   因此**零干扰**（项目分析今天就是这么做的）。`run_id` 用占位值，其心跳更新成为无害空操作。
7. **工头不需要空闲超时判定**——HTTP 请求本身就是活性信号。

### 存储与口径

8. **新增一张独立表**承载工头会话，列：角色、正文、提示 token、补全 token、该轮注入的态势快照、
   该轮的工具痕迹、创建时间。
9. **不落运行表。** 那张表的归属约束是「任务 / 项目恰好一个非空」，工头两者皆无；放宽它会让
   阶段聚合混进无阶段行，代价大于收益。
10. **工头 token 不计入全局指标。** 同时把全局指标的口径注释改正为「流水线执行 + 伪阶段，
    不含面向人的对话」——项目分析的运行行今天是**计入**全局指标的，原注释「流水线执行」四个字
    与事实已经对不上，这次一并说清。对话成本由对讲台自报「本次会话 N tok」，可见，只是不混口径。
11. **保留期接进既有的会话清理作业**，与既有保留天数同口径。

### 上下文与工具

12. **每轮上下文 = 人格（system）+ 每轮重取的夜班态势快照 + 历史窗口**。历史按既有的字符预算
    口径裁剪（不硬编码轮数），被裁掉的历史不进 prompt 但留在库里。
13. **快照只装「需要有人管的」**：待拍板（**必须带 pending 原因的原文**，否则值班长只能说枚举
    名）、在跑、失败，外加项目列表与已完成计数。不装全量看板，不装运行读数。
14. **工具只有两个，都只读**：查某个任务的详情、查某个任务某次运行的会话回执。
    **白名单在执行点强制，不在工具定义层过滤**（沿用只读子代理已有的做法）。
15. **不给文件系统读权限。** 值班长的输入是人可以随便打的任意文本，而流水线自身调用的只读
    子代理不需要面对这个。

### 执行权

16. **值班长自主调用只读工具；写动作一律由后端下发、由你按下。**
17. **值班长的回复里永远没有按钮。** 写动作只在状态区的急停轮里渲染。两个理由：`allowed_actions`
    由后端下发、前端从不计算，是全站唯一的防错误放大接缝，让 LLM 的判断直接接到状态机上等于
    把它拆了；且同一动作在两个位置各渲染一颗钮，会让「哪个是真的」变成使用者必须思考的问题。

### 前端版面

18. **版面按三层分区**：**状态直陈**（当前急停 + 值班板，钉第一屏、不随时间线滚动）、
    **对话时间线**（值班长的话、你的话）、**转述**（工位回执留在对话里）。输入坞钉底。
    急停不随时间线滚动是硬要求——一个两小时前挂起的急停滚出视野是本页最不能出的错。
19. **视觉零新增**：不造聊天组件，复用操作台对话框作为发言单元（名牌 tab 即发言者，故不做
    左右交替的气泡）；值班长的话与你的话只差名牌停靠与明暗档；回执用左缘亮度阶 + 无框，
    形状上就与发言不同；流式沿用既有的方块光标。
20. **全站唯一的响仍只在急停一处**——**包括值班长的每一句话**，它不占琥珀档。
21. **窄屏**：输入坞与桌面同位置同写法；值班板收成横向灯条，状态区仍在对话之上。
22. **语气**：冷静的值班长——只报事实与建议，不寒暄、短句。理由是「有性格」迟早会演变成
    「有自己的看法」，而那是一个会花钱、会被任意提问的 LLM 最不该有的东西。
23. **失败降级**：LLM 报错 / 未配 provider → 对讲台内一条错误轮，输入口内容**不清空**，不弹窗。
24. **空 home 可用**：无项目无任务时照常对话。空态的「去看板新建任务」是页面固定的**导航钮**，
    **不进入**后端动作契约（导航与动作是两类东西）。
25. **不主动开口**：只有你说话它才回。急停由确定性的急停轮负责，主动播报会让对话流被系统事件
    切碎，也与急停轮重复。

### 局域网与令牌

26. **令牌只在非回环绑定时生效**：默认本机形态零摩擦；局域网模式才启用配对。
27. **护的范围：所有写请求 + 工头端点**；只读的 GET 端点（看板、会话、指标、分享页）不护。
    「看的随便看，动手和花钱要凭据」。
28. **服务端生成、持久化、长期有效，外加一个重置入口**——没有重置口的长期令牌等于没有应对
    泄露的手段，而每次启动重生成会把摩擦高到使用者干脆把令牌关掉。
29. **传递方式**：配对 URL 带令牌 → 前端启动时读取、存本地、从地址栏抹掉 → 之后作为请求头带上。
    二维码本来就是「给手机递一个 URL」，多带一个参数不增加任何操作步骤。
30. **需要在服务端启动方式上做一处前置改动**：当前处理器**拿不到对端地址**（服务用裸路由启动），
    「仅回环可读」的令牌读取端点必须先让服务能取到对端地址。
31. **二维码端点的校验放宽**：从「URL 与地址白名单精确匹配」放宽为「origin 必须落在白名单内，
    允许追加 query」。**不构成泄露**——该端点既不生成也不返回令牌，调用方得先持有令牌才能构造
    出带令牌的 URL；它仍然拒绝把二维码渲染成任意外站地址。

### 落地顺序

32. **三段，每段结束都有可验证的东西**：
    - **① 后端**：表与迁移定稿、工头模块（人格 / 快照组装 / 会话循环）、三个端点、两个只读工具、
      指标口径注释。**验收**：curl 能对话；空 home 能对话；流式可见；指标不因对话变化。
    - **② 前端**：对讲台分区改造、真输入坞、流式接入、空看板可用。**验收**：本机能手动聊通，
      无任务时不再是死墙，值班长的回复里没有按钮。
    - **③ 令牌与局域网护栏**：对端地址接线、配对令牌与重置、写请求与工头端点校验、二维码校验
      放宽。**验收**：本机不要求令牌；模拟局域网客户端缺令牌 403、带令牌通过。
33. **文档同步**（收尾时一次做完，避免半截状态）：新增两条决策（语义裁决 / 实现设计）、在决策 79
    行追加修订标注、视觉规格 §1 与 §3.3 改写、路由映射表与移动表同步、文件头「唯一超出 v1
    元素集」的说明作废、测试设计用例目录、运维文档的局域网态势、README 的无鉴权告警改写、
    词汇表新增「值班长」「值班员」并对旧词「工头」消歧。

## Testing Decisions

**好测试的标准（沿用本仓既有口径）**：只测**外部行为**，不测实现细节。具体到本特性——

- **不测 prompt 的效果**（值班长答得好不好、判断准不准）。那是外部不确定性，无法做回归门，
  prompt 效果回归在本仓属 v2 离线 eval 的范围。只测 **prompt 的组装**：快照里该有的字段在不在、
  历史窗口的裁剪是否按字符预算发生、被裁的历史是否仍在库里。
- **测外部可观测的行为**：端点的形状与状态码、空 home 可用、流式事件真的到达订阅者、
  指标数字不因对话变化、保留期到点后行被清理、缺令牌被拒 / 带令牌通过、界面上「无任务时
  仍能对话」「值班长的回复里没有按钮」「急停在滚动后仍在第一屏」。

**接缝：零新增，全部复用既有接缝（本仓的可测试性接缝是权威表，决策 143）。**

| 接缝 | 生产实现 | 测试实现 | 为什么是它 |
|---|---|---|---|
| LLM 响应流 | 生产适配器 | 既有的假 agent 可脚本化响应流；**工具层全部真实执行** | 工头的话由脚本给出，工具与存储走真实现——本仓既有的替换边界 |
| 家目录 | `~/.agentpipeline/` | 环境变量指向每测试独占的临时目录 | 真库真迁移，保留期与表结构都被覆盖 |
| HTTP | 路由 | 既有的契约测试（路由 + 单次请求） | 端点形状与状态码的最高层接缝 |
| 时钟 | 系统时钟 | 假时钟手动推进 | 保留期清理无法等真实 30 天 |
| 主题契约 | 主题契约模块 + 真实渲染 | 既有的契约断言 + 真实渲染断言 | 前端视觉层不靠人工对照 |

**唯一的一处扩展（不是新接缝）**：测试基建的脚本槽现在有「按（阶段, 节点）」与「按既有伪阶段」
两路，工头既不是阶段、也不是既有伪阶段之一，需要**按伪阶段那一路加一个工头位**。这是既有接缝的
一个槽位，不引入新的替换点。

**逐模块测什么**：

- **存储**：新表的读写与保留期清理（假时钟）；指标函数不因新表变化的断言。
- **快照组装**：字段完整性（待拍板必须带原因原文）、空 home 不报错、历史按字符预算裁剪。
- **会话循环**：轮数上限、模型不再调工具即收口、工具白名单在**执行点**生效（越权工具被拒）。
- **端点（契约测试）**：三个端点的形状、空 home 可用、流式事件到达、缺令牌被拒 / 带令牌通过 /
  回环豁免。
- **前端**：既有 SSE 归约用例 + 对讲台 e2e（**新增「空看板也能对话」一条**——这是本 spec 的
  验收锚点；另外「值班长的回复里没有按钮」与「急停滚动后仍在第一屏」各一条）。

**先例**：端点形状与状态码照既有的 API 契约测试；假 agent 脚本化照既有的伪阶段脚本与
只读子代理脚本；空家目录照既有的「seedless」端到端夹具；前端视觉断言照既有主题契约测试与
对讲台既有的 4 条 e2e。

## Out of Scope

- **值班长主动开口**（你不动它就不说；急停由确定性的急停轮负责）。
- **值班长执行写操作**（它只能建议，按钮由你按）。
- **值班长读文件系统**（只给两个只读台账工具）。
- **多会话 / 会话列表**（一条长会话，即「夜班台账」；没有「新建对话」的概念）。
- **工头 token 计入全局指标**（口径保持为流水线执行 + 伪阶段）。
- **prompt 效果的离线 eval**、**性能与负载**、**非 Chromium 浏览器**（沿用本仓既有边界）。
- **PWA 与移动端全量适配**（本 spec 只做对讲台一页的窄屏可用）。
- **令牌之外的其他鉴权形态**（用户体系、多设备管理、权限分级）。
- **工头的附件 / 多模态输入**。
