# 07: 配对令牌——手机能用，别人不能

**What to build:** 值班员在自己手机上（局域网扫码那条路）配对一次之后，就能像在电脑前一样和
值班长对话；而同一网段里**没有配对过的设备**既不能动手改任务、也不能花他的 key。本机（回环）
使用**零摩擦**——默认形态根本不要求配对。

看的随便看，动手和花钱要凭据：看板、会话、指标、分享页这些只读页在局域网里照旧可以直接分享
（那本来就是打算给同事看的信息）。

**Blocked by:** 01、06（要有工头端点可护；要有来源地址可判）

**Status:** ready-for-agent

- [ ] 令牌**只在非回环绑定时生效**；默认回环形态不要求配对
- [ ] 护的范围：**所有写请求 + 工头端点**；只读 GET 端点不护
- [ ] 服务端生成、持久化、**长期有效**（每次启动重生成会把摩擦高到使用者干脆把令牌关掉）
- [ ] 一处**仅回环可读**的读取端点供本机取令牌；局域网客户端取不到它
- [ ] 配对 URL 带令牌 → 前端启动时读取、存本地、**从地址栏抹掉** → 之后作为请求头带上
      （二维码本来就是「给手机递一个 URL」，多带一个参数不增加任何操作步骤）
- [ ] **一键重置配对**（删行端点 + 界面入口）——没有重置口的长期令牌等于没有应对泄露的手段
- [ ] 二维码端点的校验放宽为「origin 必须落在地址白名单内，**允许追加 query**」，仍拒绝把二维码
      渲染成任意外站地址（该端点既不生成也不返回令牌，不构成泄露）
- [ ] 缺令牌 / 不匹配时前端提示「这台设备还没配对」并给出配对入口
- [ ] 测试：回环豁免 / 缺令牌被拒 / 带令牌通过 / 局域网客户端读不到令牌
