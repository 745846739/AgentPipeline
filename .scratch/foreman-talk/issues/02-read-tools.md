# 02: 值班长会自己翻台账——两个只读工具

**What to build:** 值班员问「那个货箱卡哪儿了」，值班长**自己**调用只读工具查到该任务的详情与
某个工位的会话回执，再给出**有出处**的回答（它会标出结论来自哪个工位）。它调不动任何越权工具。

快照只装「需要有人管的」清单，所以追问具体细节必须靠工具——这正是对讲台相对看板的价值所在。

**Blocked by:** 01（需要有能对话的工头）

**Status:** ready-for-agent

- [ ] 两个只读工具接入既有工具分发：查某个任务详情、查某个任务某次运行的会话回执
- [ ] **白名单在执行点强制**（越权工具被拒），不是在工具定义层过滤——沿用只读子代理已有的做法
- [ ] 工具集里**没有**文件系统读权限（值班长的输入是人可以随便打的任意文本，而流水线自身调用的
      只读子代理不需要面对这个）
- [ ] 会话循环对工具调用轮数有上限，超限报错而不是无限循环
- [ ] 测试：脚本化的假 agent 产出一次工具调用 → 断言**工具真执行**、结果回灌进对话、最终回答
      包含工具返回的事实（本仓既有边界：只替换 LLM 响应流，工具层全部真实执行）
- [ ] 测试：请求一个不在白名单里的工具名 → 断言被拒（而不是被静默忽略）
