# 07: 决策：中间档（480–1240px）的版面怎么折

**叠:** B-决策（一票只回答「怎么定」；本票不动任何代码）

**来源:** R2-05（实测）

**What to build:** 第一轮的采样点只有 1440 与 430，**中间整段没人量过**。实测这一段是坏的：

```
详情页 .detail.split = minmax(0,1fr) 320px，只在 479px 以下折成一列
  w=768 → main 390, pageOverflow 64      w=520 → main 142, pageOverflow 312
  w=480 → main 102, pageOverflow 352
hero 轨道固定 812px，.rail.hero 无 overflow（兄弟 .rail.spine 是裁切的）
  w=768 → heroScrollW 812 vs clientW 390
对讲台 .talk = minmax(0,1fr) 340px，同样只在 479px 以下折
  w=480 → cols "82px 340px"   w=600 → "202px 340px"
```

这一票只回答「怎么定」：中间档在哪个宽度折、折成什么形状、右栏在折之前如何收缩、
hero 轨道是裁切还是可滚、状态行在这一档保留哪些格。

**Blocked by:** None（can start immediately）

**Status:** done（决策落 `docs/decisions.md` 的 **215**）

## 裁决（决策 215 摘要）

| 定什么 | 结论 |
|---|---|
| 详情页 | `≥1100` 现状两栏（右 320）／`820–1099` 两栏（右 **280**）／`<820` **折成一列**（档案盒落到主栏下方，DOM 顺序不变），左栏下限 `minmax(480px, 1fr)`。依据：`820−40−18−280 = 482 ≥ 480` |
| 对讲台 | `≥1100` 现状两栏（右 340）／`900–1099` 两栏（右 **280**）／`<900` **折成一列**（值班板落到对话下方），对话列下限 `minmax(420px, 1fr)`。依据：`900−40−18−280 = 562 ≥ 420` |
| 右栏收缩下限 | **280px**（两处同值）——再缩，档案盒的动作行会折行，「不切页签也能拍板」就不好按了 |
| 折行那一档的形态 | **复用窄屏那套的三条规则**（整页随手指滚 / 急停摘要条钉顶栏下沿 / 输入坞钉底栏上沿），顶栏高度常量按本档重算（这一档仍是桌面款顶栏 78–81px） |
| `hero` 轨道 | **容器内横向滚**（`.rail.hero { overflow-x: auto }`）——轨道是整条流水线的位置图，站点坐标写死在 `lib/pipeline.ts`，裁掉等于「后面的工位不存在」；**滚动只发生在容器里，绝不传给文档**。`.rail.spine` 的裁切语义不变 |
| 状态行 | `≥749` 全格；`480–748` 隐 `等依赖 / 排队 / 已完成` 三格（约 220px）；`480–560` 再隐 token 量表（约 110px，数字逐字保留）；`≤479` 既有移动款一字不动。容器加 `overflow-x: auto` 兜底：**舍格优先、可滚兜底，绝不静默裁切** |
| 不动的 | 移动款（`≤479px`）既有版面、看板列 264px、过滤槽 34px、全部视觉规格（像素风格 / 2px 描边 / 12px 字阶） |
