# 08: 状态行在 480–748px 不再静默裁切

**叠:** A（不动规格；档位取舍与票 07 对齐）

**来源:** R2-10（实测）

**What to build:** 状态行是单行 flex + `white-space:nowrap`，既无 `flex-wrap` 也无 `overflow`，
唯一的适配是 479px 以下隐藏若干格。实测 480–748 之间内容被裁掉且**没有横滚**：

```
w=768 clipped=0
w=700 clipped=48     clockRight=748 > viewport=700
w=600 clipped=148
w=480 clipped=268    clockRight=748 > viewport=480
w=430 clipped=0      ← 移动款变体接管
```

也就是时钟整块、主题钮的一部分在这整段里**静默消失**（组件注释自己记着这个失败模式与
501px 的实测值，但只把下限设在 479、没管中间段）。

**Blocked by:** 07（档位取舍要与中间断点一致，避免两处阈值打架）

**Status:** done

- [x] 480–748 档：状态行内容不越出视口（折行 / 可滚 / 按优先级舍格，按票 07 的裁决）
- [x] 被舍掉的格不能是唯一入口（深浅切换在任一档都必须可达）
- [x] e2e：在 1440 / 1024 / 768 / 700 / 600 / 520 / 480 逐档断言
      `statusline.scrollWidth <= clientWidth`（即无静默裁切）
- [x] e2e：在 500 与 600 宽按得到深浅切换，断言主题真的变了

**边界.** 不要动 479px 以下既有的移动款变体行为。

## 实施记录（2026-09-18）

**落点**：`src/components/layout/StatusLine.svelte` 的样式块尾部，两条新断点（阈值与决策 215 的档位表一致）：

| 档 | 动作 | 依据 |
|---|---|---|
| `≤748px` | 隐 `.dep`（等依赖 / 排队 / 已完成 三格，约 220px） | 这三个数在看板列头与过滤槽上都有同一个值，**不是唯一入口**；容器同时加 `overflow-x: auto` + 隐藏滚动条兜底 |
| `≤560px` | 再隐 token 量表（`.tok .gauge`，约 110px） | 数字（`总量 N tok`）逐字保留，只收掉纯视觉量表 |
| `≤479px` | **一字不动**（既有移动款变体接管） | 票面边界 |

**两个决定值得记**：

1. **滚动条不占高**（`scrollbar-width: none`）。`--sbar-h` 是对讲台高度公式里的一项
   （`calc(100vh - 138px - var(--sbar-h))`），状态行若因横滚长出 15px，那笔账会跟着错。
   与 `.slots` / `.navbar` / `.tabs` 的既有手法一致。
2. **时钟不再走裸 `toLocaleTimeString`**：顺手改成 `formatClockAt`（票 15 的单一出处）。

**证据**：`frontend/e2e/ux2-geometry.spec.ts` ②「状态行在 1440→480 逐档不越界，且在
500 / 600 按得到深浅切换」——采样点按决策 215 的边界取（1440 / 1024 / 900 / 820 / 768 /
700 / 600 / 560 / 520 / 500 / 480），逐档断言 `scrollWidth <= clientWidth`。

**评审补的一条断言**：只断言「不越界」是不够的——把时钟 `display:none` 掉同样满足它，
而那**正好是本条要修的症状**（静默消失）。循环里因此多一条：每一档（含 480 / 500 / 520）
`clock` 的盒宽都 `> 0`。

**一处仍未做（不算欠账，记在这里）**：票面的 `w=700` 一档是审计的实测点，
本实现用的是 748 断点（决策 215 的档位），700 落在 `≤748` 档内、行为一致。
