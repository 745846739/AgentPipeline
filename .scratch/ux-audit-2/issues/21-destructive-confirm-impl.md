# 21: 不可逆动作的确认步与三档量级

**叠:** A（不动规格——规格由 [14](14-destructive-confirm.md) / 决策 216 定）

**来源:** R2-09；由 [14](14-destructive-confirm.md)（决策 216）开出

**What to build:** 现在 `合入` / `通过评审` / `打回并附意见` / `强制通过评审` /
`忽略失败依赖，继续执行` / `终止任务` / `重置配对` **全部一次点击直接提交**，而
「强制通过评审」（会跳过质量闸）是实心主按钮、「终止任务」（不可逆）反而是弱化的
`.btn quiet`——量级与后果反着来。

**Blocked by:** 14（判据、形态、文案、键盘行为由它定，实现照抄）

**Status:** open

- [ ] 加一条**纯函数**认档判据（建议落 `lib/actions.ts`，可单测）：
      `actionTier(action)` = `advance` / `gate-skip` / `destructive` / `quiet`，
      其中 `gate-skip` 的判据按决策 216 的写法（`resume` 且（`skip` 或（`continue` 且非
      `requires_input`）））——**不靠标签文字匹配**
- [ ] 三档量级的渲染类落到 `PendingActions` / `DiffReviewPanel` / `ReviewForm`：
      `advance` 实心、`gate-skip` 琥珀描边（`--pending`）、`destructive` 红描边（`--stop`）、
      其余 `.btn.quiet`
- [ ] 内联两步确认：动作行就地换成 `确认…？` + 同一颗钮（保留原词与原量级）+ `取消`；
      四类动作（`合入` / gate-skip / `cancel` / `重置配对`）都接上
- [ ] 后果句按决策 216③ 逐条写死（`{default_branch}` 与 `{n} 台已配对设备` 是运行时读数，
      取不到就不写数）
- [ ] 键盘：确认态不移动焦点、`Escape` 退回普通态、`取消` 不进默认焦点
- [ ] 打回标签随输入变（空 → `打回开发`，非空 → `打回并附意见`），且不进确认步
- [ ] 单测：四个档位的判据（含 `continue` 两支的分叉）；确认步「第一次点不发请求、
      第二次点才发」；`Escape` 退回
- [ ] e2e：点「合入」第一次不出现终态、出现确认句，第二次才提交；`终止任务` 同；
      `强制通过评审` 的按钮不再是实心（样式断言）

**边界.** 不改 `allowed_actions` 动作集（决策 132 移出的动作不复活）；不动现有
`.btn` 的像素纪律（2px 描边 / 12px 字阶）；`重置配对` 的确认句里的设备数从既有读数字段取。
