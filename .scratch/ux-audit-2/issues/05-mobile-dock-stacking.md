# 05: 移动款动作坞给状态行让位

**叠:** A（不动规格）

**来源:** R2-02（实测）

**What to build:** 手机上打开待拍板任务，底部动作坞与状态行都钉在 `bottom:0`，
动作坞不透明且 `z-index` 更高，把状态行**整条压掉**——实测重叠 42px，正好等于状态行高度
（`dock z31 h180` vs `status z30 h42`，`overlapPx:42`）。待处理计数、token 总量、
**深浅色切换**同时不可见也不可点。

同仓已有正确写法可照抄：对讲台的输入坞用 `bottom: var(--sbar-h)` 给状态行让位
（`Talk.svelte:2073-2079`），而 `app.css:629-632` 的注释只承认了对讲台那一处。

**Blocked by:** None（can start immediately）

**Status:** done

- [x] 详情页的 `.dock` 不再与状态行重叠（让位、或把状态行抬到坞之上并保证可见）
- [x] 详情页 `.detail.docked` 的底部内边距随之调整（内容不被坞盖住）
- [x] 手机上任一 route 上状态行都可见可点：**深浅切换必须能按到**
- [x] e2e（430 宽）：断言 `.dock` 与 `footer.statusline` 的矩形**交集为 0**
- [x] e2e：在手机上按一下深浅切换，断言主题真的变了
- [x] 回归：决策 192 / 208 的「急停钉在第一屏」不受影响（对讲台高度公式未被动坏）

**边界.** 不要动档案盒的动作行本身（六个 e2e 文件依赖它的定位）。

## 实施记录（2026-09-18）

**落点**

| 处 | 改动 |
|---|---|
| `src/app.css` | `:root` 里把两个「钉边元素让位」的高度定成变量：`--topbar-h: 78px`（兜底值，真值由顶栏量）、`--sbar-h: 38px`（= `.statusline` 的 36px 高 + 2px 上框） |
| `src/app.css` | `.dock { bottom: 0 }` → `bottom: var(--sbar-h)`（对讲台输入坞早就是这么让位的，这里照抄同一条口径） |
| `src/routes/TaskDetail.svelte` | `.detail.docked` 的底边距改成 `calc(var(--dock-h) + var(--sbar-h) + 14px)`——让位之后内容仍要避开坞与底栏**两层** |

**取舍记一笔**：没有把状态行抬到坞之上（那是「谁盖谁」的另一种解法），而是让坞让位——
理由是与对讲台一致（同一件事只有一种做法），且抬高状态行会让它在坞存在时悬在屏幕中间，
看起来像浮层。

**`--sbar-h` 顺带给了桌面档一个真值**：这一对变量此前**只在 479px 媒体查询里定义**
（`calc(42px + var(--safeb))`），桌面上 `var(--sbar-h)` 是无效值——今天没有桌面规则读它，
但下一个消费者会静默回落到 `auto`。`:root` 里补 38px 把这条路堵上（等于 `.statusline`
的盒高，逐值对齐）。

**证据**：`frontend/e2e/ux2-geometry.spec.ts` ①「手机上动作坞给状态行让位：矩形交集为 0，
深浅切换按得到」——430×932 上量两者矩形（交集必须为 0）、按一次深浅切换并断言主题真的变了。
