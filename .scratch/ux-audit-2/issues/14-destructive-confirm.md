# 14: 决策：不可逆动作的确认、后果与视觉量级

**叠:** B-决策（一票只回答「怎么定」；本票不动任何代码）

**来源:** R2-09（代码）

**What to build:** 不可逆动作全部单击即发，没有确认、没有撤销：

- `合入`（`DiffReviewPanel.svelte:119-129`）——把分支写进项目；
- `通过评审` / `打回并附意见`（`ReviewForm.svelte:94-107`）——推进/退回阶段；
- `强制通过评审` / `忽略失败依赖，继续执行` / `终止任务`（`PendingActions.svelte:49-53`）；
- `重置配对`（`Share.svelte:146-155`）——**让所有已配对手机立刻失效**。

两处加重：① `打回并附意见` 标签承诺意见，但意见框空着也照样提交；② 视觉量级反了——
会跳过质量闸的 `强制通过评审` 是实心主按钮，而不可逆的 `终止任务` 是低调按钮。
全站唯一的确认步是删项目/删 provider 的两步内联确认。

这一票只回答「怎么定」：**哪些动作需要确认步、确认步长什么样、后果陈述写在哪、
默认焦点落在哪、破坏性动作与「跳过质量闸」动作的视觉量级关系**——
以及「打回」是否要求非空意见。

## 裁决（决策 216 摘要）

| 定什么 | 结论 |
|---|---|
| 什么要确认步 | 判据是「这一下之后有没有东西在物理上回不去」的四类：**写进项目仓库**（`合入`）、**跳过质量闸**（`skip` 全体 + 不带自由输入的 `continue`）、**终结任务**（`cancel`）、**让配对设备失效**（`重置配对`） |
| 什么不要 | `continue`（带输入的）/ `goto` / `重试执行` / `重试合并` / `拆分任务` / `更换模型` / `归档` / 删项目与 provider 的既有两步确认——前六类**可再走一遍**（走错花时间不花数据），`归档` 不动仓库 |
| 形态 | **内联两步，不是模态**：动作行就地换成 `确认…？` + 同一颗钮（保留原词与原量级）+ 紧邻 `取消`。沿用删项目那套写法；理由是坞在 430px 是钉底常驻的，模态会把「不切页签就能拍板」变成「先处理一个弹窗」 |
| 后果陈述在哪 | **只在动手那一步**出现，且带运行时的数（`{default_branch}` / `{n} 台已配对的设备`）；常驻处不摆（会撑满坞）。与决策 105「理由只在动手时出现」同源 |
| 键盘 | 确认态**不移动焦点**（再按一次回车即确认）；`Escape` 退回普通态（**新增**，删项目那处没有）；`取消` 不进默认焦点 |
| 打回要不要非空意见 | **不强制**，但**标签随输入变**：空 → `打回开发`，非空 → `打回并附意见`。它**不进确认步**（不跳过闸门） |
| 三档量级 | **推进** = 实心；**跳过质量闸** = 琥珀描边（**不再用实心**，这是量级反了的那一处）；**终结 / 让设备失效** = 红描边。同一动作只有一档；`取消` 仍 `.btn.quiet` |
| `重置配对` | **要确认**（它让所有已配对手机立刻失效），确认句里给设备台数 |
| 与决策 132 | 那条移出的无端点动作（`放弃合入` / `合并任务`）**不复活**；本票只重排**在册动作**的量级与确认步 |

**实现认档不靠标签文字**：`gate-skip` 的判据是 `kind === 'resume' && (action === 'skip' || (action === 'continue' && !requires_input))`。这一点写进了 `design/frontend-design.md` §9.3（票面只记意图，认法落规格）。
