# 14: 决策：不可逆动作的确认、后果与视觉量级

**叠:** B-决策（一票只回答「怎么定」；本票不动任何代码）

**来源:** R2-09（代码）

**What to build:** 不可逆动作全部单击即发，没有确认、没有撤销：

- `合入`（`DiffReviewPanel.svelte:119-129`）——把分支写进项目；
- `通过评审` / `打回并附意见`（`ReviewForm.svelte:94-107`）——推进/退回阶段；
- `强制通过评审` / `忽略失败依赖，继续执行` / `终止任务`（`PendingActions.svelte:49-53`）；
- `重置配对`（`Share.svelte:146-155`）——**让所有已配对手机立刻失效**。

两处加重：① `打回并附意见` 标签承诺意见，但意见框空着也照样提交；② 视觉量级反了——
会跳过质量闸的 `强制通过评审` 是实心主按钮，而不可逆的 `终止任务` 是低调按钮。
全站唯一的确认步是删项目/删 provider 的两步内联确认。

这一票只回答「怎么定」：**哪些动作需要确认步、确认步长什么样、后果陈述写在哪、
默认焦点落在哪、破坏性动作与「跳过质量闸」动作的视觉量级关系**——
以及「打回」是否要求非空意见。

**Blocked by:** None（can start immediately）

**Status:** open

- [ ] 逐个列出需要确认步的动作与**不需要**的动作（避免把日常动作也加上摩擦）
- [ ] 定下确认步的形态：内联两步（照删项目的既有写法）还是模态，以及为什么
- [ ] 定下后果陈述的位置：动手前常驻、动手时出现、还是确认步里
- [ ] 定下默认焦点与键盘行为（Escape 取消、焦点不落在破坏性项上）
- [ ] 定下「打回」是否强制非空意见；若否，改掉标签里的承诺
- [ ] 定下破坏性动作 / 跳过质量闸动作 / 中性动作三者的视觉量级关系
- [ ] 定下「重置配对」是否属于需要确认的一类（它让已配对设备全部失效）
- [ ] 改规格时按惯例追加修订决策并在原文标注
- [ ] 不改任何代码
