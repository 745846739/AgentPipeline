# 界面在「一切正常」之外的第二副面孔

**Status:** done（批内 22 张票全部收口：18 张 done、票 19 superseded（被 talk-mobile-space 票 07 吸收）、票 18/21/22 经用户裁决于 2026-10-01 以 wontfix 关闭）

**Slug:** `ux-audit-2`

**来源:** 2026-09-18 对真应用做的**第二轮** UI/UX 审计。第一轮（`.scratch/ux-audit/`，决策 195–203）
审的是静息态的画面与文案；这一轮专看第一轮没覆盖的四个视角——语义与键盘、失败与断线、
中间档（480–1240px）的版面、不可逆动作与重入。证据、逐条实测数字与截图见 [README.md](README.md)。

## Problem Statement

第一轮的 27 张票把「安静地摆在那里的界面」修得很好，但它看不见**界面被推到边界时**是什么样。
把应用推到失败、推窄、推重复点击，会看到它在正常路径之外几乎只有一副面孔：**装作没事**。

- 打开任务 A，再切到一个不存在的 id：一条红字说「任务不存在」，红字底下**仍然是 A 的完整界面**，
  连 6 颗拍板按钮都在——它们会提交到那个坏 id（实测 `stillShowsOldTitle:true`，`hasActionButtons:6`）。
- 手机上打开一个待拍板任务：底部动作坞（`z-index:31`）把状态行（`z-index:30`）整条压住，
  **重叠 42px = 状态行高度的 100%**——待处理计数与深浅切换同时不可见。
- 点「重试」而请求失败：什么都没发生，没有横幅、没有提示（注入 500 后 `bannerErrors:[]`）。
- 市场里断网点「刷新」：技能列表连同「刷新」和「查看技能」两个钮**一起消失**，
  唯一的出路是整页刷新。这不是「错误没做好看」，是**没有出路的死胡同**。
- 480–1240px 之间没有任何断点：详情页主栏在 480px 只剩 **102px**、对讲台对话列只剩 **82px**，
  hero 轨道固定 812px 从约 830px 起就把整页撑出横向滚动。
- 10/11 条路由没有 `<main>`，看板与 404 没有 `<h1>`，任务详情从 `h1` 直接跳到 `h4`，
  页签不是 `tablist`，全站 `aria-current` 计数为 0，`document.title` 11 条路由完全一样。
- 「待处理」下拉播报自己是 `role="menu"`，但 **Escape 关不掉、方向键不动、点外面也不关**。
- 「合入」「通过评审」「终止任务」「重置配对」全部单击即发：没有确认、没有撤销，
  且会跳过质量闸的「强制通过评审」是实心主按钮，而不可逆的「终止任务」是低调按钮。

一句话：**正常路径上这是一个好界面，异常路径上它不是一个界面。**

## Solution

给界面补上第二副面孔，四件事：

**失败有出口、错误说得出口。** 加载失败清掉上一个任务的残留并给「重新加载」；
所有错误横幅与表单错误进 live region；市场刷新失败保留已列出的内容并提供重试；
设置五页与详情页的错误横幅都有重试钮；重试/归档失败不再静默。

**窄档真的折行。** 详情页与对讲台在 480–1240 之间折成一列（顺带修正 hero 轨道撑破页面），
状态行在 480–748 之间不再静默裁掉时钟，档案盒不再被顶栏盖住铭牌。

**语义补齐。** 全站 `<main>`、看板与 404 的 `<h1>`、详情标题层级不断级、页签是 `tablist`、
当前项带 `aria-current`、页签/选择态带 `aria-selected`/`aria-pressed`、每页有自己的 `document.title`。

**不可逆动作有刹车。** 拆分/换模型进提交中态（杜绝双击重复）；`base_url` 形状校验；
不可逆动作在动手时给出后果并需要一个确认步，破坏性动作的视觉权重不再低于跳过质量闸的动作。

## User Stories

1. 作为在看板上点到一条已删除任务的人，我希望看到一条能回去的路，而不是上一个任务
   连着它的拍板按钮一起留在屏上——我差点对一个坏 id 点了「合入」
2. 作为手机上看待办的人，我希望底部状态行（计数与深浅切换）没被动作坞盖住，这样我换得了主题
3. 作为网络慢的人，我希望点了「确认拆分」之后按钮就锁上，这样我不会把子任务建两套、原任务被取消两次
4. 作为用键盘的人，我希望打开「待处理」之后能按 Escape 关掉、能用方向键走、点外面能关
5. 作为用小屏笔电的人，我希望任务详情在 480–1240 之间正常折成一列，而不是主栏只剩 100px
6. 作为用平板看对讲台的人，我希望对话列不会被右栏挤成一条
7. 作为把窗口拖到 1000px 的人，我希望任务详情的 hero 轨道不把整页撑出横向滚动条
8. 作为用读屏的人，我希望错误出现时我能听到（而不是只有红颜色）
9. 作为市场里断网的人，我希望刷新失败后已经读到的技能还在、并且我还能再试一次
10. 作为设置页加载失败的人，我希望页面上有一颗「重试」，而不是只能整页刷新
11. 作为点「重试」失败的人，我希望被告知失败了，而不是按钮静静复活
12. 作为把窗口缩到 600px 的人，我希望状态行里的时钟不是被静默裁掉
13. 作为滚动待拍板任务的人，我希望「等你拍板」铭牌不被顶栏盖住
14. 作为在项目 B 里新建任务的人，我希望创建后跳到**我刚才建的那个**任务
15. 作为填 provider 的人，我希望 `base_url` 填错时当场被拦下，而不是任务跑模型时才炸
16. 作为拆分任务的人，我希望空标题的行被拦下，而不是造出一个没名字的子任务
17. 作为用键盘或读屏在详情页切页签的人，我希望它被当作页签播报，并且当前页签是「选中」的
18. 作为在标签页之间切的人，我希望每个页面的标题不同，这样我分得清哪个是哪个
19. 作为要把分支合入的人，我希望「合入」动手时告诉我它会做什么，并且需要一次确认
20. 作为要终止一个任务的人，我希望这个不可逆动作不要看起来比「强制通过评审」更轻
21. 作为点「打回并附意见」但没写意见的人，我希望它要么拦住我，要么别在标签上承诺意见
22. 作为把手机配对重置的人，我希望知道所有已配对设备都会失效，并且需要确认
23. 作为点了「安装」而请求悬挂的人，我希望有超时与取消，而不是永久转圈
24. 作为开着任务详情页而服务器重启的人，我希望页面告诉我实时流断了，而不是静静停止更新
25. 作为展开一条命令输出的人，我希望加载失败时看到失败，而不是永远「正在加载完整输出…」
26. 作为同时装两个技能的人，我希望两行各自有自己的进行中状态
27. 作为用非中文浏览器 locale 的人，我希望时间格式在全站一致
28. 作为读手机访问页的人，我希望同一个「绑定来源」在两处叫同一个名字
29. 作为读对讲台配对提示的人，我希望看到加粗的文字，而不是字面的 `**`
30. 作为用读屏的人，我希望按钮的名字里没有 `▶` 这种装饰
31. 作为用触屏的人，我希望顶部过滤槽与待处理芯片有够大的点按面积
32. 作为要刷新页面的人，我希望详情页签、看板过滤、对讲台草稿不会丢，并且能从 URL 恢复
33. 作为要分享一个视图的人，我希望 URL 能表达「我正在看哪个页签 / 哪次班次」
34. 作为读一条长路径的人，我希望截断的路径能看全（悬停或复制），而不是只剩省略号
35. 作为要确认这批发现做完了的人，我希望每条都有票与验收点，并且证据可复现

## Implementation Decisions

**分两叠，与第一轮同规矩**

- **A 叠（不动规格的纯实现修正）**：一发现一票，互不阻塞。
- **B 叠（要动规格）**：先出一张决策票（只回答「怎么定」），定了再出实现票；
  与规格文本冲突处按修订决策追加记录，原文处标注，不静默改。
  本轮的 B 叠三项都是**版面/交互形态的定义**，不是修 bug：中间档断点、不可逆动作的确认语义、
  中流状态的持久与深链。

**失败的形状（R2-01 / 06 / 07 / 08）**

- 详情页 `load()` 的 `catch` 必须清掉上一个任务（`task`、`cursors`、`allowedActions`、
  `transitions`、`conversations`、`commands`），否则 `{#if task}` 会短路掉加载/空分支。
- 错误横幅进 live region 用 `role="alert"`（加载/提交失败是**打断级**，不是 `polite`）；
  表单错误同时要给字段 `aria-invalid` 与 `aria-describedby`。
- 「重试」出口的口径：加载类失败给「重新加载」，动作类失败保留用户已填内容。
- 市场刷新失败**保留 `list`**：把 `listError` 分支挪到 `list` 之后，或让错误态自带重试钮。

**窄档（R2-05 / 10 / 11）**

- 详情 `.detail.split` 与对讲台 `.talk` 都要在 480–1240 之间有一个中间断点（具体阈值属 B 叠决策）。
- `.rail.hero` 要么按容器裁切、要么可横向滚——**不能把滚动条传给整个文档**；
  参考兄弟 `.rail.spine` 已裁切的写法。
- 状态行的适配不能只在 479px 以下：中间档要么折行、要么可滚、要么先舍掉次要格。
- 档案盒 `top` 别再用魔数 56：顶栏实测 78–81px（应用别处已记着这个值），
  取真实高度（CSS 变量或 `--sbar-h` 同类做法）。

**重入与校验（R2-03 / 13）**

- `submitSplit` / `submitModelOverride` 与 `runAllowedAction` 一样设 `busyKey`，
  成功后等回执、带 safety timeout；对话框的 `submitting` 才真正生效。
- `base_url` 非空时校验形状（协议 + 主机），前端拦下并给字段级错误；后端是否补校验另议。
- 拆分行：标题为空的行拦下并指到第几行；文本域全空时给提示，不做静默 no-op
  （现有单测 `SplitDialog.test.ts:41-51` 把 no-op 钉住了，那一条要跟着改）。

**语义（R2-19 / 20）**

- 每个路由一个 `<main>`；看板与 404 补 `<h1>`（视觉上可以仍靠列头/文案，但语义要有）。
- 详情页签改 `role="tablist"` + `role="tab"` + `aria-selected` + `aria-controls`，
  面板 `role="tabpanel"`；方向键切换。
- 全站去 `▶` 进可访问名（`content` 装饰要么 `aria-hidden` 化、要么从 `::before` 移出）。
- `document.title` 每路由一个（含任务标题）。
- 顶栏当前项 `aria-current="page"`。

**不可逆动作（R2-09，B 叠）**

- 要定的是：哪些动作需要确认步、确认步的形态（内联两步 / 模态）、
  后果陈述写在哪、默认焦点落在哪、破坏性动作与「跳过质量闸」动作的视觉量级关系。

**中流状态（R2-21，B 叠）**

- 要定的是：哪些状态进 URL（页签 / 过滤 / 班次）、哪些进 localStorage（草稿）、
  以及刷新后的恢复语义。

## Testing Decisions

**好测试的判据**（沿用第一轮）：只测外部行为——断言落在「用户看到/点到什么」与
「计算样式/几何是什么」上，不落在 class 名、组件内部状态或文件结构上；文案精确匹配只用于
**契约性**字符串（按钮名、状态词），不用于说明性段落。

**复用既有接缝，零条新接缝。** 全部落在既有的两条上：
主题契约模块（决策 169 那条接缝）与前端 E2E harness（真二进制 + 内嵌产物 + 真后端 + 真浏览器）。
本轮不需要为可测试性改任何生产代码。

**哪一层测什么**

- 纯函数层（vitest）：`submitSplit` 的校验、`validateProviderDraft` 的 base_url 形状、
  格式化函数的一致性。
- 端到端层（playwright + 真后端）：这是本轮的主战场——详情失败态清空、失败注入（`page.route`
  造 4xx/5xx）后的可见反馈、断开重连指示、宽度扫描（480/520/768/1024/1240）的几何断言、
  页签的 role/aria、`document.title`、状态行与动作坞的叠放关系。
- **宽度扫描要断言数字**（`main >= 320`、`pageOverflow === 0`、`overlap === 0`），
  不靠截图肉眼；照 `pixel-theme.spec.ts` 与 `board-overflow.spec.ts` 的既有姿态写。

**本轮取证 spec 可直接改成门**：`frontend/e2e/ux-audit-2.spec.ts` 目前默认 skip
（`UX_AUDIT2=1` 才跑），它的 `①.1`（语义枚举）、`①.4`/`①.7`（宽度扫描）、`①.8`（状态行裁剪）
已经把断言所需的值都量出来了——实现票把它们**收窄成断言**即可进 `make check-e2e`。

**要留意的脆弱点**

- 档案盒的动作行被六个 e2e 文件里的多处定位依赖着（第一轮就记过）——改 `PendingDossier`
  的 sticky/坞时不要动动作行本身。
- 窄档断点会同时影响详情与对讲台两页，改 `.talk` 的高度公式时要留神
  决策 192 / 208 的「急停钉在第一屏」保证（别让页面能滚）。

## Out of Scope

- **桌面壳（Tauri / dmg）与手机端真实浏览器**的实测（本轮 harness 只有 Chromium 桌面内核）。
- **真实 provider 下的长任务体验**（harness 全是 mock LLM；token/耗时曲线不代表真实）。
- 视觉主题本身：像素风格、2px 描边、12px 字阶、264px 列宽都**不动**。
- 车间隐喻体系（只做一致性，不推翻）。
- 第一轮已交付并复核成立的部分（对比度门、设置信息架构、模态框键盘、空态语汇）——
  本轮不重开。
- 200% 缩放、多 DPR、`prefers-color-scheme` 跟随的实测（本轮按视口减半推算，未跑）。
- `docs/backlog-v2.md` 的 v2 预留项。
