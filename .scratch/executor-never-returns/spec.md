# 执行体不再无声卡死（executor-never-returns）

**Status:** done（12 张票全部落地，决策 302–311）

> **来源**：用户诉求「分析对讲台最近一次对话，为什么执行了这么久还没有解决问题」。实测底稿 =

## Problem Statement

我在对讲台说「协助任务 01M3BGVCX… 完成」，它跑了 **2 小时 26 分、95 轮、43.4 万生成 token**，
最后我按停，它回我一句「它还没说出什么，没有部分结论可留」——**一条结论、一条提议都没有**。

而真相是：那条任务**从头到尾就没动过**。执行体在 03:30:01 启动后卡死在一次文件读取里
（同步 `open()` 阻塞 4 小时+，4 个 tokio worker 占死 1 个），看门狗把 run 判了 timeout 却
**没释放执行权**，于是 03:49 我按续跑时，乐观锁 `WHERE executor_owner IS NULL` 永远为假，
重试 30 秒后打出一行 warn 就**永久放弃**。此后 2 小时 27 分钟，流水线日志里一行调度活动都没有。

更难受的是：**系统其实早就知道**。03:35 的超时在 03:49:02 就落成了 `run_failed` 和
`scheduler_no_effect` 两条待办——但 03:49:58 我这一轮开跑后，值守轮按决策 289 **排队**，
那两条待办就挂在那里 2 小时 26 分没人消费，我**一条提醒都没收到**。

这不是第一次：日志里「resume 触发被在跑的 executor 持续挡下」出现过 **4 次**（09-19、09-26×2、
09-27）。我重启过很多次，**还是会再出**。已查明的触发是**重建**不是重启——应用未签名
（`codesign` 报 `not signed at all`），TCC 授权按 CDHash 归属，**每次重建换身份 → 授权失效 →
重新弹窗 → 没人应答 → `open()` 无限阻塞**。

## Solution

四层，缺一层都还会复发：

1. **不再占死运行线程**：一次节点请求的文件读取全部挪进阻塞池——环境再卡，应用整体不再"看着活着其实降级"。
2. **执行权不再依赖 future 返回**：看门狗判 run 终态的**同一处**就清 `executor_owner`——任务再也不可能因为"执行权没释放"而永久停住，**哪怕 future 永远不返回**。
3. **挡住了要有人知道**：`resume` 被挡满预算放弃时落一条**专属类别**的待办；「卡住」的判据补上第三类，认得出这次这个形态（游标 `pending` + run 已终态 + 执行权仍持有）；这些待办**在对讲台页头常驻可见**，包括值守轮排队期间。
4. **触发层自己会说话**：每次启动**有界**探测完全磁盘访问权限，有效则完全静默、缺失才引导；真缺授权时节点**立刻**返回可操作的错误，而不是每个白等 300 秒。

## User Stories

1. As a 值班经理，I want 执行体卡住后这条任务仍能被续跑，so that 我不必靠重启应用来恢复它。
2. As a 值班经理，I want run 被判超时的**同时**执行权就被释放，so that 一个永不返回的 future 再也锁不住任务。
3. As a 值班经理，I want `resume` 被挡满预算后系统落一条待办，so that 「试过了、放弃了」这件事我看得见，而不是只在日志里。
4. As a 值班经理，I want 这条待办有**自己的类别**，so that 它不会和「调度器处置未生效」混为一谈，我永远答得出「这次续跑到底试过没有」。

8. As a 值班经理，I want 词汇表与测试文档里「判据只认两类」的明文同步更新，so that 后来的人不会以为判据到此为止。

10. As a 值班经理，I want 授权有效时这个检查**完全静默**，so that 正常使用不会被无关弹窗打扰。
11. As a 值班经理，I want 缺授权时节点**立刻**返回「去系统设置 → 隐私与安全性 → 完全磁盘访问权限开启」，so that 我不用每个节点都白等 300 秒再失败。

13. As a 值班经理，I want 启动探测本身**不阻塞启动**，so that 缺授权时应用仍能开起来、我仍能被引导。
14. As a 值班经理，I want 对讲台页头**常驻**显示未消费待办条数，so that 值守轮排队期间我也看得见系统在报警。
15. As a 值班经理，I want 窄档（≤479px）下这条读数**不被截断**，so that 我在手机上也看得见。
16. As a 值班经理，I want 窄档隐藏「本次会话 N tok」来腾位置，so that 最该看见的那条读数优先。
17. As a 值班经理，I want 这条读数是**只读文字**、不加按钮不加面板，so that 对讲台的肌肉记忆不动（沿用「UI 零改动」那条既有裁决）。
18. As a 值班经理，I want 环境再卡，节点的文件读取也不占用运行线程，so that 应用整体不会降级成"看着活着"。

## Implementation Decisions

1. **覆盖面 = 一次节点请求的组装**（`RequestPlan::assemble_seeded` 这一层），不是只包住报错的那一处。
   该层内的**全部**同步文件读一律挪进阻塞池：项目指令文件、persona 读取、技能目录扫描、任务文件、
   闸门日志。**只包一处是打地鼠**——下一次卡住的大概率是 persona 或技能目录，症状一模一样。
   拒绝做成「agent 路径所有 `std::fs` 一刀切」：`run_command`、迁移、SQLite 那些本来就在同步上下文里。
2. **执行权释放与 future 返回解耦（显式修订决策 226）**：判超时那一方（`handle_timeout`）在判 run
   终态的**同一处**清 `executor_owner`。理由：`release_executor` 原本只在 `run_inner` 正常返回后执行，
   而 run 被标 timeout **只是改了 run 行**，future 照样挂在同步 `open()` 里——两者必须解耦。
   **决策 226 的「不做 `AbortHandle`」维持**：即便未来 IO 已挪出 `poll`，`AbortHandle` 也只是放弃等待、
   中断不了那个仍在跑的阻塞闭包，226 的原始理由没有失效。
3. **新增 `AttentionKind::resume_blocked`（类别数 12 → 13）**：`resume` 重试预算耗尽、放弃触发时落账。
   **不复用 `scheduler_no_effect`**——后者说的是「调度器处置未生效」，混用会让「这次续跑试过没有」永远
   答不出来。**放弃时不自动转 `unstick`**——`try_run` 返回 false 也可能是**有健康执行体正在跑**
   （决策 36 的进程内去重正是为此），判成卡住会清掉健康占用，`unstick` 的文件头为此写了整段警告。
4. **`stuck_evidence` 第三类**：判据从「run 必须仍 `Running`」放宽为「**执行权持有超过阈值**」，
   并允许游标处于 `pending`；有无活 run 是同一条判据的两个分支，**不拆成两条**。
   同步改 `docs/glossary.md` 与 `docs/testing.md` 中「判据只认两类」的明文。
5. **决策 289 维持**：人在跑时值守轮照旧排队（理由——同一时刻两份十几万 token 打同一个 provider——
   仍然成立）。本 spec 只补**信息通路**：让人这一轮里也读得到未消费待办。
6. **完全磁盘访问的启动探测**：每次启动做一次**有界**读取（阻塞池 + 超时，可杀），超时即判「未授权」→
   打开系统设置对应面板引导；授权有效则**永远静默**（零噪声）。**选启动时而非安装时**，因为这条授权
   能否跨重建存活在这台未签名机器上无法离线验证——启动检测对「稳定」「不稳定」两种世界都正确。
   探测用**阻塞池 + 超时**而非普通读，否则探测本身就复刻这次 4 小时的形状。
7. **授权状态以「值」注入，不新造类型缝**：启动时写入一份授权快照，测试直接置值。照第五条接缝
   （远端地址替换点，`AGENTPIPELINE_MARKET_GIT_BASE`）的「**非类型缝**」先例。
   **明确不新造 `DiskAccessProbe` trait**——决策 250 刚删掉一条只有一处 `impl` 的假 seam。
8. **缺授权时快速失败**：组装前读授权快照，缺失即返回可操作错误、节点转 `pending`，**不等那 300 秒**。
   不能在读的那一刻探（`access()` / `stat()` 对受保护路径**同样会阻塞**），只能用启动时记下的快照。
   **错误文案必须含「若你刚刚已开启，请重启应用」**——快照是启动时刻的，运行中改设置进程不知道。
9. **接受阻塞池线程泄漏 + 观测**：`spawn_blocking` 的闭包被 drop 后继续跑，线程不会回来。
   **不用 `timeout` 掩盖**（它唯一的作用是让 `run_inner` 返回，而那件事已由决策 2 的那一层独立保证；
   留着只会让日志多一类"超时"、掩盖"线程还在那儿"这个真实状态）；**不用有界专用池**（满了会把
   「环境卡住」翻译成「节点失败」→ 走重试 → 再卡，把一个可观测的挂起变成一串不可观测的失败重试，
   正是这次故障的形状）。观测 = 卡住的读计数 + 日志 + 超阈值落待办。
10. **前端落点 = 对讲台页头元信息行新增一枚独立只读 span**。
    **明确不并进那枚「值守台账 · 正在跑」的 crumb**——它的判据是「值守轮在飞」，而本场景值守轮
    **正在排队**（决策 289），`in_flight = false`，crumb 根本不出现：**最需要看见的那一刻它不在**。
    也不落状态区 / 值班板——两者的几何被 e2e 锁死，且折行档 / watchMode 下整块不渲染。
    窄档规则：**隐藏「本次会话 N tok」、保留待办**——用一条更该在窄档出现的读数补上决策 300 腾出的位置。
    同时新增一个**只读计数端点**（未消费待办条数 + 类别摘要；现有计数 SQL 已在，缺的是读取端点）。
11. **决策 300 的边界说明（不修订）**：决策 300 明写「明确不做：不另找地方补 pending」。
    本读数是**新增一类别的读数**、不是补 pending；两者语义不同，票里必须写明这句理由，
    否则就是静默假设。
12. **立票切分**：本 spec = 一个 slug（卡死链），烧钱链 = 另一个 slug，**两者之间无阻塞边**。
    跨链的一条依赖写在烧钱链内部（`count_tokens` 改动同时影响流水线 L3 压缩，两侧同批测）。

## Testing Decisions

**什么算好测试**：只测**外部行为**——执行权清了没有、待办落了没有、错误文案里有没有可操作的下一步、
页头读数在不在。不断言内部把 IO 挪到了哪个线程、断言的是「行为在」而不是「实现长这样」。

**接缝**：**不新增任何可测试性接缝**（照决策 299 / 300「§3.1 五条不动」的姿态，及决策 250 删假 seam）。
拟用全部为既有：

| 接缝 | 承担 |
|---|---|
| `AGENTPIPELINE_HOME`（每测试独占家目录） | 造待办表 / provider 行 / 阈值行；`stuck_evidence` 三类形态；`resume_blocked` 落账 |
| `Clock`（`start_paused` 手动推进） | 空闲超时、`resume` 30 秒有界重试、启动探测的有界等待 |
| scheduler `tick()` 手动驱动 | **主链验收**：run 判终态 → 执行权已清 → 下一次 `try_run` 拿到执行权 |
| 进程组终止器（记录调用） | 有界探测超时则杀的见证 |
| LLM 响应流 `Script` 槽（决策 182 的 `Script::for_foreman()`，既有扩展） | 造「节点悬着不返回」、0 提议停轮、缺授权快速失败路径 |
| 前端 `routes/` vitest 接线 + e2e `talk.spec.ts` | 页头读数接线真变、页头高 46 不变、窄档一行几何；§12.3 表由 `behavior-map.test.ts` 自动拦 |

**主链验收的诚实标注**：测试里**没有**可阻塞的受保护路径，所以它验的是**可观察契约**——
「future 不返回 + run 已判终态 → 执行权仍被清、下一次 `try_run` 仍能拿到」，用 `Script` 让节点悬着 +
`Clock` 推进触发超时来造这个形态。**真 TCC 那一层不进默认门**（照真 LLM 冒烟的 opt-in 姿态）。

**which modules**：执行权申请/释放、超时处置、`resume` 有界重试、待办类别与写入、卡住判据、
节点请求组装、授权探测与快照、前端页头组件与只读端点。

**prior art**：`cursor_lifecycle.rs`（执行权与游标生命周期）、`foreman.rs` 集成用例（多会话与待办段）、
`api_contract.rs`（端点形状）、前端 `routes/*.test.ts` 接线测试（照 `Share.test.ts` /
`SettingsLanding.test.ts` 先例）、`e2e/talk.spec.ts`（页头几何与 `.ts` 文案锚点）。

## Out of Scope

1. **`AbortHandle`** —— 决策 226 已裁「不做」，本批**维持不做**（决策 2 的那一层已覆盖它要解决的问题）。
   **重开条件**：阻塞 IO 已挪出 `poll` 之后，若仍需要「立刻中断在飞轮」这个能力。
2. **Developer ID 签名** —— 本机 `security find-identity` = **0 有效身份**，需外部资源；它是**唯一根治**
   （授权按稳定身份归属、跨重建有效），但不该挡住本批。
   **重开条件**：拿到证书；签完名后完全磁盘访问那一层可以撤。
3. **运行期间实时感知授权变化** —— 快照有滞后，本批以文案告知（「若刚开启请重启」）而非实时刷新。
   **重开条件**：出现「运行中改设置」是常态用法的实证。

## Further Notes

**残余风险（要如实写进票面）**：

1. **触发层现在只剩完全磁盘访问这一层**。裁决「不叠加读 worktree」的理由是：*worktree 的项目代码
   未必是 AgentPipeline 的项目代码*，不能拿它当项目指令的来源。于是若授权随重建失效、且启动引导被
