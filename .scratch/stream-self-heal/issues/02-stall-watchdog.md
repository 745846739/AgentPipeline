# 02: 客户端停滞看门狗:「已连接」超过 45 秒没字节就判死重连

**What to build:** 屏幕亮着时网络闪断(Wi-Fi 切换、路由抽风)会产生半开连接:流读取挂死、状态一直显示「已连接」、再也没有新事件。看板有 10 秒对齐 tick 兜着,任务详情页和对讲台没有任何周期兜底,内容一直 stale、断线横幅也不出现。本票在连接层加停滞看门狗:`open` 状态下按「**最近一次收到任何字节**」计时,超过阈值(3 × 心跳间隔 = 45 秒)判定死流,置「断过线」标记后走既有主动重连(重置退避、中断旧连接、立即重开);重连成功后因标记在场必补一次全量校准——断流期的事件已丢,「接回」必须等于「内容也恢复」。判据是字节而非事件:心跳帧没有事件但有字节,这正是把「安静且健康」与「安静且已死」分开的东西,健康空闲连接不被误杀。看门狗长在连接层,看板、详情页、对讲台共用一条,三处自动同享。

**Blocked by:** 01 (服务端 SSE 心跳) —— 先有心跳才分得清「安静且健康」与「安静且已死」;否则空闲任务每 45 秒被白白重连一次。

**Status:** done（已实现）

- [ ] 单测:`open` 后静默到阈值 → 发起新的连接尝试(既有 stub fetch 形态断言第二次请求)
- [ ] 单测:阈值内收到任意字节(包括不携带 data 的心跳帧)→ 计时重置,不触发重连;健康安静连接不被误杀
- [ ] 单测:看门狗判定的重连成功后,全量校准回调被调用(「断过线」标记由看门狗置位)
- [ ] 阈值可注入:单测用毫秒级小阈值驱动,不真等 45 秒
- [ ] `connecting` / `closed` 状态不归看门狗管;stop 之后无悬挂计时器
- [ ] 既有连接层单测一条不红;状态机形状不变(idle/connecting/open/closed/error,不新增状态)
