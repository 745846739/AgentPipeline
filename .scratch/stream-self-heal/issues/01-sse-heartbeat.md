# 01: 服务端 SSE 心跳:静默流也每 15 秒来一帧

**What to build:** 任务详情或对讲台开着、暂时没有动静时,一条半开的连接双方都察觉不到——服务端「有事件才出字节」,客户端读取可能挂死很久不报错。本票让两个 SSE 端点(任务流、值班长流)在**没有任何业务事件**时也每 15 秒发一帧不携带 data 的心跳,让「线还活着」成为可观测的字节。心跳不携带 data,客户端解析器只认 data 行,零改动;两个端点必须同做,否则值班长流成为漏网的那条。这是看门狗(02 票)分清「安静且健康」与「安静且已死」的前提。

**Blocked by:** None (can start immediately)

**Status:** done（已实现）

- [ ] 契约测试:连上任务流、故意不触发任何业务事件,在 keep-alive 间隔 + 测试余量内收到心跳帧
- [ ] 契约测试:值班长流同断言,同窗口内收到心跳帧
- [ ] 心跳帧不携带 data:客户端分帧单测加一条注释/空帧断言——解析器对它产出零事件、不影响残留缓冲
- [ ] 既有 SSE 契约用例(事件按任务路由、工头事件不串台、提议事件分发等)一条不红;content-type 仍为 text/event-stream
- [ ] 心跳间隔单一常量(15 秒),注释注明与客户端看门狗阈值的 3 倍关系(阈值本体在 02 票落)
