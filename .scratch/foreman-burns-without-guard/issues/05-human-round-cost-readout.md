# 05: 人的那一轮的成本读数——今天那条软告警只看生成 token

**Status:** ready-for-human（要先裁决决策 292 的判据方向，才谈实现形状）
**Blocked by:** 一次裁决（决策 292 的判据方向），不是别的票

**What to build:** 作为值班经理，我要在**人的那一轮**里看见「**这一轮读了多少**」。
今天那条软告警只报生成 token，而这一班的开销 **98% 在输入侧**——它整班一次都没响。

**实证（2026-10-08 班次 `01M4CDY9EC9M9FSSE236GJXYZC`）**：

| 读数 | 值 |
|---|---|
| 全班输入 / 输出 | **12,172,916** / 217,782 |
| 单轮最贵（407，跑 48 分钟） | 输入 **5,163,470** / 输出 **38,054** |
| 其余两个大轮（394 / 405） | 3,265,532 / 60,533、1,139,034 / 21,917 |
| 三轮占全班输入 | **78.6%** |
| 软告警命中次数 | **0**（`content LIKE '%这一轮已烧%'`） |

判据在 `runner.rs:1065`：`cost_verdict(input.is_watch(), tokens.1, token_line)`——`tokens.1` 是
**生成** token，线是 `FOREMAN_WATCH_TOKEN_BUDGET = 120_000`。407 的输出 3.8 万，远在门槛下。

**为什么这条是「裁决」而不是「修 bug」**：决策 **292**（`docs/decisions.md:1764`）的标题就写着
「值守轮 120k 硬界、**人的那一轮无硬界只落软告警**」，正文与文案（`OPERATION_LOG_MARK` 那句）用的
都是「**生成** token」这个口径。改它是**修订 292 的判据面**，得有人拍板——而 292 的立意
（人的那一轮由人定终点）看起来仍然是想要的。

**形状（三选一，荐 (b)）**：

- (a) **不动**：保持只看生成 token。代价如实记：本班这种「输入爆、输出小」的形态永远不告警。
- **(b) 软告警改成双读数（输入 + 输出），不加硬界——荐**：把「这一轮读了多少」摆出来，
  终点仍由人定。**不碰 292 的立意**，只把读数补全。
- (c) 给输入侧也加一条线：等于动 292 的「无硬界」，本票不荐。

**若选 (b)**，两处形状要顺带定：① 判定与文案同处（`cost_verdict` 的签名 + 告警句），
**一处改两处生效**；② **线怎么定要看一批真实的输入分布**——本账只给了三个样本
（3.27M / 1.14M / 5.16M），若按输入设线，「线」的量级是**百万**而不是十二万，别沿用 120k。

**验收**（若选 (b)）：

- [ ] L1 单元：`cost_verdict` 四格——输入高输出低 / 输入低输出高 / 都高 / 都低
- [ ] L2 集成：人的那一轮落一条带**双读数**的软告警
- [ ] L2 集成：**值守轮 120k 硬界行为一字不改**（既有用例
      `the_token_budget_stops_the_watch_round_but_never_the_human_one` 必须仍绿）
- [ ] 手工面：拿本账班次的数据重演 407 轮 → 应当出现一条「本轮已读 X / 已生成 Y」的软告警
