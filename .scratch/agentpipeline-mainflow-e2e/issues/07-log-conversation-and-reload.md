# 07: 日志与对话的内容可信 + 刷新后状态恢复

**What to build:** 用户「看任务跑」时最常做两件事是**看日志/对话**和**刷新页面**。
当前两条用例对这两件事只验到「页签能点」：`happy-path.spec.ts:39-45` 逐个点页签断言
`class` 带 `on`，再断言产出文件列表含 `design.md`。而（a）命令与输出页签里的**内容**、
（b）会话页签里的**对话内容**、（c）**刷新后**实时流断掉能否把状态补回来——全部未验。

风险面很具体：命令输出与对话是 SSE 推送 + 落库回读两条路径的汇合点
（`command_output` / `conversation_delta` 事件，见 `api/types.ts:284-360` 的事件全集），
两条路径任一坏掉，页签仍能切、界面仍「看起来正常」，用户看到的却是空面板。
刷新恢复则是「实时流是唯一数据源」的经典缺陷：断开后若不重新拉取快照，用户会看到停在
刷新那一刻的旧状态。

- [x] **命令与输出内容**：任务推进期间断言该页签内出现**非空且可识别的命令内容**

- [x] **实时流的行为**：任务运行中断言界面出现流式产生的内容（`conversation_delta` /

- [x] **刷新恢复**：任务处于 pending（或 running）时 `page.reload()` →
      断言（a）页面重新加载后仍显示正确的任务状态与 pending 面板；

      至少断言重连后状态最终收敛到真值
