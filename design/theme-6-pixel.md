## 1. 设计概念

**一句话：** 开发者是深夜车间的**值班经理**，看板是一台还在运转的 8-bit 流水线——
任务是传送带上的货箱，工位是机器，指示灯报告每台机器的状态，pending 是机器急停、
弹出的对话框正在等你按键。**值班长（工头）是一个会说话的角色**，坐在 §3.3 的对讲台上，
替你把 8 个工位的处境讲成人话并给出建议——**它动手分层、不直连状态机**：环境层看档位、
本服务写接口恒提议等你按键、托管只放一个免按键动作（决策 206 / 207 / 210）。

> **身份已裁决（决策 176；人的名分由决策 193 修订）。** 本节的「工头」= **值班长**（agent，
> 对话的另一方），与 §3.3 对讲台是同一个角色。裁决前的稿件（决策 174）把工头定为玩家本人，
> 该读法**已作废**。dossier 那枚头像（16×16 美术、契约显示尺寸 48px）的归属随之明确为
> **值班长在向你汇报**——它把货箱的处境摆到你面前、等你拍板，语义自洽。
>
> 人类开发者的名分**原为「值班员」，决策 193 改为「值班经理」**：`员` 与 `长` 是同一序列里
> 相邻的两级，而本页的权力是反着配的（拍板与本服务写接口的确认钮永远在人手里——决策 207/210 的
> 现口径），名分比对面低
> 一级、权力却全在自己手里，读起来就成了下属给上级下命令。界面上的两块名牌——时间线
> `turn.mine .dname` 与输入坞 `.typer .dname`——都写这个词，`FOREMAN_PERSONA` 里对人也用
> 这个词：**同一个名分只有这一个答案**。

领域词汇在此主题的转译：任务 = **货箱**，列 = **工位**，轨道 = **传送带**，
状态 = **信号灯**，pending = **急停**，dossier = **操作台对话框**，
折返线 = **回流带**，并行分支 = **双带并轨**。

四条原则：

1. **像素纪律。** 全站唯一字体（缝合像素 12px，见 §2.2），字号只取 12 的整数倍
   （12 / 24 / 36），禁用中间号；圆角恒为 0，描边只有 2px 一档；阴影只能是
   `4px 4px 0` 的硬投影；禁止平滑渐变与柔光——**2×2 棋盘 dithering 是全站唯一的"渐变"**，
   只允许出现在货箱顶盖带与已归档工位两处。
2. **灯即状态。** 沿用全站信号语义（绿 = 执行、琥珀 = 等人、红 = 失败、灰 = 归档、
   蓝 / 紫 = 分支徽章）。灯是实心像素方块，绝不作大面积底色；一张货箱上最多
   一枚灯 + 一种描边色。琥珀仍是全站唯一告警。
3. **急停对话框是主角。** pending 内容渲染成 RPG 对话框（双线框 + ▼ 光标），
   它是全站视觉权重最高、也是唯一"响"的东西；其余一切保持安静。
   boldness 只花在这一处。
4. **帧步进，无缓动。** 一切动画用 `steps()` 离散步进，像素世界的位移不经过中间帧：
   运行中工位的传送带虚线步进、对话框 ▼ 光标与流式输出方块光标闪烁、按钮按压位移。
   `prefers-reduced-motion` 下全部静止。禁止 ease / cubic-bezier 缓动与淡入滑入。

**选型自评（为什么不是那些更省事的像素风）：**
GameBoy DMG 四色绿——与主题三磷光绿同色相，撞车；`Press Start 2P`——像素主题的
默认字体，且无中文；全站 CRT 扫描线 / 玻璃反光——模板装饰，不携带信息；
近纯黑底 + 单酸绿强调——与主题三气质重复。最终选择：夜靛底 + 暖纸白文字 +
中文字体像素化，靠「急停对话框 + 传送带」两个领域转译承载个性。

### 2.2 字体

| 角色 | 字体 | 用法 |
|---|---|---|
| 全站唯一 | 缝合像素 12px 等宽（Fusion Pixel 12px Monospaced，zh_hans + latin） | 标题、正文、数字、命令一律同族；`-webkit-font-smoothing: none` 保脆 |

字阶：**12 / 24 / 36**（12 的整数倍，禁止中间号）。基准 12px 行高 1.6；
工位名 / 列头 12px + `letter-spacing: 0.08em`；大数字（时长、token、计数）24px 起步，
配 12px 灰注；wordmark 24px。禁用粗体模拟层级（像素字体无字重轴），
层级靠字号倍数、亮度阶与描边，`<b>` 仅作亮度提升。

### 2.5 应用图标（桌面壳 / Dock）

Tauri 壳的图标（`crates/desktop/icons/{icon.png,icon.icns}`，`tauri.conf.json` 的 `bundle.icon`）
也是本主题的一份素材，故纳入本文管辖：**新增/改动图标需回到本节修订**，与 §2.3 的 sprite 表同一条纪律。

**母题**：一只货箱坐在传送带上，右上角一盏绿灯——即 §1 的三个领域转译物
（货箱 = 任务、传送带 = 轨道、灯 = 状态）在同一帧里的最小组合。**图里没有第四个元素**：
没有齿轮、没有箭头、没有字母 A，避免落进「开发者工具 = 齿轮/终端」的通用默认。

**画法**：单份 **32×32 像素母版**（坐标表写在 `scripts/make-icon.mjs`），
各尺寸由它整数倍推导（16px 为 2×2 箱式降采样，其余为最近邻放大）。
像素画的可审查形式是坐标表而非位图——改图改脚本、重跑生成，与 sprite 表同一种做法。

| 元素 | 母版几何（32×32） | 取色 |
|---|---|---|
| 底板 | 内缩 2px 的像素台阶圆角（半径 6px，≈ macOS 0.225 比例） | `--bg` |
| 货箱 | 20×16，居中 | 箱沿 `--belt-lit` / 顶盖带 `--pane` / 箱面 `--wash` |
| 货单标签 | 8×2 一行 | `--text-2` |
| 信号灯 | 6×6，与箱右沿齐平、上半悬出箱顶 2px | `--go`（全图唯一的绿与最亮点） |
| 传送带 | 3 节 × (4px 链 + 4px 隙) = 20px，与货箱等宽对齐 | 已通过 `--belt-lit` / 未点亮 `--pane` |

**两条硬约束**（都不在视觉品味层面，而是正确性层面）：

1. **所有矩形坐标与尺寸必须为偶数。** 16px 由母版 2×2 降采样得到，21 / 17 这类奇数
   会让 2×2 箱跨在图形边缘上，降采样出中间色（既脏又难解释）。`scripts/make-icon.mjs`
   的 `assertEven()` 违反即报错退出；`--dump` 打印 16px 真实位图，可核对「图例里除 token 外
   别无中间色」。另核传送带总宽 = 货箱宽（否则 16px 下两者左右不齐）。
2. **明度序与界面一致，但整体提亮一档。** 界面的货箱面 `--panel` 与底板 `--bg`
   只差一档明度（对比 1.12:1）——32px 尚可，16px 下整只箱子会糊进底板。图标因此取
   `沿 --belt-lit > 盖 --pane > 面 --wash`，即界面 `pane > wash > panel` 同序整体 +1 档。
   **不取暖纸白做箱面**：试过，16px 下箱面成一大块白，反把绿灯的对比吃掉——
   boldness 只花在灯这一处（§1 原则 3）。

**生成与核验**（仓库根执行；无第三方依赖，PNG 由内置 zlib 编码，输出确定性）：

```bash
make icon          # 出 crates/desktop/icons/{icon.png(1024), icon.icns(10 档)}
node scripts/make-icon.mjs --check   # 取色表须与 §2.1 逐字一致，否则报错
node scripts/make-icon.mjs --dump    # 16px 真实位图 + 图例（核像素用）
node scripts/make-icon.mjs --preview # .scratch/shots/icon-preview.png（16/32/256 在深浅两底的放大对照；该目录不入库）
```

### 2.6 对比度门（无障碍）

> **本节是补回的，并且是一条机器门。** 主题六改版时，旧主题各自都有的「无障碍与实现注记」
> 一节**整节丢掉**了——本文改版后查「对比度」「无障碍」零命中，全站纸面上只剩
> `--text-hi ≥ 12:1`、`--text-2 ≥ 4.5:1` 两个数字，`--text-3` / `--text-4` 没有任何要求；
> 而实测里承载着必读内容的两档灰字只有 **3.28:1** 与 **2.25:1**。规则丢了半年没人发现，
> 是因为它只是散文；**决策 195 把它做成一条「改差即变红」的门**。

**裁决一：阈值按 token 职责分档，不采用统一的「正文 ≥ 7:1」。** 一条「凡正文类文字 ≥ 7:1」的
门会把 `--text-2` / `--text-3` 一起拉到 7:1，**整站随之拉亮**，并且**压平信号色的相对关系**——
失败红 `--stop` 对 `--bg` 只有 **5.64:1**（浅色款执行绿 `--go` 只有 **4.30:1**），正文类文字一旦
整体 ≥ 7:1，全站唯一的两个强信号（红 = 失败、绿 = 执行）就比正文更弱。钱要花在
「读不到就会挡住下一步」的那些地方，不花在「整站一起变亮」上。

**裁决二：逐档门槛与用法职责。** 门槛对**两套配色 × 两个承载表面**的每一个都要成立：

| token | 用法职责 | 门槛（对 `--bg` 与 `--panel` 都要成立） | 现状（深 bg / panel；浅 bg / panel） |
|---|---|---|---|
| `--text-hi` | 标题、可执行物、当前游标 | ≥ **12:1**（沿用 §2.1 既有注记，把同一数字延伸到 `--panel`） | 14.12 / 12.62；14.51 / 16.47 ✅ |
| `--text` | 正文 | ≥ **7:1**（这条 7:1 **只属于这一档**，不是全站口径） | 9.45 / 8.45；10.37 / 11.77 ✅ |
| `--text-2` | 次文本 | ≥ **4.5:1**（保持） | 5.22 / 4.67；5.74 / 6.51 ✅ |
| `--text-3` | **次级必读**：列头、页面导入语、空态引导句、待处理下拉里的原因、元信息行（语言 / 闸门命令 / 地址 / 归档行）、返回入口、输入框占位符、任务卡时长 | ≥ **4.5:1**（**新增**；由票 15 提亮 / 加深达标） | 3.28 / 2.93；3.32 / 3.77 ❌ |
| `--text-4` | **纯装饰**：不承载必读信息的刻度与结构噪声 | **门里豁免**（不设门槛） | 2.25 / 2.01；2.19 / 2.49 —— 豁免 |

`--text-2` / `--text-3` / `--text-4` 在 §2.1 与 §2.4 两张表里的**语义列**已按本表改写；
**值列**在票 15 落地后已回填为实现真值（`--text-3` 深 `#8E8CA5` / 浅 `#636477`，
`--text-4` 与 `--done` 值不变）。

> **落地后实测（2026-09-16 票 15 落地，回填给读者一个当前值，不是改本裁决）：**
> 上表「现状」一列记的是 195 拍板时的**改动前**值（`--text-3` 深 3.28 / 2.93、浅 3.32 / 3.77），
> 它们正是这付门当初要拦的红。实现落地后的真值是：`--text-3` 深 **5.12**（`--bg`）/ **4.58**
> （`--panel`）、浅 **4.64** / **5.26**，两套配色 × 两个面**全部达标**。深色款上 `--text-3`
> 与 `--text-2` 在约束面 `--panel` 上只剩 **0.09** 的差（4.58 对 4.67）——「挤到半格以内」
> 这条代价已经发生，层级从此由字号 / 位置 / 用法承担（§2.6 裁决四），
> 不许为保层次压暗 `--text-2`，也不许合并这两个 token。

**用法职责四条**（与门槛同等重要——门槛管「值」，规约管「谁用哪档」）：

1. **判据一句话：读不到就会挡住下一步的，用 `--text-3`；纯刻度装饰，才留 `--text-4`。**
   `--text-4` 的合法用法是**结构噪声**（还没走到的未来站名、回流带的 `↩`、空刻度槽）——
   它承载的是「这里有个位置」而不是「这里是这个信息」。
2. **凡用到 `--text-4` 的地方不得承载必读信息**；上面表里那些职责一整批都归 `--text-3`，
   由票 15 逐处归位（含现在用错档、以及 `.state` 这类只有文字编码的状态词）。
3. **信号色与材质色不是文字档，不进这副门**：`--go` / `--go-hi` / `--pending` / `--stop` /
   `--done` / `--branch-dev` / `--branch-tst` / `--belt-lit` / `--pane` / `--wash` / `--bg` /
   `--panel` / `--ink` / `--hairline`，以及带透明度的 `--overlay` / `--pending-tint`——
   它们承担的是灯、条、图元、描边与底。**用它们作文字时另受一条约束**：只许出现在
   **已有第二编码**的状态标记上（灯 / 条 / 图元 + 状态词同时出现）；**只有文字编码、要人读的，
   改用 `--text-3`**（例：`StageRecommendations.svelte` 的 `.state.on`「已安装」）。
4. **成对色单独一栏**：这些前景不是坐在「页面的底」上，而是坐在**另一枚 token 的实心面**上，
   逐对也要 ≥ 4.5:1 —— `--go-ink` on `--go`（深 9.17 / 浅 **4.87**）、
   `--diff-add` on `--diff-add-bg`（深 7.87 / 浅 5.28）、
   `--diff-del` on `--diff-del-bg`（深 6.27 / 浅 5.67）。

**裁决三：门的位置、范围与形状**（票 15 落地）：

- **落在 vitest 层**：`frontend/src/theme/contrast.ts`（纯函数）+ `contrast.test.ts`（用例），
  属既有的「静态扫描 + 逐值比对」家族，**不新增接缝、不为它改生产代码形状**。门比的是
  **契约里的 token 值 × 表面值**——这张矩阵在纯函数层毫秒级跑完；e2e 只能覆盖显式取样到的
  几处渲染，覆盖不到它。
- **门必须从契约读值**（`DARK_COLORS` / `LIGHT_COLORS`），**不得在测试里重抄一份字面值**：
  重抄就等于造了一副「改契约不改测试也绿」的假门。
- **表面就取 `--bg` 与 `--panel` 两个**，**两个面都要过**。理由是一条算术：深色款的约束面是
  `--panel`（比 `--bg` 亮一档：`--text-3` 2.93 < 3.28），浅色款的约束面是 `--bg`
  （比 `--panel` 暗一档：3.32 < 3.77）——**只核一个面会在另一套配色上漏**。
  `--wash` 是 hover / active 的瞬态底，**不进这副门**；但**只在 `--wash` 上出现且低于 4.5:1
  的文字，按上面的用法职责改用 `--text-2`**（`--text-3` 在 `--wash` 上是 2.58 / 3.00；
  **票 15 落地后为 4.03 / 4.18，仍低于 4.5，故这条规约照旧适用**）。
- **豁免名单必须在测试里显式列出、并被测试校验**：`--text-4` 与上面第 3 条那一族写进
  `EXEMPT`，另加一条断言「`EXEMPT` 里的每个 token 都能在契约里找到」——索引与豁免最大的
  失败形态不是没建，是建完悄悄烂掉。
- **失败信息说清四件事**：哪个 token、哪套配色、哪个表面、差多少。定稿格式：
  `对比度门：--text-3（深色）对 --panel 实测 4.13:1 < 门槛 4.5:1（差 0.37）`。只说「不达标」不算。

**裁决四：值与门的关系——改值必须成对改、一次改全。**

- 深浅两套的 token 值是**手工镜像**：契约模块 `frontend/src/theme/contract.ts` 的
  `DARK_COLORS` / `LIGHT_COLORS` ↔ 全局样式表 `frontend/src/app.css` 的 `:root` 与
  `html[data-theme='light']` 两个块；`frontend/src/theme/css-parity.test.ts` 对两套**逐值双向
  比对**（少一条、多一条、值不同三种都红）。所以**改值必须成对改、一次改全**：只改契约、
  只改 `app.css`、改了深色忘浅色，三种都立刻变红——四个改点（`contract.ts` 两处 +
  `app.css` 两处）一次改齐才绿。
- **两档灰字靠近是这条门槛的必然代价，明说**：`--text-3` 提到达 4.5:1 后，深色款上它与
  `--text-2` 的亮度差会挤到「半格以内」（约束面 `--panel` 上 `--text-2` 现值 4.67，
  达标线 4.5 就在它下面一格多一点），浅色款上还留得出一档（`--text-2` 5.74）。
  层级从此由**字号、位置与用法**承担，不再靠继续压暗 `--text-3`；
  **不允许**为了保住层次把 `--text-2` 压暗（那会把次文本拉下 4.5）；**也不合并这两个 token**
  （合并要动契约 token 名表与全部消费点，代价远大于收益，而两档职责确实不同）。
- **`--done` 与 `--text-3` 的进退关系**（最容易被改错的一处）：两者**当前共用同一个字面值**
  （深 `#6E6C82`、浅 `#7A7B8E`）但**不是同一个 token**。从决策 195 起：
  **`--text-3` 提上去、`--done` 原地不动**——`--done` 是信号色（§2.1「归档灰，刻意退后」），
  提亮它会拿走「归档退后」这条既有语义，并连带改掉灯、量表与条形图的颜色。三条推论写死：
  ① 两者的字面值从此**不再相同**，这是预期的——`css-parity.test.ts` 逐 token 比对各自的值，
  **不会**因此变红；② 曾靠「两者同值」隐式得到的对等（归档的灰字与弱文本一样亮）**不再成立**，
  凡**读得到才算数**的归档文字走 `--text-3`，凡**只是退后**的灯与图元保持 `--done`；
  ③ **提升 `--text-3` 时不许顺手把 `--done` 一起提**——那会把「归档」从视觉上抹掉。

> **一句话记住**：`--text-hi` 12 / `--text` 7 / `--text-2` 4.5 / `--text-3` 4.5（次级必读）/
> `--text-4` 豁免（纯装饰）；信号色与材质色不进这门；成对色（钮字 / diff）单独 4.5。

### 2.7 看板几何：列宽、溢出与对齐守护

> **决策 196。** 背景是审计里最刺眼的一处：八列 264px（阵列 2130px）在 **1440px** 的常规
> 笔记本上只露 5 列、第 6 列被从词中间切断，而**最决定性的 `merge` / `done` 完全在屏外**——
> 唯一的存在提示是那个被切断的列（macOS 的 overlay 滚动条不滚动不出现）。处置是
> **不改几何，改可见性与提示**：把结论钉住，把「还有列」说出来。

- **列宽 264px 不动。** `.panes` 2130px、`.hinner` 2162px（= 2130 + 2×16 内边距）是既有几何，
  本项**不碰**列宽、不碰列数、不碰脊线坐标（改列宽是另一件事，见 Out of Scope）。

**两档行为**（判定用桌面款内部的一条媒体断点，桌面款之外无影响）：

| 档 | 行为 |
|---|---|
| **≥ 1400px**（钉右档） | `merge` / `done` 两列**钉在右侧、不参与横滚**——钉住区宽 = `columnWidth × 2` = **528px**（与列宽同源，不另取数）；中间六列（init / architect-design / design / develop / review / test）横滚。**钉缝** = 钉住区左缘的那条 2px `--pane` 竖线；**同一把刀切列与脊线**：脊线与主传送带在同一个 x 处断开，两段各自沿用「列 j 中心 = `columnWidth/2 + columnWidth × j`」（j 在该段内从 0 计）——**不许只切一边**，只切一边就是脊线与列错位。 |
| **< 1400px**（不钉右档） | 不钉右。打开看板时横滚区的**初始位置落在 `merge`**，右缘留一条「**还有 N 列**」的指示。 |

- **「落在 `merge`」的定义必须是可实现的，这里写死**：让 `merge` 贴横滚区**左缘**在算术上
  **不可达**——最大可滚量 = 2162 − 视口宽，在任何 < 1400px 的宽度上都小于 `merge` 的左缘
  （≈1616），所以在 < 1400px 里唯一成立的读法是「**`merge` 贴横滚区的右缘**」：
  `scrollLeft = merge 右缘 − 横滚区宽`，钳制在 `[0, max]`。此时 `done` 仍在右缘之外——
  **这正是「右缘还有列没显示」成立的原因**，两条口径由此自洽。
- **初始滚动只做一次**（首次装载看板时），**不是**每次任务刷新都把视口拽回去：刷新不抢
  人已经拖到的位置。
- **「还有 N 列」指示（定稿形态）**：
  - 文案 `还有 {n} 列 ▸`，`n` = 横滚区右缘之外**完整不可见**的列数；`n` 随滚动递减，
    **滚到最右整条消失**（`n = 0` 即不渲染）。
  - 形态：2px `--pane` 描边 + `--wash` 底 + 12px `--text-3` 字（提升后达标）；高由内容撑出
    （12px 字 + 2×2px 描边 + 2px 竖内边距 ≈ 20px），横内边距 6px；`▸` 用**文字字形**，
    **不新增 sprite**（sprite 表冻结，§2.3）。
  - 落位：钉在横滚区**右缘**（`right: 2px`），纵向压在**脊线带底部的空带与阵列顶框之间**
    ——**不覆盖任何货箱、列头与计数**。
  - `pointer-events: none`、不进 tab 序、`aria-hidden`：它是**指示**不是控件
    （「点一下右滚一列」是另一件事，本轮不做）。

    中间六列的屏外数；< 1400px 时它钉在**看板横滚区的右缘**，`n` 数的是整条阵列的屏外数。
    一处实现、一条规则，不为两档各造一套提示。
- **移动款不受影响**：上面两档**都只在桌面款内部**；< 480px 仍是纵向站点带（`.panes` 转

  `(min-width: 1400px)` 媒体断点**——它不引入第二套版面（不是平板版），只切换「钉右 / 不钉右」；
  480px 那条断点与它的行为一字不动。这条新增是对像素主题 effort「仍是 480px 单断点」
  那条 Out of Scope 的**显式例外**（同文件已就地标注修订）。断点值在契约里是
  `GEOMETRY.boardPinBreakpoint: 1400`，在 `Board.svelte` 的媒体查询里是字面量 `1400px`
  （CSS 的 `@media` 不认自定义属性），**由下方守护的静态扫描断言两者相等**。

**几何对齐守护**（本项的兜底，落在 `frontend/src/lib/pipeline.geometry.test.ts`）：

- **为什么必须有**：脊线站点坐标与列宽是**手工对齐**的，两处分别是
  `frontend/src/lib/pipeline.ts` 的 `SPINE_GEOM`（列 i 中心 = `132 + 264i`，其中 `132 = 264 / 2`）
  与契约 `GEOMETRY.columnWidth: 264`；`PipelineRail.svelte` 里 spine 段的主带 / 双带 / 回流带的
  `left` / `width` 也全是 264 的整数关系（主带 `left:132, width:1848 = 264×7`；双带
  `left:396, width:528 = 264×2`；回流带 `left:924, width:792 = 264×3`……）。**改一处不同步改
  另一处，今天没有任何测试会报警**，只会让脊线**静默错位**（`buildSpineStations` 的 `x`
  直接进渲染）。
- **守护方式**：一条**静态扫描 + 逐值比对**的纯函数检查（与 `css-parity.test.ts` 同一家族，
  不是新接缝），断言四件事——① 从契约读 `columnWidth`（**不得重抄 264**）；
  ② `SPINE_GEOM` 的每个列位 `x === columnWidth/2 + columnWidth × i`（并行那两站共用列 x），
  且列位数 === `columnCount`；③ spine 段的静态几何字面量满足
  `(left − columnWidth/2) % columnWidth === 0` 且 `width % columnWidth === 0`
  （**扫描范围只有 spine 变奏**：hero 与 mini 变奏另对齐冻结原型 `#v-run .hrail`，与列宽无关）；
  ④ 主带端点 `left + width === columnWidth/2 + columnWidth × (columnCount − 1)`。
  **改单边即红。** 若票 17 顺手把 `SPINE_GEOM` 与 spine 几何改成由 `columnWidth` 推导（推荐），
  ③④ 退化成一条「`pipeline.ts` 与 spine 段不得出现裸 `264` / `132` 字面量」。
  同一文件里再加⑤「`Board.svelte` 媒体查询的 `1400px` === `GEOMETRY.boardPinBreakpoint`」。

> **落地补注（2026-09-16 票 17 落地后回填）：实现取了上面那条「推荐」路径，守护的 ③④ 因此已退化。**

> spine 坐标与带几何**全部由 `GEOMETRY.columnWidth` 推导**，`pipeline.ts` 里不再有裸 `264` / `132`
> 字面量——列 x 走 `spineColumnX(i) = columnWidth/2 + columnWidth × i`，带几何走

> `−columnWidth × base`，负值由宿主 `overflow: hidden` 裁掉），`spineBeltsAll()` / `segmentStationX()`
> / `spineColumnIndex()` 是守护用的读数口；`PipelineRail.svelte` 的 spine 段也不再写 `left` / `width`

> 现在这些值由 `spineBelts()` 现算）。
> 守护的实际断言为六条：① `BOARD_COLUMNS` 列数 === 契约 `columnCount` + `app.css` 的
> `--rail-col-width` === 契约 `columnWidth`；② 各站 `x === spineColumnX(列号)` 且反查回同一列号、
> 落位列数 === `columnCount`；③ 两段的每条带满足 `(left − columnWidth/2) % columnWidth === 0`
> 与 `width % columnWidth === 0`（`vt` 纵向接头除外，其宽由 CSS 定 6px）；④ 主带端点在首末列站心，
> 且两段的带回到整条看板口径**逐条相同**（这就是「同一把刀」的断言化）；⑤ `Board.svelte` 的

  （冻结原型同一手法、且漂移更大），**本决策不动它**：守护只保证「脊线坐标与列宽同源」这条
  关系，**不**把「站心 = 列内容中心」当断言——今天的实现过不了那条，那属于另一次几何清理。

| 输入坞 | 底栏上沿（`.typer`，`bottom: var(--sbar-h)`） | 约 **88.4px**（提示语那一行已撤） | 说话的地方永远在手边 |

其余（对话）一律随手指滚——滚上去的版面就不占用这块小屏幕。
**窄屏连单张急停也折成摘要条**：一张 376px 的展开轮钉在 900px 的屏上等于把整块屏幕钉死
（展开一张时状态区**退出钉住**，回到普通文档流并由 `toggleStop` 滚回视野上沿，
`scroll-margin-top` = `calc(var(--topbar-h) + 56px)`（决策 218 把决策 192 的写死值挪到
「带子下沿 + 10px」，决策 242 起改读实测顶栏高）——否则人点了
「展开恢复动作」，动作却在屏幕之上）。折叠判据仍是同一个 `lib/talkStops.ts`，窄档只是把
`forceFold` 传成真（由 `window.matchMedia('(max-width: 899px)')` 决定，断点住在
`frontend/src/lib/talkLayout.ts` 一处，`talkLayout.test.ts` 把它与 `Talk.svelte` 里的
CSS 字面量对着钉——决策 215 / 218 的 899 因此是**一个断点三处用**：时间线折成一列、
页头 ⋯ 与折行档版面、`forceFold`）。

**实测（真实应用，430×900，单张急停挂着）：对话区从 26px 涨到 385px。** 26px 不是笔误——
钉死的状态区按 38vh 拿走 322px（还自带 46–78px 的区内滚动），页头 72px、值班板 67px、
输入坞 145px 再把剩下的分完，一行话都放不下。窄屏另外两处与宽屏不同：`dvh` 而不是 `vh`
（地址栏收放时 `vh` 会把钉底的输入坞推到屏幕外），以及**一轮新回话落地后把视口带到它那里**
（`scrollToNewest`：窄屏滚文档末尾、宽屏滚 `.timeline` 末尾；只在**轮数**变化时滚，
流式增量不乱动视口）。

**急停折叠（决策 183）**：一张急停轮**最高的形状**（`info_insufficient`：`AllowedAction::
resume("continue","补充信息并继续").requiring_input()` + `side_effect("cancel","取消任务")`，
`crates/core/src/actions.rs:161-163`）约 **330px**——含 2 行补充输入框、两个整行宽的钮、两个
分组头；而状态区上限桌面 `46vh`（**决策 208 之后是「46vh」与「先留给时间线的那一份」两项取小**，
13″ 内高约 748px 上实测 **202px**），**展开一张就已经把整个状态区
占满**，第二张必然掉出第一屏，正是上面那句禁止的错。故：**只有一张急停时完全不变**（全展开，
不出现任何折叠 UI；单急停的版面与折叠前逐像素一致）；**两张及以上时一张都不展开**，全部收成
**一行摘要条**（每条约 **36px**）——几张都留在第一屏。**「多张同挂时默认展开最新那张」达不到
目的**：一张展开就是 330px，其余照样掉出去。
（**`≤899px` 一档修订「单张不折」这一条**，决策 218 ⑥：折行档与窄档同源、钉住的东西必须便宜，
一张 376px 的展开轮钉在 768px 高的窗口上就是半块屏，故那一档**单张也折**；**桌面（≥900px）
仍是「单张展开」逐像素不变**。）

人点「展开恢复动作 ▸」才展开那一张，**同时只展开一张**（点另一张的展开会收起前一张）。展开后
状态区可能需要区内滚动——这是使用者**主动**要的，且他正看着那一张。

**矮窗口：状态区让位给时间线（决策 208）。** 三分区是**零和**的，46vh 那条上限只管「状态区
不能吃满整页」，它没管时间线还剩多少。2026-09-17 在 1280×720 实测：状态区吃满 331px 之后
**时间线只剩 26px**——恰好是它自己的上下内边距，内容区为 0，连一条提议轮的确认钮都放不下；
点不到的直接原因是输入坞那颗悬出框沿 16px 的名牌截走了点击（`elementFromPoint` 命中它）。
故上限改成**两项取小**：`min(46vh, 100vh - 其它一切 - 时间线下限)`。「其它一切」是逐块量得的
**386px**（底栏区 46 + 顶栏 88 + 页内边距 26 + 页头 38 + 三条行距 60 + 输入坞 124，向上取整——
与 `.talk` 的 `height` 公式同一手法：宁可少给状态区几像素），**时间线下限 160px**（放得下一条
提议轮的「身份标签 + 参数摘要 + 30px 的钮」）。**视口高 ≥ 约 930px 时第二项大于 46vh**，规则
退化成原来的 46vh、逐像素不变；矮窗口里生效的是第二项，代价是**状态区自己滚得更多**（那本来
就是它让位的方式）——13″（748px）上同时看得到的摘要条因此从约 5 张降到约 3 张，这是零和，
如实记。零和的证据是 e2e 里的四条几何断言：时间线 ≥160px、钮整颗落在时间线里、钮的中心点
命中的是它自己（不是那颗名牌）、输入坞与整页都没被顶坏。**下界**：视口高低于约 546px 时连
160px 都让不出来（386 + 160 已经等于屏高），此时两项公式仍把时间线顶在最前，状态区只剩余下
那条缝——三分区在那么矮的窗口里本就没有解，不在本条的处理范围内。

**摘要条是一行三块**：`[琥珀的「⏸ 等你拍板 · pending 类型中文标签」] [「任务标题」· N 个动作]
[展开恢复动作 ▸]`。折叠行**不再单独渲染 `.dtag` 那一行**（并进摘要条这一行里），故约 36px；
窄屏（≤479px）这一行会折行，仍是「一屏好几张」的量级。**详情没到（拉取中或拉取失败）时不写
「0 个动作」**——把「还没读到」说成「没有」，与空看板那条纪律（决策 182①）是同一个错。
（决策 218 ⑦a/⑦b 在 `≤899px` 一档又收了两刀，桌面款都不动：**折叠态不画名牌**、上内边距
随之归 0（名牌 22px 高、向上悬出卡片框沿 14px，有名牌就至少要 14px 净空），故那一档摘要条
约 **73.9px**；**一张急停都没有时状态区整块退场**（原先那个「当前没有急停」引导块在 430px 上
约 65px），于是「急停」一词的首现平实说法从那个空态**搬到摘要条自己的琥珀标签**
（`⏸ 急停（等你拍板的阻塞）· 合并审批`，只在本页第一张上给括号）——译文跟着词走：没词就没有
要翻译的词，决策 200 的口径不变，换的只是落点。）

折叠**只收动作区，不收身份**：折叠行的琥珀框、`4px 4px 0` 硬投影、`▼` 闪烁光标与展开行
**完全相同**——折叠不产生第二种「响」的形态，也不新增动画位（纪律 2 与「全站四个动画位」不变）。
展开／收起是**纯呈现**：动作集仍由后端下发（决策 69/101）、仍在那张展开的轮里内联，摘要条上的
个数就是这一点的可见证据；收起是**显式**的，点了就保持收起、不自动弹回，选中的那张被处理掉
（resume 成功后不再 pending）后展开项不悬空。判据抽在 `frontend/src/lib/talkStops.ts`（纯函数
`defaultOpenStop` / `resolveOpenStop` / `toggleOpenStop` / `isFoldable` / `isStopOpen` / `stopActionCount`，
L1 单测 `talkStops.test.ts`），组件里只剩渲染。
（**`≤899px` 一档对「不收身份」作了局部修订**，决策 218 ⑦a：那一档的折叠摘要条**不画名牌**，
身份由框色 / 硬投影 / `▼` 三样承担——这三样正是决策 183 裁决③给摘要条定的形状里已有的东西，
名单里本来就没有名牌；**展开那一张才画名牌、才要那 20px 上内边距**（`.stop-open`，展开时本来
就退出钉住）。桌面款的摘要条一字不改。）

**残留（如实记）**：折叠把「状态区里**同时看得到**几张急停」从 1 张提到约 **5 张**（13″ 可用约
344px ÷ 每张实际占的约 62px = 一行摘要条约 36px 加 26px 间距），但**展开任何一张都可能把其余挤出
可见区**。**决策 208 之后，这一档在矮窗口里降到约 3 张**（13″ 内高 748px：上限由 344px 收到
202px，因为要先让出时间线的 160px）——同一种取舍，只是分母换了。窄屏那一档的这个残留**已被
决策 192 消掉**：状态区不再区内滚，摘要条钉在顶栏下沿，展开一张时它自己退成文档流的一块（滚的是整页）。
即**默认态是「都看得到」，展开态是「看这一张」**——这不是消除，是把「静默滚出」换成「主动展开」。
上面这些数字（330px / 344px / 36px / 261px）按 CSS 盒模型推算，**不是浏览器实测**（决策 192 与 208 那两批数字是实测，见上「窄屏」与「矮窗口」两段）。

**窄屏的残留（同为如实记）**：① 钉住的摘要条会随张数长：一张实测约 **66px**（窄屏摘要条两行；
**决策 218 ⑦a 之后 73.9px**——折叠态无名牌但仍是两行标签）加 26px 间距，两张约 186px；到
**45vh 兜底上限**（按实测行高推算：900px 机型约五张、740px 约四张）之后
这条带子自己滚——被滚出去的那张就不再「一直看得见」了（与宽屏那条残留是同一种取舍）；
② 宽屏在**矮窗口**上「状态区吃满、时间线被压到 0」的老问题**已由决策 208 修掉**（见上「矮窗口」；
1280×720 实测时间线 26px → 163px）——本条当时只动 ≤479px、把宽屏那一档如实记下，208 是回来收它的。
③ **决策 218 在 `≤899px` 一档的残留，同样如实记**：a) 班次相关的动作（含开新对话）从此**只在
页顶够得着**——补回来的办法就是把页头那一行钉住，这一档已经钉了（46px 带子），故长会话里换
班次要先滚回顶部；b) 折行档（480–899px）与窄档同源，故 480–899 的「桌面款」形态**不存在**了
——那是刻意的（原先 480px 上对话列只剩 82px，`minmax(0,1fr)` 的 `1fr` 能缩到 0）；c) 375×667
一档对话区**几乎不变**（156.8 → 约 195px），那 37px 静置溢出的消失**换的不是对话区变大**，
是「页面不该滚却在滚」被消掉；d) 排满三只钉住物之后，这一档的对话内容区在 430×900 上是
**447.7px（有急停）/ 535.6px（没有急停）**——钉住物变贵（46px 页头带子）换的是班次动作恒可达，
账在「修订决策 218」那一段里逐块列着。

**边界（重要）：值班长说的话里永远没有按钮。** 时间线与状态区的按钮**三处**、都**不在值班长的话里**：
急停轮里的后端下发动作钮（resume / retry / 拍板 / merge / 建任务——必须由你点）、
提议轮里操作台内联的确认钮（执行 / 拒绝——决策 207③，动手的是按下那颗钮的人）、
以及提问轮的选项钮（决策 265——点一个选项是**替你说出下一条话**，回发走的还是既有发话口；
框色用正文色再深一档 `--text-2`，与提议轮的 `--text-3` 分开，已答整轮灰一档）。理由有二：
决策 69/101 的「`allowed_actions` 后端下发、前端从不计算」是全站唯一的防错误放大接缝，
让 LLM 的判断直接接到状态机上等于把它拆了；且两个位置各渲染一颗同样的钮，会让「哪个是真的」
变成你必须思考的问题。

**值班长会动手，但闸门分族（决策 188 / 206 / 207 / 210）。** 工具面从「两个只读台账工具」扩到
**24 项、清单驱动**（单一事实源 `FOREMAN_TOOL_SPECS`，顺序有冻结断言钉住，清单生成广告集与
执行点白名单；分层见词汇表「值班长能力面」条）。它按档门动手：`ask` 档（值班长缺省）下环境层
写那一类每次调用落成一条**提议**——时间线上多一轮 `.turn.prop`（操作台记的一笔账 + 两颗钮：执行 / 拒绝，
决策 207③），人按下才走既有端点执行；`auto` 档环境层直通、`deny` 档连广告都不给；
**本服务的写接口**（`task` / `config` / `skills` / `service`）**永不受档位管辖**——它们永远走
确认钮（决策 206）；决策 210 的托管另对单任务放免按键 `task resume(continue)`。**「回复里
没有按钮」这条因此改写成「回复里没有按钮，时间线上的钮两处——操作台那一轮里的确认钮与
提问轮的选项钮」（决策 265 修订 176④ / 207③ 的「唯一」口径；「回复里没有按钮」不变）**：
模型的话里依然一颗钮都没有（它不能渲染 UI），
而确认钮挂在**操作台**的名牌下（动手的是按下那颗钮的人，不是值班长）。这条与上面那条接缝
**无关**：`allowed_actions` 那一套（决策 69/101）管的是流水线自身的写动作，一步没动。

**实现要点（四处非显然的坑，已修）**：

1. **详情必须随待办集合变化重拉，不能只在 `onMount` 拉一次**——`board.init()` 是异步的
   （`App.svelte` 的 `onMount` 发起），本页 `onMount` 时 `board.tasks` 往往还空着；只拉一次
   会让 `details` 永远为空，页面安静退化成「打开任务详情」按钮，**把后端下发的恢复动作整片
   吞掉**（e2e ⑩ 打红即此）。现以实现 `pendingKey` 指纹（id + pending 类型 + 阶段）驱动
   `$effect` 重拉：集合不变不重拉，一变（装载完成 / resume 后翻转 / `pending_updated` 换理由）才重取。
2. **导航 chip 里的 `foreman` 头像必须缩到 16px**——它的契约显示尺寸是 48px（dossier 用），
   塞进页签盒会把盒撑高，窄档**底部页签栏**的 `--nav-h` 是写死的账（58 + safeb），一高
   全线错；桌面档则连带顶栏导航行变高、`scroll-margin-top`、横幅 `top`、页头带子 `top`
   一起偏（它们全读 `--topbar-h`）。已用 `.chip .ic svg.sprite{width:16px}` 收住
   （e2e ⑨ 各有一条断言钉住顶栏与页签栏高度）。
3. **页面级分组头与 `PendingActions` 自己的逐组头重复**——本页原先在 `PendingActions` 之前
   无条件渲染一个 `<div class="grp">恢复动作</div>`，于是 resume 类 pending 上「恢复动作」
   叠两行；`human_review`（动作集只有两个 `side_effect`，`crates/core/src/actions.rs:242-247`）
   上标题写「恢复动作」而下面全是旁路动作；无动作时标题下面跟着「当前没有可下发的动作」。
   任务详情页的对应分支本就避开了这一重复并留了注释
   （`frontend/src/components/task/PendingDossier.svelte:184`「恢复动作 / 旁路动作的分组头由
   `PendingActions` 逐组渲染，不在此重复」，其 `merge_approval` / `human_review` 分支才自带
   头）。已删掉该页面级标题（连同其 `.grp` 样式规则），改由 `PendingActions` 逐组渲染。
4. **摘要条中间那一块的类名不能叫 `st`**——`app.css` 里的 `.st` 是全局的「状态文字标记」
   （`::before` 塞一枚 8px 方灯 + `white-space: nowrap`），同名的局部类会**同时套上这两条**：
   摘要条上凭空多一枚无意义的灯，且标题不换行、直接压到展开钮上（430px 实测：`.st` 盒宽
   122px、文字 160px，重叠 28px）。改名为 `.stt`（`Talk.svelte` 局部），并让它在窄屏显式
   排成两行（标签一行、标题与展开钮一行）。同一批还修掉两条「桌面款规则漏在窄屏生效」：
   `.talk` 的 `height: calc(100vh - 88px - 46px)` 与 `.timeline` 的 `overflow-y: auto`
   ——窄屏只写了 `min-height` 与 `flex`，于是整页仍被钉成 798px、时间线仍是滚动容器
   （实测：撤掉 `height` 后对话区 398px、文档高度正好等于视口）。

**设计取向：不造聊天组件，把操作台对话框竖起来排。** 全站视觉权重最高的东西是急停对话框
（§1 原则 3），对讲台直接复用它作为发言单元：**压在框沿上的名牌 tab 就是发言者**，故不再
另加一行 `who`，也不做左右交替的气泡。一列对话 = 一叠对话框，身份由名牌承载而非位置。

### 3.4 脊线的站点数字与并行站名标签

> **决策 197。** 这条是**补定义**——规格从未写过脊线上那个数字是什么口径，而它与列头那个数字
> 长得一模一样（都是「站名 + 2px 框里的一个数」），量却不同，同一时刻实测相差一倍。

**两个数字是两件事**：

| | 脊线站点数字 | 列头数字 |
|---|---|---|
| 实现 | `PipelineRail` 的 `.ct`（`buildSpineStations`，`lib/pipeline.ts:608-631`） | `BoardColumn` 的 `.col-n`（`tasks.length`） |
| 口径 | **累计到过这一站**（流量 / 漏斗） | **此刻停在这一列**（存量） |
| 位置 | 阵列**上方**的脊线带（站点灯与站名之下） | 每个工位列头行的**右端** |
| 标注 | **带 `累计` 词**（必读、常显） | **不带词**（裸数字） |
| 悬停 | `title="累计到过这一站"` | `title="此刻停在这一列"` |

**裁决：保留「累计到过这一站」的口径**——它是唯一能回答「这条链上跑过多少」的量，改成存量就
与列头重复、白丢一个读数。

**定稿标注（不得破坏像素纪律）**：脊线数字的 2px 框内、数字**左侧**加 12px 的 **`累计`** 二字，
与数字**同色同框**（`--text-3`，`tabular-nums` 只作用于数字），完整读法 `[累计 3]`。
字号取 **12**（唯一字阶的最小档，**不新增字号**），框仍是 2px `--pane`、圆角 0、
内边距 `0 4px`（沿用 `.ct` 现值）——**不新增色、不新增形状、不新增动画位**。待拍板站点的
`.ct.pen` 形态不变：数字与标注**一起**转 `--pending`（标注不许掉队——它是同一个框里的同一句话）。

**两端如何不被误认为同一个量**（一句话规则）：**带 `累计` 词的必是流量，不带词的必是存量**；
主手段是**常显的标注词**（悬停提示只是辅助，不是主手段——同屏要能直接读出来）。两条纪律：
脊线那个数字**只准带这一个词**（不许再叠「合计 / 总数 / 通过」这类同义词），
列头那个数字**不许加词**（加词会让两处又长得一样，且列头行没有富余宽度）。

**没有数字的站不画空框**：并行两个侧站没有数字（`buildSpineStations` 在这两站给
`count: undefined`），标注因此没有宿主，**整块不渲染**——不把「没有」画成「0」
（与看板空态那条纪律同源）。

**并行站名标签的层叠（记录）**：`dev-design` / `test-design` 两个侧站标签坐在双带上、靠
`background: var(--bg)` 的**不透明遮罩**遮住链节——**这是原型继承的几何，不是实现回归**
（`design/prototype-pixel.html` 的 `.stn.side .lb` 与 `.belt` 起点几何同构：原型的侧站
`top:62px / 90px` 正落在双带的 y 上，标签盒纵跨带线，靠遮罩读出字）。**本轮接受并留档**。
唯一要改的是实现漏抄的那处内边距（原型 `.stn.side .lb{padding:0 4px}`，实现只抄了背景，
于是有遮罩的两个标签比原型窄 8px、链节从字的两端透出）——**票 10 已落地**：
`frontend/src/components/pipeline/PipelineRail.svelte` 的 `.stn.side .lb` 现有
`padding: 0 4px`（形制与原型一致），本条由「待处置」改为**已决**。

**补完内边距之后是否还需要动层叠：不需要，不动层叠。** 理由：标签盒是
`position: absolute` + 不透明 `--bg` 底，在 DOM 里排在链节带**之后**，同一个层叠上下文里
后画的盖住先画的——链节从来没有画在字上面；「被压穿」的观感只是**遮罩比字窄**这一处内边距
缺失造成的。补回 4px 横向内边距后，遮罩覆盖字形的左右端点，链节不再从字里透出。
**`z-index` / 层叠顺序 / `isolation` 一律不动**——动它们等于给一个已经解决的问题加一条新规则，
还会牵动 `app.css` 其余层叠。

**档外如实记（不在本决策的处置范围，本轮不动、不改坐标）**：脊线**主站**名
（`architect-design` / `develop`）的**上半行**被并行下带（实现 y=50–56）横穿——按 CSS 盒模型
推算，主站名盒在 y 46–60。冻结原型里主站名在链带**之上**（`.railwrap` 高 168px、主带 y=76、
主站名 y 0–34），实现里主站名在链带**之下**（`.rail.spine` 高 116px、主带 y=36、灯心压在带上）。
它与并行侧站那两个标签**不是同一件事**（那两处是原型继承），也不由票 10 覆盖；成因
（竖向排布的有意选择还是漂移）未登记，**另立票再议**。改它要动脊线带高与看板首屏高度。

## 4. 选型注意

- 与主题三的边界：同为深色，但主题三是「字符终端」（单字族等宽、字符线路行、无盒体），
